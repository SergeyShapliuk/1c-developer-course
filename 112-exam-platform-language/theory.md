# Теория. Платформа и язык на одной странице

## Какую задачу мы решаем

Этапы 1–2 вы проходили давно, и с тех пор многое стало привычкой: вы нажимаете `F7`, не думая, что именно обновляете, и пишете `&НаСервере`, не вспоминая, почему не `&НаКлиенте`. На экзамене привычка подводит: вопрос сформулирован не так, как вы привыкли делать, и правильный ответ приходится восстанавливать из понимания, а не из движения рук.

Эта страница собирает темы первых двух этапов в короткие утверждения и рядом с каждым называет ловушку, на которой ошибаются. Это не замена занятиям: если утверждение не вызывает узнавания, вернитесь к занятию из последней колонки.

## Как работать с билетом

Каждый билет этапа проходится одинаково.

1. **Решить на время**, не подглядывая, называя контекст каждого вопроса.
2. **Проверить по ключу** и для каждой ошибки прочитать объяснение.
3. **Проверить спорное экспериментом.** Если объяснение не убеждает, воспроизведите ситуацию в базе. Факт, увиденный своими глазами, запоминается надёжнее прочитанного.
4. **Завести карточки** на ошибки и обновить план подготовки.

Эксперименты ставят в «Учебной консоли» базы разработки. Она под контролем Git с этапа 9, поэтому после эксперимента легко убедиться, что ничего лишнего не осталось: выгрузить конфигурацию и посмотреть `git status`.

## Платформа и конфигурация

| Утверждение | Ловушка | Занятие |
| --- | --- | --- |
| Платформа исполняет конфигурацию; конфигурация описывает прикладное решение | принять конфигурацию за программу, а платформу — за данные | 1 |
| В файловом варианте база — один файл на диске; в клиент-серверном данные хранит СУБД | думать, что файл базы можно править или копировать во время работы | 2 |
| Пользователи работают с конфигурацией базы данных; основная конфигурация попадает в неё обновлением `F7` | считать, что сохранения `Ctrl+S` достаточно | 3 |
| Имя объекта — для кода, синоним — для пользователя | путать, что видит пользователь | 4 |
| Подсистема без объектов в интерфейсе не видна | искать причину в правах или синониме | 5 |

## Модель данных

| Утверждение | Ловушка | Занятие |
| --- | --- | --- |
| Справочник хранит список однотипных объектов; код и наименование — стандартные реквизиты | использовать код как бизнес-идентификатор | 6 |
| Предопределённый элемент создаёт разработчик, и код обращается к нему по имени | думать, что его создаёт пользователь или что он хранится в константе | 6 |
| Значения перечисления задаёт разработчик; пополняемый пользователем список — справочник | выбрать перечисление для списка, который будет расти | 7 |
| Константа хранит одно значение | использовать константу как список | 7 |
| Связь объектов хранят реквизитом ссылочного типа, а не строкой с наименованием | хранить «Иванов» строкой | 8 |
| Составной тип хранит одно значение одного из разрешённых типов | думать, что он хранит все значения сразу | 8 |
| `ЗначениеЗаполнено` пустой ссылки — `Ложь` | сравнивать ссылку с `Неопределено` | 8, 12 |

## Встроенный язык

| Утверждение | Ловушка | Занятие |
| --- | --- | --- |
| Тип принадлежит значению, а не переменной | ждать ошибки при записи в переменную значения другого типа | 12 |
| Функция возвращает значение через `Возврат`, процедура — нет | вызывать процедуру в выражении | 15 |
| Параметр без `Знач` передаётся по ссылке: изменение внутри видно вызывающему; с `Знач` — не видно | считать, что параметры всегда копируются | 15 |
| Структура ищет по строковому ключу-имени; соответствие — по ключу любого типа, в том числе по ссылке | хранить цену материала в структуре с ключом-наименованием | 17 |
| Таблица значений на клиенте тонкого клиента недоступна | создавать её в клиентской процедуре | 18 |
| После `ВызватьИсключение` выполнение переходит в ветку `Исключение`; строки после вызова не выполняются | ждать, что код продолжится | 24 |

## Модули, клиент и сервер

| Утверждение | Ловушка | Занятие |
| --- | --- | --- |
| Правило, которое должно срабатывать при любой записи объекта, живёт в модуле объекта | писать его в форме | 21, 33 |
| Общий модуль с флагами **Сервер** и **Вызов сервера** позволяет вызвать его экспортную процедуру с клиента и выполнить на сервере | ставить флаг **Глобальный** или **Клиент** | 21 |
| Обращаться к базе данных в клиентском коде тонкого клиента нельзя: поиск, чтение, запись — на сервере | вызывать менеджер справочника в процедуре `&НаКлиенте` | 19, 22 |
| `&НаСервереБезКонтекста` не видит реквизитов формы, в том числе `Объект`; получает только параметры | обращаться к `Объект` из внеконтекстной процедуры | 22 |
| Каждый серверный вызов — обмен между клиентом и сервером; вызов в цикле множит его | вызывать сервер на каждую строку | 22 |

## Что важно запомнить

1. Билет решают на время, проверяют по ключу, спорное проверяют экспериментом, ошибки превращают в карточки.
2. Пользователи работают с конфигурацией базы данных; её обновляет `F7`.
3. Связь объектов — ссылка; код и наименование для этого не годятся.
4. Перечисление задаёт разработчик, справочник пополняет пользователь, константа хранит одно значение.
5. Без `Знач` параметр передаётся по ссылке.
6. Соответствие ищет по ключу любого типа, структура — по строковому имени.
7. К базе обращаются на сервере; внеконтекстная серверная процедура не видит формы.
8. Правило, обязательное при любой записи, — в модуле объекта.
