# Теория. Виртуальная таблица среза последних

## Какую задачу мы решаем

На занятии 41 цена попала в регистр `ЦеныМатериалов`, а форма заявки стала брать её на дату документа функцией `ЦенаМатериала`. Решение работает, но у него два недостатка, и оба мы тогда записали как долг.

Первый: цена подставляется в момент выбора материала. Если снабженец поменял дату заявки или в регистре появилась новая цена, строки остаются со старой ценой, и обновить их можно только перевыбором материала в каждой строке.

Второй: каждая цена — отдельное обращение к базе. В заявке на тридцать позиций это тридцать вызовов `ПолучитьПоследнее`. То же в обработке `УчебнаяКонсоль`, где цены всех материалов читаются в цикле.

Снабженцу нужна кнопка **Заполнить цены**: одно нажатие — и все строки получают цены на дату заявки. Программе нужен способ спросить цены **всех нужных материалов одним запросом**.

## Виртуальная таблица

В запросе к регистру можно обратиться к его обычной таблице записей: `РегистрСведений.ЦеныМатериалов`. Это то же, что форма списка регистра, — все записи со всеми периодами. Чтобы получить из неё цены на дату, пришлось бы для каждого материала найти максимальный период не позже даты и соединить результат с записями. Получается тяжёлый запрос, который легко написать неправильно.

Платформа делает эту работу сама. У регистра есть **виртуальные таблицы** — таблицы, которых нет в базе, но которые платформа строит по записям регистра в момент выполнения запроса. Для периодического регистра сведений их две:

| Виртуальная таблица | Что возвращает |
| --- | --- |
| `СрезПоследних` | по одной записи на каждое сочетание измерений — последнюю с периодом не позже заданной даты |
| `СрезПервых` | по одной записи на каждое сочетание измерений — первую с периодом не раньше заданной даты |

`СрезПоследних` — ровно то правило, которое вы записали на занятии 41: «в срез попадает по одной записи на каждый материал — последняя из тех, чей период не позже заданной даты». Метод `ПолучитьПоследнее` отвечает на этот вопрос для одного материала, виртуальная таблица — для любого их количества.

## Параметры виртуальной таблицы

Виртуальную таблицу записывают в секции `ИЗ` с параметрами в скобках:

```bsl
ВЫБРАТЬ
	Цены.Материал КАК Материал,
	Цены.Цена КАК Цена
ИЗ
	РегистрСведений.ЦеныМатериалов.СрезПоследних(&Дата, Материал В (&Материалы)) КАК Цены
```

Параметров у `СрезПоследних` два.

1. **Период** — дата, на которую берётся срез. Если параметр не указан, берутся самые последние записи вообще.
2. **Условие** — отбор записей регистра, которые участвуют в построении среза. Пишется как обычное условие на поля регистра.

В конструкторе запроса параметры задают кнопкой **Параметры виртуальной таблицы** над списком выбранных таблиц.

## Условие в параметрах и условие в ГДЕ

Отбор можно записать и в параметре виртуальной таблицы, и в `ГДЕ`. Это **не одно и то же**, и разница — главная мысль занятия.

- Условие **в параметрах** применяется **до** построения среза: платформа отбирает записи регистра и уже из них выбирает последнюю на дату.
- Условие **в `ГДЕ`** применяется **после**: срез построен по всем записям, и из его строк остаются подходящие.

Для условия на **измерение** результат одинаков: срез по цементу и срез, из которого потом взяли цемент, совпадают. Но в параметрах платформа не строит лишнего — не считает срез по материалам, которые не нужны. Поэтому **условия на измерения пишут в параметрах**.

Для условия на **ресурс** результат разный. Вопрос «какие материалы сейчас дешевле 13 рублей». Условие `Цена < 13` в параметрах сначала выбросит октябрьскую запись цемента по `13,10`, и срез на октябрь вернёт сентябрьскую цену `12,50` — цемент попадёт в ответ по цене, которая уже не действует. Условие в `ГДЕ` возьмёт действующую цену `13,10` и честно не включит цемент. Поэтому **условия на ресурсы пишут в `ГДЕ`**.

## Соединение с виртуальной таблицей

Виртуальная таблица — полноправный источник: её можно соединять с другими таблицами. Список всех материалов с ценами строится левым соединением справочника со срезом:

```bsl
ИЗ
	Справочник.Товары КАК Товары
		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.ЦеныМатериалов.СрезПоследних(&Дата, ) КАК Цены
		ПО Цены.Материал = Товары.Ссылка
```

Левое — потому что материал без цены должен остаться в ответе с `NULL` в цене, а не исчезнуть. Это всё то же правило занятия 58.

## Где живёт заполнение цен

Команда **Заполнить цены** меняет строки документа, открытого в форме и, возможно, не записанного. Значит, это команда формы, как **Пересчитать заявку** на занятии 34, а не команда объекта. Запрос выполняется на сервере, поэтому основная работа — в процедуре формы `&НаСервере`: ей нужен доступ к `Объект.Материалы`, то есть контекст формы. Клиентский обработчик команды только вызывает её.

## Что важно запомнить

1. Виртуальная таблица строится платформой по записям регистра при выполнении запроса и в базе не хранится.
2. `СрезПоследних(Период, Условие)` возвращает по одной последней записи на сочетание измерений на заданную дату.
3. Условия на измерения пишут в параметрах виртуальной таблицы: результат тот же, а работы меньше.
4. Условия на ресурсы пишут в `ГДЕ`: в параметрах они меняют сам срез и дают неверный ответ.
5. Виртуальную таблицу можно соединять с другими таблицами; для «всех материалов с ценами» нужно левое соединение.
6. Одним запросом к срезу цены всех строк документа получаются за одно обращение к базе.
