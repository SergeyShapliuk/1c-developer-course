# Практика. Резюме и отклик

## Перед началом

Понадобятся рассказ о проекте `career/project-pitch.md` из конспекта, README и архитектурные решения `docs/decisions.md` из репозитория `construction-erp` (занятие 117) и доступ к любому сайту вакансий.

Резюме содержит личные данные. Если ваш конспект `1c-learning-notes` опубликован на GitHub, держите файлы этого занятия вне репозитория конспекта — в отдельной папке на диске — или сделайте конспект закрытым. Ниже файлы называются так, как если бы они лежали в каталоге `career` конспекта; выберите место сами.

## Шаг 1. Разберите три вакансии

1. Найдите три свежие вакансии junior 1С-разработчика или стажёра 1С. Подойдут и вакансии «1С-программист без опыта».
2. Создайте файл `career/vacancies.md` и для каждой вакансии заполните таблицу:

| Требование | Вид | Где у меня | Занятие |
| --- | --- | --- | --- |
| | обязательное, желательное или шум | файл или объект проекта, где это видно | |

3. Отметьте требования, для которых в колонке «Где у меня» пусто. Для каждого запишите, что вы скажете о нём честно: «изучал основы», «не работал, но понимаю, как устроено», «не знаю».

**Проверка:** три вакансии разобраны, у каждого требования указан вид, пустые места отмечены и для них записан честный ответ.

## Шаг 2. Соберите ключевые слова

1. Выпишите обязательные требования, которые встретились хотя бы в двух вакансиях из трёх. Это ваш список ключевых слов.
2. Для каждого ключевого слова запишите одной строкой пример из проекта. Например, «язык запросов» — «запрос остатков с границей момента в контроле проведения передачи».

**Проверка:** у каждого ключевого слова есть пример из проекта.

## Шаг 3. Напишите резюме

Создайте файл `career/resume.md` по разделам теории. Используйте свои настоящие данные только в этом файле и только если он не публикуется.

1. **Заголовок.** «Junior 1С-разработчик».
2. **Контакты.** Телефон, почта, город, ссылка на портфолио — опубликованный репозиторий или фраза «репозиторий проекта покажу на собеседовании».
3. **Кратко о себе.** Две-три фразы. Пример: «Прошёл практический курс разработки на 1С:Предприятие 8.3 из 120 занятий и построил на нём учебную конфигурацию для строительной компании: документы, проведение по регистрам, запросы, отчёты на СКД, печатные формы, права. Работаю через Git: ветки, pull request, ревью, версии».
4. **Навыки.** Пять-шесть групп, в каждой — три-пять конкретных пунктов. Группы: встроенный язык и клиент-сервер; документы, регистры, проведение; запросы; СКД и отчёты; формы и печать; права и администрирование; Git и процесс разработки; тестирование. Порядок групп — по ключевым словам шага 2.
5. **Проекты.** Учебный проект: одна фраза о системе и пять-семь строк того, что сделано, — каждая строка результатом, а не «изучал». Хотя бы одна строка — о месте логики. Отдельной строкой — честно: «учебный проект; командный процесс моделировался со вторым учебным разработчиком».
6. **Опыт работы.** Если есть прежняя работа — две-три строки о том, что из неё пригодится 1С-разработчику: учёт, склад, документы, работа с пользователями.
7. **Образование и сертификаты.** Курс; сертификат 1С:Профессионал, если получен, или запланированная дата экзамена.

Объём — одна-две страницы.

**Проверка:** в резюме семь разделов, раздел «Проекты» описывает результаты, в нём есть строка о месте логики и честная строка об учебном характере проекта.

## Шаг 4. Сопоставьте навыки с проектом

Для каждого пункта раздела «Навыки» запишите рядом — в отдельном файле `career/resume-check.md` — где в проекте он виден и в каком занятии изучен. Пункт, для которого нет примера, уберите из резюме или переформулируйте честно.

**Проверка:** у каждого навыка резюме есть место в проекте и занятие; навыков без подтверждения не осталось.

## Шаг 5. Проверьте резюме по чек-листу

| № | Проверка | Отметка |
| --- | --- | --- |
| 1 | Желаемая должность названа в заголовке | |
| 2 | Ссылка на портфолио или фраза о показе проекта есть в контактах | |
| 3 | Ключевые слова обязательных требований встречаются в навыках и проектах | |
| 4 | Ни одного навыка без примера из проекта | |
| 5 | Уровни владения честные, слов «эксперт» и «в совершенстве» нет | |
| 6 | Учебный проект не выдан за коммерческий опыт | |
| 7 | Типовые конфигурации, если упомянуты, описаны честно | |
| 8 | Нет опечаток: резюме прочитано вслух целиком | |
| 9 | Объём — не больше двух страниц | |
| 10 | Файл с личными данными не лежит в публичном репозитории | |

Попросите кого-нибудь прочитать резюме одну минуту и ответить: на какую должность вы претендуете и что умеете. Если ответ не совпадает с тем, что вы хотели сказать, — правьте начало резюме.

**Проверка:** все десять пунктов отмечены; результат «минутного чтения» записан.

## Шаг 6. Напишите сопроводительное письмо

Выберите из трёх вакансий ту, что подходит больше всего, и напишите в `career/cover-letter.md` письмо по структуре теории: почему эта вакансия, два-три требования и где они видны в проекте, ссылка на портфолио, готовность к тестовому заданию. Пять-семь предложений.

Затем подстройте резюме под эту вакансию: поставьте первыми группы навыков, которые в ней обязательны.

**Проверка:** письмо в пять-семь предложений ссылается на требования конкретной вакансии и на проект; резюме подстроено под неё.

## Проверка результата

Занятие пройдено, если выполняются пять условий:

1. Три вакансии разобраны по видам требований, ключевые слова собраны.
2. Резюме из семи разделов, раздел «Проекты» описывает результаты и место логики.
3. Каждый навык подтверждён местом в проекте и занятием.
4. Резюме прошло чек-лист из десяти пунктов и «минутное чтение».
5. Сопроводительное письмо написано под конкретную вакансию, резюме подстроено под неё.

## Контрольные вопросы

Не подглядывая в теорию, ответьте устно или в заметках:

1. Как отличить обязательное требование вакансии от желательного и от шума?
2. Почему для junior раздел «Проекты» важнее опыта работы?
3. Что значит «подтверждённый навык» и как это проверить до отправки резюме?
4. Что вы честно скажете о типовых конфигурациях и что покажете вместо опыта с ними?
5. Из чего состоит сопроводительное письмо и почему оно короткое?
6. Напишите строку раздела «Проекты» о контроле остатков так, чтобы из неё было видно место логики: где живёт проверка и почему не в форме.

Сверьте ответы с [теорией](theory.md). Если на каждый вопрос получается ответить одним-двумя предложениями, переходите к занятию 119.
