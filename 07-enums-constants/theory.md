# Теория. Перечисления и константы

## Перечисление

**Перечисление** — объект метаданных с заранее определённым небольшим списком вариантов. Пользователь не добавляет в него новые элементы во время работы: он только выбирает один из тех вариантов, которые уже заложены в конфигурацию.

Пример из нашего проекта. Каждый контрагент строительной компании относится к одному из трёх типов: «Заказчик» — тот, для кого строят; «Поставщик» — тот, у кого покупают материалы; «Подрядчик» — тот, кто выполняет часть работ. Других вариантов в этой классификации нет и не предполагается. Эти три варианта создаёт разработчик в Конфигураторе, и список на этом закрывается.

Перечисление подходит, когда набор значений известен заранее и редко меняется. Виды клиентов, способы доставки, вид оплаты, пол сотрудника — типичные перечисления. Список клиентов, список товаров, список складов — нет: они растут по ходу работы, и это задача справочника.

## Значения перечисления задаёт разработчик

У значения перечисления есть **имя** и **синоним** — так же, как у любого объекта метаданных. Имя `Заказчик` нужно платформе и коду, синоним «Заказчик» читает пользователь.

А вот чего у значения перечисления **нет** — это кода и наименования, которые правит пользователь. Значение перечисления в принципе не является данными: это часть конфигурации, часть описания системы. Пользователь не может его переименовать, не может удалить и не может добавить новое.

Из этого вытекает главное практическое следствие. Чтобы добавить четвёртый вид клиента, недостаточно что-то ввести в работающей программе. Нужно:

1. открыть Конфигуратор;
2. добавить новое значение в перечисление;
3. сохранить конфигурацию;
4. обновить конфигурацию базы данных.

Звучит как неудобство, но в этом и смысл перечисления: набор защищён от случайного расширения. Никто не заведёт «Заказчик (новый)» или «заказчик» со строчной буквы, потому что завести что-либо вообще нельзя. Классификация остаётся чистой, и отчёты по ней собираются корректно.

## Константа

**Константа** — объект метаданных, который хранит одно общее значение для всей информационной базы. Наименование организации, дата начала учёта, адрес головного офиса, фамилия главного бухгалтера — всё это константы.

Ключевое слово здесь «одно». В отличие от реквизита, константа не повторяется у каждого элемента справочника. Название вашей собственной компании — одно для всей базы; хранить его в каждом клиенте бессмысленно и вредно: у тысячи клиентов будет тысяча копий одного и того же текста, и при смене названия придётся править тысячу записей.

Разделение обязанностей для константы такое же, как для всей платформы в целом:

- **разработчик** создаёт константу в Конфигураторе и задаёт её **тип** — строка, число, дата, булево;
- **пользователь** вводит само значение в режиме «1С:Предприятие».

Это важно не перепутать. Разработчик решает, что константа «Дата начала учёта» хранит дату. Какую именно дату — решает тот, кто работает с базой, и он может её поменять, не обращаясь к разработчику.

Слово «константа» не означает, что значение нельзя изменить. Оно означает, что значение одно на всю базу.

## Как выбрать объект

Три объекта, три разные задачи. Удобно держать в голове такую таблицу.

| Объект | Для чего | Кто заводит значения | Пример |
| --- | --- | --- | --- |
| Справочник | Растущий список сущностей | Пользователь в работе | Клиенты, Товары, Склады |
| Перечисление | Фиксированный выбор из нескольких вариантов | Разработчик в Конфигураторе | Виды клиентов |
| Константа | Одно общее значение на всю базу | Пользователь, но значение одно | Наименование компании |

Неправильный выбор усложняет работу, причём заметить это получается не сразу.

Если сделать виды клиентов справочником, пользователи со временем заведут в нём дубли и опечатки, и классификация расползётся.

Если сделать наименование компании реквизитом справочника клиентов, оно продублируется столько раз, сколько у вас клиентов, и перестанет быть единым.

Если сделать список клиентов перечислением, то каждого нового клиента придётся заводить через Конфигуратор и обновление базы данных — то есть руками разработчика.

Проверочный вопрос звучит так: кто и как часто будет менять этот набор? Часто и силами пользователя — справочник. Редко и силами разработчика — перечисление. Набора нет, есть одно значение — константа.

## Что важно запомнить

1. Перечисление — фиксированный небольшой список вариантов, который задаёт разработчик; пользователь только выбирает из готового.
2. У значения перечисления есть имя и синоним, но нет кода и наименования: это часть конфигурации, а не данные.
3. Чтобы добавить вариант в перечисление, нужно изменить конфигурацию и обновить базу данных — набор защищён от случайного расширения.
4. Константа хранит одно значение на всю информационную базу и не повторяется у каждого элемента справочника.
5. Тип константы задаёт разработчик в Конфигураторе, а само значение вводит пользователь в режиме «1С:Предприятие».
6. Растущий список — справочник, фиксированный выбор — перечисление, одно общее значение — константа.
