# Практика. Сводная потребность в материалах

## Перед началом

Запустите конфигуратор учебной конфигурации **«Управление строительной компанией с логистикой»** и откройте модуль формы обработки `УчебнаяКонсоль`.

Понадобятся данные занятия 58: заявка «ЖК Северный» на цемент, кирпич и песок и два проведённых поступления по ней — цемент `100` с кирпичом `300` и кирпич `200`. Нужны также ещё одна-две заявки, в том числе на другой объект строительства, в которых встречаются те же материалы.

После каждой правки кода: `Ctrl+S`, затем `F5`, раздел **Разработка → Учебная консоль**, кнопка **Выполнить**.

## Шаг 1. Сложите потребность по материалам

Вопрос: «Сколько каждого материала просят все рабочие заявки?»

1. Добавьте процедуру и вызовите её из `Выполнить` вместо прежних вызовов:

```bsl
&НаСервере
Процедура ВывестиПотребность()

	Запрос = Новый Запрос;
	Запрос.Текст =
		"ВЫБРАТЬ
		|	ПРЕДСТАВЛЕНИЕ(ЗаявкаМатериалы.Материал) КАК Материал,
		|	СУММА(ЗаявкаМатериалы.Количество) КАК Потребность
		|ИЗ
		|	Документ.ЗаявкаНаМатериалы.Материалы КАК ЗаявкаМатериалы
		|ГДЕ
		|	НЕ ЗаявкаМатериалы.Ссылка.ПометкаУдаления
		|	И ЗаявкаМатериалы.Ссылка.Состояние <> ЗНАЧЕНИЕ(Перечисление.СостоянияЗаявок.Отклонена)
		|СГРУППИРОВАТЬ ПО
		|	ЗаявкаМатериалы.Материал
		|УПОРЯДОЧИТЬ ПО
		|	ЗаявкаМатериалы.Материал";

	Выборка = Запрос.Выполнить().Выбрать();

	Пока Выборка.Следующий() Цикл
		Сообщить(Выборка.Материал + ": " + Выборка.Потребность);
	КонецЦикла;

КонецПроцедуры
```

2. Сохраните, запустите, нажмите **Выполнить**.

В `СГРУППИРОВАТЬ ПО` стоит само поле `ЗаявкаМатериалы.Материал`, а в списке полей — его представление. Это допустимо: представление вычисляется из поля группировки и одно на группу.

3. Сверьте одну сумму руками: откройте все рабочие заявки с цементом и сложите количество в строках.

**Проверка:** каждый материал выведен одной строкой, и сумма по цементу совпала с ручным подсчётом.

## Шаг 2. Нарушьте правило группировки

1. Добавьте в список полей `ЗаявкаМатериалы.Количество КАК Количество` без агрегатной функции.
2. Запустите консоль. Запрос завершится ошибкой: поле не входит в группу.
3. Уберите поле.

Запишите в конспект своими словами, почему платформа не может выполнить такой запрос.

**Проверка:** вы видели ошибку и после исправления сводка выводится снова.

## Шаг 3. Добавьте число заявок и максимум

1. Добавьте в список полей ещё два:

```bsl
		|	КОЛИЧЕСТВО(РАЗЛИЧНЫЕ ЗаявкаМатериалы.Ссылка) КАК ЧислоЗаявок,
		|	МАКСИМУМ(ЗаявкаМатериалы.Количество) КАК КрупнейшаяСтрока
```

2. Допишите их в вывод и запустите.
3. Добавьте в одну из заявок вторую строку цемента, запишите заявку и запустите снова. `ЧислоЗаявок` для цемента не изменилось, а потребность выросла.
4. Для сравнения замените `КОЛИЧЕСТВО(РАЗЛИЧНЫЕ ...)` на `КОЛИЧЕСТВО(ЗаявкаМатериалы.Ссылка)` и запустите. Теперь число увеличилось на единицу — посчитаны строки, а не заявки. Верните `РАЗЛИЧНЫЕ` и удалите добавленную строку цемента.

**Проверка:** у каждого материала выведены потребность, число разных заявок и крупнейшая разовая потребность.

## Шаг 4. Разбейте потребность по объектам и отберите крупные

Вопрос: «Сколько каждого материала нужно каждому объекту, если считать только позиции больше 200?»

1. Добавьте процедуру `ВывестиПотребностьПоОбъектам`: скопируйте запрос шага 1 и добавьте в поля и в `СГРУППИРОВАТЬ ПО` объект строительства:

```bsl
		|	ПРЕДСТАВЛЕНИЕ(ЗаявкаМатериалы.Ссылка.ОбъектСтроительства) КАК Объект,
```

```bsl
		|СГРУППИРОВАТЬ ПО
		|	ЗаявкаМатериалы.Ссылка.ОбъектСтроительства,
		|	ЗаявкаМатериалы.Материал
```

2. Запустите. Цемент теперь выведен отдельно для каждого объекта.
3. Добавьте после группировки условие на группу:

```bsl
		|ИМЕЮЩИЕ
		|	СУММА(ЗаявкаМатериалы.Количество) > 200
```

4. Запустите. Остались только сочетания «объект — материал», где общая потребность больше `200`.
5. Попробуйте перенести это условие в `ГДЕ`. Запрос не выполнится: в `ГДЕ` агрегатные функции недопустимы. Верните `ИМЕЮЩИЕ`.

**Проверка:** потребность выведена в разрезе объектов, и в ответе только группы с суммой больше `200`.

## Шаг 5. Исправьте размножение строк в исполнении заявки

1. Откройте процедуру `ВывестиИсполнениеЗаявок` занятия 58 и вызовите её из `Выполнить`. Строка кирпича по-прежнему выводится дважды.
2. Замените в ней поля и добавьте группировку:

```bsl
		|ВЫБРАТЬ
		|	ЗаявкаМатериалы.Ссылка.Номер КАК НомерЗаявки,
		|	ПРЕДСТАВЛЕНИЕ(ЗаявкаМатериалы.Материал) КАК Материал,
		|	ЗаявкаМатериалы.Количество КАК Заказано,
		|	СУММА(ЕСТЬNULL(ПоступлениеМатериалы.Количество, 0)) КАК Поступило
```

```bsl
		|СГРУППИРОВАТЬ ПО
		|	ЗаявкаМатериалы.Ссылка,
		|	ЗаявкаМатериалы.НомерСтроки,
		|	ЗаявкаМатериалы.Материал,
		|	ЗаявкаМатериалы.Количество
```

Секция `СГРУППИРОВАТЬ ПО` встаёт после соединения и перед `УПОРЯДОЧИТЬ ПО`.

3. Поле `ОсталосьПолучить` пока вычислите во встроенном языке: `Выборка.Заказано - Выборка.Поступило`. Выражение с агрегатной функцией в запросе тоже возможно, но сейчас важнее увидеть сам результат группировки.
4. Запустите консоль.

Поле `Ссылка.Номер` стоит в списке полей без агрегатной функции, хотя в группировке его нет. Это допустимо, потому что номер однозначно определяется полем группировки `Ссылка`: у одной заявки один номер.

**Проверка:** кирпич выведен одной строкой «заказано 500, поступило 500, осталось 0».

## Проверка результата

Занятие пройдено, если выполняются пять условий:

1. Процедура `ВывестиПотребность` выводит общую потребность, число заявок и крупнейшую строку по каждому материалу рабочих заявок.
2. Процедура `ВывестиПотребностьПоОбъектам` группирует по объекту и материалу и отбирает группы условием `ИМЕЮЩИЕ`.
3. Вы видели ошибку поля, которое не входит в группу, и можете её объяснить.
4. Процедура `ВывестиИсполнениеЗаявок` выводит каждую строку заявки один раз при любом числе поступлений.
5. Вы можете объяснить, где граница этого исправления — когда материал записан в заявке двумя строками.
