# Практика. Репозиторий construction-erp

## Перед началом

Понадобится установленный Git (занятие 10) и учебная база **«Управление строительной компанией с логистикой»** в состоянии после занятия 98, включая активное расширение `ДоработкиСнабжения`.

Запустите конфигуратор учебной базы под пользователем «Администратор» и выгрузите базу в новый файл `.dt` в папку резервных копий: **Администрирование → Выгрузить информационную базу**. Сегодня мы создадим ещё одну базу и будем загружать в неё конфигурацию, и резервная копия должна быть сделана до первого шага.

Команды Git ниже написаны для Git Bash, в PowerShell они такие же. Создавать служебные файлы удобнее всего в «Блокноте» или в редакторе вашей среды разработки.

Выгрузка из занятия 10 в конспекте `1c-learning-notes` остаётся как есть. Она была учебной; у проекта теперь будет собственный репозиторий.

## Шаг 1. Создайте репозиторий проекта

Перейдите в каталог, где лежит конспект `1c-learning-notes`, — новый репозиторий будет рядом с ним, а не внутри.

```bash
mkdir construction-erp
cd construction-erp
git init
git config --global core.quotepath false
git status
```

`git init` создаёт пустой репозиторий. Настройка `core.quotepath false` с ключом `--global` действует во всех ваших репозиториях: Git будет показывать кириллические имена файлов как есть, а не восьмеричными кодами. Без неё вывод `git status` по выгрузке 1С превращается в набор чисел.

**Проверка:** `git status` сообщает о ветке без коммитов.

## Шаг 2. Создайте служебные файлы

1. Создайте в каталоге `construction-erp` файл `.gitignore` и запишите в него пять строк, каждую на своей строке: `*.dt`, `*.cf`, `*.cfe`, `ConfigDumpInfo.xml`, `.idea/`.
2. Создайте файл `.gitattributes` и запишите в него одну строку: `* -text`.
3. Перечитайте обе записи и сверьте с теорией, зачем нужна каждая строка. Строка `ConfigDumpInfo.xml` без каталога в начале действует для файла с таким именем в любом каталоге репозитория — в выгрузке конфигурации и в выгрузке расширения.

**Проверка:** в каталоге два служебных файла; `git status` показывает их как неотслеживаемые.

## Шаг 3. Выгрузите конфигурацию

1. В конфигураторе учебной базы выполните **Конфигурация → Выгрузить конфигурацию в файлы**.
2. В качестве каталога выгрузки укажите `src\cf` внутри `construction-erp`. Каталогов `src` и `cf` пока нет — создайте их в окне выбора.
3. Если окно предлагает выбрать формат, выберите иерархический. Если в нём есть флаг выгрузки только изменений, снимите его: первая выгрузка всегда полная.
4. Запустите выгрузку и дождитесь окончания.

**Проверка:** в `src\cf` появились файл `Configuration.xml`, каталоги `Catalogs`, `Documents`, `Roles` и файл `ConfigDumpInfo.xml`.

## Шаг 4. Найдите в выгрузке знакомые объекты

Откройте каталог `src\cf` в проводнике и найдите:

1. Файл `Catalogs/ОбъектыСтроительства.xml`. Откройте его в «Блокноте» и найдите реквизиты `Адрес`, `ДатаНачалаРабот` и `Заказчик` — по тегу с именем каждого.
2. Файл `Documents/ПередачаМатериалов/Ext/ObjectModule.bsl`. Откройте его: это модуль объекта передачи с процедурами `ОбработкаЗаполнения`, `ОбработкаПроведения` и `ПроверитьОстаткиМатериалов`.
3. Каталог `Documents/ПередачаМатериалов/Forms`. Внутри — форма документа: `Ext/Form.xml` с элементами и `Ext/Form/Module.bsl` с модулем формы, где лежит обработчик `ОстаткиСклада` из занятия 79.
4. Файл `Roles/Прораб/Ext/Rights.xml`. Найдите в нём текст ограничения доступа к передачам из занятия 98.

Запишите в конспект, в каком файле лежит каждая из четырёх вещей. Это пригодится на каждом следующем занятии: читая историю, вы будете узнавать объект по пути.

**Проверка:** в конспекте четыре пути, и вы открыли каждый файл.

## Шаг 5. Выгрузите расширение

1. Выполните **Конфигурация → Расширения конфигурации**, выделите `ДоработкиСнабжения` и откройте его конфигурацию, как на занятии 97.
2. В окне конфигурации расширения выполните **Конфигурация → Выгрузить конфигурацию в файлы**.
3. Укажите каталог `src\cfe\ДоработкиСнабжения` внутри `construction-erp`.
4. Откройте выгрузку и найдите модуль объекта заимствованного документа с процедурой `Расш1_ПередЗаписью` и аннотацией `&Перед("ПередЗаписью")`.

**Проверка:** в `src\cfe\ДоработкиСнабжения` есть `Configuration.xml` расширения и модуль с процедурой `Расш1_ПередЗаписью`.

## Шаг 6. Сделайте первый коммит

```bash
git status
git status --ignored
git add .
git commit -m "Add configuration and extension source after stage 8"
git log --oneline
```

Сравните вывод двух первых команд. `git status` показывает `.gitignore`, `.gitattributes` и каталог `src/`. `git status --ignored` дополнительно перечисляет то, что Git игнорирует: там оба файла `ConfigDumpInfo.xml`. Они на диске, но в коммит не попадут.

**Проверка:** в истории один коммит; `git status` чист; `git ls-files` не содержит ни одного `ConfigDumpInfo.xml`.

## Шаг 7. Соберите конфигурацию заново

Проверим, что в репозитории есть всё, из чего состоит конфигурация.

1. В конфигураторе учебной базы выполните **Конфигурация → Сохранить конфигурацию в файл** и сохраните её в папку резервных копий как `УСК_этап8.cf`. Это эталон для сравнения.
2. В окне запуска 1С нажмите **Добавить**, выберите создание новой информационной базы **без конфигурации**, назовите базу `УСК_Проверка` и разместите её в отдельном каталоге.
3. Откройте `УСК_Проверка` в конфигураторе и выполните **Конфигурация → Открыть конфигурацию**. Дерево пустое.
4. Выполните **Конфигурация → Загрузить конфигурацию из файлов** и укажите каталог `src\cf` репозитория. Подтвердите замену конфигурации.
5. Выполните **Конфигурация → Сравнить конфигурации** и сравните основную конфигурацию с файлом `УСК_этап8.cf`. Различий нет.
6. Выполните `F7` и примите изменения структуры. База пуста, поэтому обновление займёт секунды.

**Проверка:** сравнение собранной конфигурации с `УСК_этап8.cf` не показывает различий, база данных `УСК_Проверка` обновлена.

## Шаг 8. Соберите расширение

1. В конфигураторе `УСК_Проверка` откройте **Конфигурация → Расширения конфигурации** и добавьте расширение с именем `ДоработкиСнабжения`.
2. Откройте его конфигурацию и в окне расширения выполните **Конфигурация → Загрузить конфигурацию из файлов** из каталога `src\cfe\ДоработкиСнабжения`.
3. Найдите в дереве расширения заимствованный документ `ЗаявкаНаМатериалы` и процедуру `Расш1_ПередЗаписью` в его модуле объекта.
4. Обновите конфигурацию базы данных в окне расширения.

База `УСК_Проверка` сделала своё дело и дальше не понадобится: удалите её из списка баз в окне запуска и удалите её каталог. Файл `.dt`, сделанный в начале занятия, сохраните — на занятии 103 из него получится копия рабочей базы для проверки поставки.

**Проверка:** в `УСК_Проверка` есть расширение `ДоработкиСнабжения` с тем же модулем, что и в учебной базе.

## Шаг 9. Выгрузите изменения повторно

Выгрузка — постоянная часть работы, а не разовое действие. Посмотрим, как она выглядит, когда ничего не менялось.

1. Вернитесь в конфигуратор учебной базы, в основную конфигурацию.
2. Снова выполните **Конфигурация → Выгрузить конфигурацию в файлы** в каталог `src\cf`, на этот раз с флагом выгрузки только изменений, если он есть. Если флага нет, выполните полную выгрузку в тот же каталог.
3. Выполните `git status`.

Git сообщает, что изменений нет. Содержимое файлов совпадает с закоммиченным, и даже полная перезапись каталога ничего не меняет в истории.

4. Запишите в конспект правило из теории: после изменения конфигурации — выгрузить и закоммитить; после получения изменений — загрузить и обновить базу.

**Проверка:** повторная выгрузка без изменений конфигурации оставляет `git status` чистым, правило записано.

## Проверка результата

Занятие пройдено, если выполняются шесть условий:

1. Рядом с конспектом есть репозиторий `construction-erp` с одним коммитом.
2. В репозитории есть `src/cf` с выгрузкой конфигурации и `src/cfe/ДоработкиСнабжения` с выгрузкой расширения.
3. `.gitignore` исключает `.dt`, `.cf`, `.cfe`, `ConfigDumpInfo.xml` и `.idea/`; `.gitattributes` содержит `* -text`.
4. Git показывает кириллические имена файлов без кодов.
5. Конфигурация, собранная из `src/cf` в пустой базе `УСК_Проверка`, не отличается от `УСК_этап8.cf`.
6. Повторная выгрузка без изменений конфигурации не меняет файлы в репозитории.
