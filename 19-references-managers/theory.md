# Теория. Ссылка, объект и менеджер

## Ссылка

До сих пор код работал со значениями, которые мы сами же и писали. Теперь нужно добраться до реальных данных справочников — до элементов «Цемент М500» и «Центральный склад», которые вы заводили в занятиях 6 и 8.

**Ссылка** — это значение, которое указывает на конкретный элемент справочника. У неё есть свой тип, например `СправочникСсылка.Товары`.

Этот тип вам уже знаком: на занятии 8 у реквизита `Ответственный` справочника `Склады` был тип `СправочникСсылка.Сотрудники` — то есть в реквизите хранится ссылка на элемент справочника `Сотрудники`.

Ссылка лёгкая: сама она не содержит ни наименования, ни телефона, ни даты приёма, а только указание, где эти данные взять. Поэтому ссылку дёшево хранить, копировать и передавать между процедурами.

## Объект

**Объект** — это данные элемента, загруженные в память целиком. Тип объекта называется `СправочникОбъект.Товары`. У объекта можно читать реквизиты, менять их и записывать изменения в базу.

Объект получают из ссылки методом `ПолучитьОбъект()`:

```bsl
Объект = СсылкаНаТовар.ПолучитьОбъект();
```

Разница практическая: ссылка — «адрес», объект — «загруженная карточка». Получать объект без нужды не стоит: это дороже, чем работать со ссылкой. Изменять и записывать объект будем на занятии 20.

## Менеджер справочника

Чтобы найти элемент, нужна точка входа в справочник. Такая точка входа — **менеджер справочника**, и записывается она просто: `Справочники.Товары`.

Менеджер — это не элемент и не список элементов. Это «стойка обслуживания» справочника: через него ищут элементы, перебирают их и создают новые. Сам менеджер никаких данных в себе не держит.

```bsl
СсылкаНаТовар = Справочники.Товары.НайтиПоНаименованию("Цемент М500");
```

Читается так: у менеджера справочника `Товары` попросили найти элемент по наименованию и получили ссылку.

## Разыменование

Если в руках есть ссылка, её реквизиты читаются через точку:

```bsl
СсылкаНаСклад = Справочники.Склады.НайтиПоНаименованию("Центральный склад");
Сообщить(СсылкаНаСклад.Адрес);
Сообщить(СсылкаНаСклад.Ответственный.Наименование);
```

Такое чтение данных по ссылке называют **разыменованием**: платформа сама понимает, что за ссылкой надо сходить в базу, и достаёт нужный реквизит.

В последней строке точек две, и обращений к базе тоже два: сначала платформа читает у склада реквизит `Ответственный` (это ссылка на сотрудника), потом по этой ссылке читает наименование сотрудника. Каждое звено цепочки — отдельное обращение.

Для одной строки это незаметно, а внутри цикла по тысяче элементов — уже тысячи обращений. Поэтому правило: разыменование удобно для единичного чтения и нежелательно в цикле. Подробно про цену обращений поговорим на занятии 22.

## Поиск элемента

У менеджера есть два простых метода поиска:

```bsl
Товар = Справочники.Товары.НайтиПоНаименованию("Цемент М500");
Другой = Справочники.Товары.НайтиПоКоду("000000001");
```

Самое важное — что происходит, когда элемент не найден. Платформа **не выдаёт ошибку** и **не возвращает `Неопределено`**. Она возвращает **пустую ссылку**: значение правильного типа `СправочникСсылка.Товары`, которое ни на какой элемент не указывает.

Это удобно: тип результата всегда один и тот же, и код не ломается. Но проверять результат обязательно, иначе разыменование пустой ссылки вернёт пустые значения, и вы получите пустые сообщения вместо понятной ошибки.

Проверяют двумя способами:

```bsl
Если Товар.ПустаяСсылка() Тогда
	Сообщить("Товар не найден");
КонецЕсли;

Если НЕ ЗначениеЗаполнено(Товар) Тогда
	Сообщить("Товар не найден");
КонецЕсли;
```

Функция `ЗначениеЗаполнено()` знакома с занятия 12 и для ссылок работает ровно так же: пустая ссылка считается незаполненным значением.

## Перебор всех элементов

Чтобы пройти по всем элементам справочника, у менеджера просят **выборку**:

```bsl
Выборка = Справочники.Товары.Выбрать();

Пока Выборка.Следующий() Цикл
	Сообщить(Выборка.Наименование + " — " + Строка(Выборка.Цена));
КонецЦикла;
```

`Выбрать()` возвращает выборку — курсор по элементам справочника. `Следующий()` двигает курсор на один элемент и возвращает `Истина`, пока элементы есть, и `Ложь`, когда они закончились.

Это тот самый цикл `Пока` из занятия 14, и теперь видно, зачем он нужен: сколько будет элементов, заранее неизвестно, поэтому цикл `Для` со счётчиком тут не подходит.

Внутри цикла у выборки доступны `Выборка.Ссылка` (ссылка на текущий элемент), `Выборка.Наименование`, `Выборка.Код` и все реквизиты — например `Выборка.Артикул` и `Выборка.Цена`.

## Почему этот код живёт на сервере

Менеджеры справочников доступны только на сервере: `Справочники.Товары` в клиентском коде не существует. Причина та же, что у таблицы значений на занятии 18 — работа с базой данных ведётся на сервере.

Поэтому весь код этого занятия пишется в процедурах с директивой `&НаСервере`, а клиентский обработчик кнопки их только вызывает. Как устроен механизм клиент-серверного взаимодействия, разберём на занятии 22.

## Что важно запомнить

1. Ссылка указывает на элемент и сама реквизитов не содержит; объект — это данные элемента, загруженные в память.
2. Объект получают из ссылки методом `ПолучитьОбъект()`, и делают это только когда данные нужно менять.
3. Менеджер справочника `Справочники.Товары` — точка входа: через него ищут, перебирают и создают элементы.
4. Разыменование `Склад.Ответственный.Наименование` читает данные по ссылке; каждая точка — отдельное обращение к базе, поэтому в цикле так делать дорого.
5. `НайтиПоНаименованию()` и `НайтиПоКоду()` при неудаче возвращают пустую ссылку, а не ошибку и не `Неопределено`; проверяют через `ПустаяСсылка()` или `ЗначениеЗаполнено()`.
6. Все элементы перебирают связкой `Выбрать()` и `Пока Выборка.Следующий() Цикл`.
7. Менеджеры справочников доступны только на сервере, поэтому такой код помечают `&НаСервере`.
