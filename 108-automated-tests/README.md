# Занятие 108. Автоматическая проверка: обработка тестов

## Цель

Научиться превращать главные тест-кейсы проведения и остатков в код, который проверяет их за секунды и не оставляет в базе следов. Разобраться, как устроен автоматический тест — подготовка, действие, проверка, — зачем каждый тест выполняется в транзакции, которую потом отменяют, почему после ошибки внутри транзакции к базе больше не обращаются и как убедиться, что тест вообще способен упасть.

## Результат занятия

В подсистеме **Разработка** появится обработка `ТестыСнабжения`, доступная только администратору. Кнопка **Выполнить тесты** запускает пять тестов: поступление даёт приход, передача даёт расход, передача ровно остатка проводится, передача сверх остатка не проводится, передача на завершённый объект не проводится. Протокол показывает результат каждой проверки. После прогона в базе нет ни тестовых складов, ни тестовых документов. Обработка попадает в `main` через ветку `feature/supply-tests`.

## Ключевые термины

Автоматический тест, подготовка, действие, проверка, утверждение, протокол тестов, изоляция теста, транзакция, `НачатьТранзакцию`, `ОтменитьТранзакцию`, испорченная транзакция, `ПолучитьСообщенияПользователю`, проверка теста на способность упасть, YAxUnit, Vanessa Automation.
