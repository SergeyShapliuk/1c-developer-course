# Практика. Обработка ТестыСнабжения

## Перед началом

Понадобятся учебная база, совпадающая с `main` репозитория `construction-erp`, и знакомые объекты: документы `ПоступлениеМатериалов` и `ПередачаМатериалов` с проверками занятий 48, 52, 67, 101 и 102, общий модуль `ОстаткиМатериаловСервер` с функцией `ОстатокМатериала` (занятие 65), справочники `Склады`, `Товары`, `ОбъектыСтроительства` с реквизитом `Завершен`, `Клиенты` с реквизитом `ВидКлиента`, `Сотрудники`, подсистема **Разработка**.

1. Запустите конфигуратор учебной базы под пользователем «Администратор» и выгрузите базу в новый файл `.dt`.
2. Выгрузите конфигурацию в `src\cf` и убедитесь, что `git status` чист.
3. Создайте ветку задачи:

```bash
git switch main
git pull
git switch -c feature/supply-tests
```

Тесты сегодня выполняются в учебной базе. Это безопасно: каждый тест отменяет свою транзакцию, и после прогона база остаётся такой же, как до него. На шаге 6 вы это проверите.

## Шаг 1. Создайте обработку

1. Выполните **Обработки → Добавить**. Задайте **Имя** — `ТестыСнабжения`, **Синоним** — «Тесты снабжения».
2. На вкладке **Подсистемы** отметьте **Разработка**.
3. Создайте основную форму обработки.
4. В форме на вкладке **Команды** добавьте команду `ВыполнитьТесты` с заголовком «Выполнить тесты» и перетащите её в командную панель формы. Создайте для команды обработчик на клиенте.
5. `Ctrl+S`.

**Проверка:** у обработки `ТестыСнабжения` есть форма с командой «Выполнить тесты», обработка входит в подсистему **Разработка**.

## Шаг 2. Напишите вспомогательные процедуры

Откройте окно редактирования обработки, вкладку **Прочее**, и откройте **Модуль менеджера**. Тесты будут жить здесь: это серверный модуль, не связанный с формой.

Начните с утверждений — процедур, которые сравнивают и пишут в протокол:

```bsl
// Сравнивает ожидаемое значение с фактическим и записывает результат в протокол.
Процедура ПроверитьРавенство(Ожидаемое, Фактическое, Описание, Итоги)

	Если Ожидаемое = Фактическое Тогда
		Итоги.Пройдено = Итоги.Пройдено + 1;
		Итоги.Протокол.Добавить("ПРОЙДЕН: " + Описание);
	Иначе
		ЗаписатьПровал(Описание + ": ожидалось " + Строка(Ожидаемое)
			+ ", получено " + Строка(Фактическое), Итоги);
	КонецЕсли;

КонецПроцедуры

Процедура ЗаписатьПровал(Текст, Итоги)

	Итоги.Провалено = Итоги.Провалено + 1;
	Итоги.Протокол.Добавить("ПРОВАЛЕН: " + Текст);

КонецПроцедуры
```

И документы:

```bsl

КонецПроцедуры

// Возвращает Истина, если документ провёлся, и Ложь, если проведение отклонено.
```

## Шаг 3. Напишите позитивные тесты

Добавьте в модуль менеджера три теста. Каждый устроен одинаково: транзакция, подготовка, действие, проверка, отмена транзакции.

```bsl
Процедура Тест_ПоступлениеДаётПриход(Итоги)

	Описание = "Поступление 10 даёт остаток 10";

	НачатьТранзакцию();
	Попытка
		Данные = НовыеТестовыеДанные();
		ПровестиПоступление(Данные, 10);
		ПроверитьРавенство(10, ОстатокТестовогоМатериала(Данные), Описание, Итоги);
	Исключение
		ЗаписатьПровал(Описание + ": " + ОписаниеОшибки(), Итоги);
	КонецПопытки;
	ОтменитьТранзакцию();

КонецПроцедуры

Процедура Тест_ПередачаДаётРасход(Итоги)

	Описание = "Передача 4 из 10 оставляет 6";

	НачатьТранзакцию();
	Попытка
		Данные = НовыеТестовыеДанные();
		ПровестиПоступление(Данные, 10);
		ПровестиПередачу(НоваяПередача(Данные, 4));
		ПроверитьРавенство(6, ОстатокТестовогоМатериала(Данные), Описание, Итоги);
	Исключение
		ЗаписатьПровал(Описание + ": " + ОписаниеОшибки(), Итоги);
	КонецПопытки;
	ОтменитьТранзакцию();

КонецПроцедуры

Процедура Тест_ПередачаРовноОстатка(Итоги)

	Описание = "Передача ровно остатка 10 проводится и оставляет 0";

	НачатьТранзакцию();
	Попытка
		Данные = НовыеТестовыеДанные();
		ПровестиПоступление(Данные, 10);
		ПровестиПередачу(НоваяПередача(Данные, 10));
		ПроверитьРавенство(0, ОстатокТестовогоМатериала(Данные), Описание, Итоги);
	Исключение
		ЗаписатьПровал(Описание + ": " + ОписаниеОшибки(), Итоги);
	КонецПопытки;
	ОтменитьТранзакцию();

КонецПроцедуры
```

Разберите, зачем каждая строка.

`НачатьТранзакцию()` стоит до создания данных: всё, что тест создаст, войдёт в транзакцию. `ОтменитьТранзакцию()` стоит после `КонецПопытки` и выполняется всегда — и когда тест прошёл, и когда упал с исключением. Если бы отмена стояла внутри `Попытка`, после исключения транзакция осталась бы открытой.

Если проведение в позитивном тесте неожиданно отклонено, `Записать` вызовет исключение, и тест попадёт в ветку `Исключение`. Это тоже провал, и в протокол попадёт текст ошибки.

Тест «ровно остатка» — граница из занятий 67 и 107: самое уязвимое место контроля.

**Проверка:** три позитивных теста в модуле менеджера, синтаксический контроль ошибок не находит.

## Шаг 4. Напишите негативные тесты

```bsl
Процедура Тест_ПередачаСверхОстаткаНеПроводится(Итоги)

	Описание = "Передача 11 при остатке 10 не проводится";

	НачатьТранзакцию();
	Попытка
		Данные = НовыеТестовыеДанные();
		ПровестиПоступление(Данные, 10);
		Передача = НоваяПередача(Данные, 11);

		ПолучитьСообщенияПользователю(Истина);
		Проведена = ПопробоватьПровестиПередачу(Передача);
		Сообщения = ПолучитьСообщенияПользователю(Истина);

		// После отказа транзакция испорчена: к базе больше не обращаемся.
		ПроверитьРавенство(Ложь, Проведена, Описание, Итоги);
		ПроверитьРавенство(Истина, ЕстьСообщение(Сообщения, "Не хватает материала"),
			Описание + ": есть сообщение о нехватке", Итоги);
	Исключение
		ЗаписатьПровал(Описание + ": " + ОписаниеОшибки(), Итоги);
	КонецПопытки;
	ОтменитьТранзакцию();

КонецПроцедуры

Процедура Тест_ПередачаНаЗавершенныйОбъектНеПроводится(Итоги)

	Описание = "Передача на завершённый объект не проводится";

	НачатьТранзакцию();
	Попытка
		Данные = НовыеТестовыеДанные(Истина);
		ПровестиПоступление(Данные, 10);
		Передача = НоваяПередача(Данные, 1);

		ПолучитьСообщенияПользователю(Истина);
		Проведена = ПопробоватьПровестиПередачу(Передача);
		Сообщения = ПолучитьСообщенияПользователю(Истина);

		ПроверитьРавенство(Ложь, Проведена, Описание, Итоги);
		ПроверитьРавенство(Истина, ЕстьСообщение(Сообщения, "завершён"),
			Описание + ": есть сообщение о завершённом объекте", Итоги);
	Исключение
		ЗаписатьПровал(Описание + ": " + ОписаниеОшибки(), Итоги);
	КонецПопытки;
	ОтменитьТранзакцию();

КонецПроцедуры
```

Обратите внимание на порядок в негативном тесте. Попытка провести — последнее обращение к базе. После неё тест проверяет только переменную `Проведена` и массив сообщений: ни то, ни другое не требует базы. Если бы после отказа тест спросил остаток, `ОстатокМатериала` выполнил бы запрос в испорченной транзакции и завершился ошибкой.

Первый вызов `ПолучитьСообщенияПользователю(Истина)` очищает очередь, чтобы в проверку не попали сообщения от подготовки данных. Второй забирает сообщения отказа.

Во втором тесте материала на складе хватает: отказать может только проверка завершённого объекта. Так тест проверяет ровно одно правило.

**Проверка:** два негативных теста, синтаксический контроль ошибок не находит.

## Шаг 5. Подключите запуск

```bsl
// Выполняет все тесты снабжения и возвращает протокол — массив строк.
Функция ВыполнитьВсеТесты() Экспорт

	Итоги = Новый Структура("Пройдено, Провалено, Протокол", 0, 0, Новый Массив);

	Тест_ПоступлениеДаётПриход(Итоги);
	Тест_ПередачаДаётРасход(Итоги);
	Тест_ПередачаРовноОстатка(Итоги);
	Тест_ПередачаСверхОстаткаНеПроводится(Итоги);
	Тест_ПередачаНаЗавершенныйОбъектНеПроводится(Итоги);

	Итоги.Протокол.Добавить("Итого проверок: пройдено " + Строка(Итоги.Пройдено)
		+ ", провалено " + Строка(Итоги.Провалено));

	Возврат Итоги.Протокол;

КонецФункции
```

В модуле формы обработки заполните обработчик команды:

```bsl
&НаКлиенте
Процедура ВыполнитьТесты(Команда)

	Протокол = ВыполнитьТестыНаСервере();

	Для Каждого СтрокаПротокола Из Протокол Цикл
		Сообщить(СтрокаПротокола);
	КонецЦикла;

КонецПроцедуры

&НаСервереБезКонтекста
Функция ВыполнитьТестыНаСервере()

	Возврат Обработки.ТестыСнабжения.ВыполнитьВсеТесты();

```

Форма делает одно — запускает тесты и показывает протокол. Тесты выполняются одним серверным вызовом, без контекста формы.

`Ctrl+S`, `F7`.

**Проверка:** синтаксический контроль ошибок не находит, обработка видна в разделе **Разработка**.

## Шаг 6. Запустите тесты

1. Запустите приложение под администратором и откройте **Разработка → Тесты снабжения**.
2. Нажмите **Выполнить тесты**. В окне сообщений — семь строк «ПРОЙДЕН» и итог: пройдено `7`, провалено `0`. Проверок семь, а тестов пять: в каждом негативном тесте две проверки.
3. Откройте справочник **Склады**: склада «Тест: склад» нет. Откройте журнал поступлений и форму списка регистра `ОстаткиМатериалов`: тестовых документов и движений нет.
4. Запустите тесты ещё раз. Результат тот же: тесты не зависят ни от предыдущего прогона, ни друг от друга.

Если какая-то проверка провалена, прочитайте строку протокола: в ней ожидаемое и фактическое значение или текст ошибки. Частые причины — опечатка во фрагменте сообщения, неоперативное проведение передачи и обязательный реквизит справочника, который тест не заполнил.

**Проверка:** все семь проверок пройдены, после прогона в базе нет тестовых данных, повторный прогон даёт тот же результат.

## Шаг 7. Убедитесь, что тест умеет падать

1. В конфигураторе откройте модуль объекта `ПередачаМатериалов` и закомментируйте строку `Отказ = Истина;` в проверке завершённого объекта (занятие 101): поставьте в самом начале строки два символа `//`.
2. `Ctrl+S`, `F7`, запустите тесты.
3. Тест завершённого объекта провален: «ожидалось Ложь, получено Истина» — передача провелась. Вторая проверка этого теста прошла: сообщение выдано, но отказа нет. Так протокол показывает, какая именно часть правила сломана.
4. Удалите добавленные `//`, ничего больше в строке не меняя. `Ctrl+S`, `F7`, запустите тесты — снова всё пройдено.
5. Выгрузите конфигурацию и выполните `git status`. Модуль объекта передачи в списке изменённых файлов отсутствует: правило возвращено в точности.

**Проверка:** при сломанном правиле тест провалился, после восстановления прошёл; `git status` не показывает изменений модуля объекта передачи.

## Проверка результата

Занятие пройдено, если выполняются шесть условий:

1. В подсистеме **Разработка** есть обработка `ТестыСнабжения`, тесты живут в модуле её менеджера.
2. Пять тестов — три позитивных и два негативных — дают семь пройденных проверок.
3. Каждый тест выполняется в своей транзакции и отменяет её; после прогона в базе нет тестовых данных.
4. В негативных тестах попытка провести — последнее обращение к базе; сообщение отказа проверяется через `ПолучитьСообщенияПользователю`.
5. Тест завершённого объекта провалился, когда правило было отключено, и прошёл после его восстановления.
6. Обработка слита в `main` через ветку задачи.
