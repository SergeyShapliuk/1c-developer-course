# Практика. Отчёт «Обеспечение объектов»

## Самостоятельная задача

Готового решения в этом разделе нет. Прочитайте постановку, решите задачу сами и только потом открывайте разбор.

Снабженец каждое утро просил разработчика запустить справку по объекту в учебной консоли — функцию `СправкаПоОбъекту` занятия 68. Теперь он хочет открывать её сам: выбрать объект строительства в разделе **Логистика** и увидеть, что объект заказал по рабочим заявкам, сколько из этого поступило по поступлениям, введённым на основании этих заявок, сколько осталось получить, сколько выдано на объект и сколько каждого материала сейчас лежит на всех складах вместе. То, что ещё не получено, должно бросаться в глаза. Руководителю тот же отчёт нужен картинкой.

Работайте в учебной конфигурации **«Управление строительной компанией с логистикой»**. Правила подсчёта граф — те же, что на занятии 68; функцию `СправкаПоОбъекту` не меняйте: она понадобится для сверки.

Задача разбита на пять этапов. **Доводите этап до его проверки и только потом переходите к следующему.** Неверное число в отчёте из четырёх наборов придётся искать во всех наборах и связях сразу.

### Этап 1. Ожидаемый ответ

1. Запустите в учебной консоли процедуру `ВывестиСправкуСнабженца` занятия 68 для «ЖК Южный» и запишите справку в конспект. Это ожидаемый ответ отчёта.
2. Сделайте то же для «ЖК Северный».
3. Выберите или создайте объект строительства без единой заявки, например «ЖК Западный» в справочнике `ОбъектыСтроительства`.

Данные «ЖК Южный» с занятия 68 уже содержат всё, что проявляет типичные ошибки: цемент двумя строками одной заявки, отклонённую заявку на песок, два проведённых поступления по одной заявке — кирпич `300` и `200`, поступление без основания на второй склад, передачу на объект. Непроведённое поступление по основанию вы создадите сами в шаге 7 чек-листа. Если вы удаляли эти документы, восстановите их по этапу 1 занятия 68.

**Проверка этапа:** справки двух объектов записаны до того, как создан отчёт.

### Этап 2. Схема отчёта

Создайте отчёт `ОбеспечениеОбъектов` с синонимом «Обеспечение объектов» в подсистеме **Логистика** и его основную схему компоновки данных. В отчёте одна строка на материал рабочих заявок объекта и шесть колонок: материал, заказано, поступило, осталось получить, выдано, на складах. Материал, по которому ничего не поступало и не выдавалось, остаётся в отчёте с нулями. Внизу — общий итог.

**Проверка этапа:** отчёт по «ЖК Южный» совпадает со справкой из этапа 1 по каждому числу.

### Этап 3. Объект и обязательность

Объект строительства пользователь выбирает на форме отчёта. Без выбранного объекта отчёт не строится: результат пуст, пользователь получает сообщение «Выберите объект строительства». Ни в окне **Настройки**, ни в окне **Еще → Изменить вариант...** пользователь не может изменить ничего, что меняет правила подсчёта.

**Проверка этапа:** без объекта — сообщение и пустой результат; со сменой объекта отчёт меняется; в настройках нет параметров периода.

### Этап 4. Представление

1. Материалы, по которым осталось получить больше нуля, выделены в отчёте.
2. Есть второй вариант отчёта «Диаграмма обеспечения»: по каждому материалу столбцы «заказано», «поступило» и «выдано».

**Проверка этапа:** выделены только недополученные материалы; диаграмма показывает те же числа, что таблица.

### Этап 5. Отчёт на движениях

Пройдите чек-лист ниже, сверяя отчёт со справкой после каждого шага.

### Требования

1. Ни одного запроса в коде: данные — только в наборах данных схемы.
2. Каждый набор данных, который служит приёмником связи, возвращает не больше одной строки на ключ связи.
3. Правила учёта — проведённость, состояние заявки, пометка удаления — стоят в `ГДЕ` запросов, а не в отборах настроек.
4. Объект строительства — параметр данных с быстрым доступом; параметры, которые пользователь менять не должен, закрыты ограничением доступности.
5. Код — только в модуле отчёта, только в `ПриКомпоновкеРезультата` и только для проверки обязательного объекта.

## Критерии готовности

Каждое утверждение проверяется, не заглядывая в схему.

1. Отчёт по «ЖК Южный» и «ЖК Северный» совпадает со справкой `СправкаПоОбъекту` по каждому материалу и каждой графе.
2. Цемент, заказанный двумя строками одной заявки, выведен одной строкой с суммой.
3. Материал без поступлений и выдачи выведен с нулями в графах «поступило» и «выдано» и полным количеством в графе «осталось получить».
4. Непроведённые документы, отклонённые и помеченные на удаление заявки на отчёт не влияют, и пользователь не может включить их из формы отчёта.
5. Материал на двух складах выведен одной строкой с суммой остатков.
6. Без выбранного объекта отчёт пуст и выводит сообщение «Выберите объект строительства».
7. Выделены только материалы, по которым осталось получить больше нуля.
8. Вариант «Диаграмма обеспечения» показывает те же числа, что основной вариант.

## Типичные ошибки

**1. Размножение через связь.** Симптом: заказано по кирпичу `1000` вместо `500`. Причина: приёмник `Поступило` выбирает строки поступлений без группировки, и строка заявки нашла две пары — по одной на каждое поступление. Исправление: сгруппировать приёмник по материалу в его запросе (занятия 62–63, 73).

**2. Остаток размножил строку.** Симптом: после поступления на второй склад цемент заказан `200`. Причина: набор `НаСкладах` возвращает строку на каждую пару «материал — склад». Исправление: сгруппировать остатки по материалу в запросе набора.

**3. Материал без поступлений исчез.** Симптом: в отчёте нет кирпича, пока по нему ничего не пришло. Причина: связь направлена от `Поступило` к `Заказано`. Исправление: источник всех связей — набор `Заказано`: отчёт отвечает на вопрос о заказанном (занятие 73).

**4. Пустота вместо нуля.** Симптом: у материала без поступлений пусты графы «поступило» и «осталось получить». Причина: поле приёмника без пары пусто, и вычисление с ним тоже. Исправление: `ЕстьNULL` в выражении вычисляемого поля и в выражениях ресурсов полей, пришедших из приёмников (занятие 74).

**5. Правило учёта в отборе.** Симптом: в настройках отчёта есть отбор «Проведен», и после его отключения графа «поступило» выросла от черновика. Причина: условие учёта поставлено в настройки. Исправление: условие в `ГДЕ` запроса набора (занятие 72).

**6. Чужие поступления.** Симптом: графа «поступило» больше, чем в справке. Причина: в наборе `Поступило` нет условия на объект заявки-основания, и в отчёт попали поступления других объектов. Исправление: условие `Ссылка.ДокументОснование.ОбъектСтроительства = &ОбъектСтроительства` вместе с правилами рабочей заявки (занятие 68).

**7. «На складах» на чужую дату.** Симптом: пользователь выбрал в настройках дату, и графа «на складах» перестала совпадать со справкой. Причина: параметр `Период` таблицы остатков остался доступным. Исправление: ограничение доступности у параметра (занятие 72).

**8. Отчёт без объекта.** Симптом: без объекта отчёт выводит пустой лист — или, что хуже, сводку по заявкам всех объектов сразу, если система компоновки отбросила условие с незаданным параметром. Пользователь в обоих случаях принимает результат за ответ. Причина: нет проверки обязательного параметра. Исправление: проверка в `ПриКомпоновкеРезультата` с сообщением (занятие 79).

**9. Код выбирает данные.** Симптом: в модуле отчёта появился `Новый Запрос`, а схема пуста или дублирует его. Причина: отчёт построен как обработка. Исправление: данные — в наборах, код — только для того, что схема выразить не может (занятия 69, 79).

### Наборы данных

Четыре набора — по одному на графу, которую даёт отдельный источник. Каждый сгруппирован по материалу. Все условия учёта — в `ГДЕ`. Параметр `&ОбъектСтроительства` используется в трёх наборах, и в схеме он один.

Почему сделано именно так.

Запросы — это временные таблицы `ВТ_Заказано`, `ВТ_Поступило`, `ВТ_Выдано` и `ВТ_НаСкладах` эталона занятия 68, перенесённые в наборы данных. Правила те же, потому что вопрос тот же: обе стороны каждого сопоставления отбираются по одному определению «рабочей заявки».

Группировка по материалу в каждом наборе — та же предварительная группировка, что в пакете занятия 68. Там она защищала от размножения в левом соединении, здесь — в связи наборов: связь и есть левое соединение.

Набор `НаСкладах` считает остатки всех материалов, а не только заказанных объектом. В пакете занятия 68 условие на материалы ставилось в параметры таблицы остатков, чтобы не считать лишнего. Здесь лишние строки отбросит связь, а в учебной базе материалов немного. В рабочей базе с тысячами материалов это повод передать список материалов в набор параметром связи — возможность, которую курс не разбирал; для приёмки сегодня достаточно, что числа верны.

### Связи, вычисляемое поле, ресурсы

Связи наборов данных — три строки, источник везде `Заказано`:

| Источник | Приёмник | Выражение источник | Выражение приёмник |
| --- | --- | --- | --- |
| `Заказано` | `Поступило` | `Материал` | `Материал` |
| `Заказано` | `Выдано` | `Материал` | `Материал` |
| `Заказано` | `НаСкладах` | `Материал` | `Материал` |

Вычисляемое поле: путь к данным `ОсталосьПолучить`, выражение `Заказано - ЕстьNULL(Поступило, 0)`, заголовок «Осталось получить».

Ресурсы:

| Поле | Выражение |
| --- | --- |
| `Заказано` | `Сумма(Заказано)` |
| `Поступило` | `Сумма(ЕстьNULL(Поступило, 0))` |
| `ОсталосьПолучить` | `Сумма(ОсталосьПолучить)` |
| `Выдано` | `Сумма(ЕстьNULL(Выдано, 0))` |
| `НаСкладах` | `Сумма(ЕстьNULL(НаСкладах, 0))` |

Почему сделано именно так.

Источник всех связей — `Заказано`: отчёт отвечает на вопрос о заказанном, и материал без поступлений и выдачи должен остаться. Это направление связи занятия 73.

`ЕстьNULL` стоит везде, где поле приходит из приёмника: в вычисляемом поле — чтобы «осталось получить» не стало пустым, в выражениях ресурсов — чтобы в строке материала был ноль, а не пустая клетка. Это `ЕСТЬNULL` занятия 68, перенесённый из запроса в выражения схемы.

Общий итог по колонкам складывает мешки, штуки и кубометры. Он оставлен, потому что не вводит в заблуждение строку материала; если снабженцу он мешает, общие итоги отключают в настройках варианта.

### Параметры

| Параметр | Заголовок | Тип | Ограничение доступности |
| --- | --- | --- | --- |
| `ОбъектСтроительства` | «Объект строительства» | `СправочникСсылка.ОбъектыСтроительства` | нет, быстрый доступ |
| `Период` | — | дата | да |

`Период` система компоновки добавила сама для таблицы остатков. Графа «на складах» по постановке — текущий остаток, поэтому параметр закрыт: пользователь не должен получить «на складах» на другую дату, а справка, с которой отчёт сверяют, всегда считает текущий остаток.

Объект — параметр, а не отбор: он нужен трём запросам, и в наборах `Поступило` и `Выдано` нет поля, по которому можно было бы отобрать «заявки объекта». Это граница параметра и отбора занятия 72.

### Настройки основного варианта

- Представление варианта — «Обеспечение».
- Структура: группировка `Материал`.
- Выбранные поля: `Заказано`, `Поступило`, `ОсталосьПолучить`, `Выдано`, `НаСкладах`.
- Сортировка: `Материал`.
- Параметр «Объект строительства» — в пользовательских настройках, быстрый доступ.
- Условное оформление у узла **Отчет**: цвет текста красный, условие `ОсталосьПолучить` больше `0`, оформляемых полей нет — выделяется вся строка материала. Правило у узла отчёта действует и в общем итоге: если хоть что-то не получено, итог тоже красный, и это правда.

### Вариант «Диаграмма обеспечения»

- Структура: диаграмма, точки — группировка `Материал`, серий нет.
- Выбранные поля диаграммы: `Заказано`, `Поступило`, `Выдано` — каждый ресурс становится своей серией.
- Тип диаграммы — гистограмма.
- Параметр «Объект строительства» с быстрым доступом — у варианта свои пользовательские настройки.

Материалы стоят точками, а не сериями: сравниваются графы одного материала — заказано, поступило, выдано, — у которых одна единица измерения. Это ответ на вопрос о сериях занятия 78.

### Модуль отчёта

```bsl
Процедура ПриКомпоновкеРезультата(ДокументРезультат, ДанныеРасшифровки, СтандартнаяОбработка)

	Настройки = КомпоновщикНастроек.ПолучитьНастройки();

	ЗначениеОбъекта = Настройки.ПараметрыДанных.НайтиЗначениеПараметра(
		Новый ПараметрКомпоновкиДанных("ОбъектСтроительства"));

	Если ЗначениеОбъекта = Неопределено
		Или Не ЗначениеОбъекта.Использование
		Или Не ЗначениеЗаполнено(ЗначениеОбъекта.Значение) Тогда

		СтандартнаяОбработка = Ложь;
		ДокументРезультат.Очистить();
		Сообщить("Выберите объект строительства");

	КонецЕсли;

КонецПроцедуры
```

Почему сделано именно так.

Обработчик не выполняет компоновку сам. Если объект выбран, `СтандартнаяОбработка` остаётся `Истина`, и отчёт строит платформа — со всеми своими возможностями, включая расшифровку. Код вмешивается только тогда, когда отчёт строить нельзя. Это тот же приём «отказать, но не перехватить», что проверка периода на занятии 79.

Значения по умолчанию, как у периода ведомости, здесь нет: у снабженца нет «объекта по умолчанию», и подставленный схемой объект показал бы чужие числа. Отказать в формировании и сказать пользователю, что выбрать, схема не умеет. Поэтому правило в модуле отчёта: обработчик выполняется на сервере при любом формировании отчёта.
