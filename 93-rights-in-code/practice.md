# Практика. Согласует только руководитель снабжения

## Перед началом

Запустите конфигуратор учебной конфигурации **«Управление строительной компанией с логистикой»** под пользователем «Администратор».

Понадобятся роли и пользователи занятий 91–92, форма заявки с процедурой `УстановитьДоступностьЭлементов` (занятие 81) и командой **Согласовать** с функцией `СогласоватьНаСервере` (занятие 35), а также модуль объекта заявки с обработчиком `ПередЗаписью` (занятие 35).

После каждой правки: `Ctrl+S`, затем **Конфигурация → Обновить конфигурацию базы данных** (`F7`). Проверку под пользователем выполняйте, запуская **1С:Предприятие** из окна запуска 1С.

## Шаг 1. Убедитесь, что среди прав платформы такого правила нет

1. Войдите в приложение под «Сидорова Анна». Создайте заявку на «ЖК Северный», «Песок речной» — `1`, нажмите **Согласовать** и запишите. Снабженец согласовал заявку сам.
2. Откройте в конфигураторе роль `Снабженец` и найдите среди прав документа `ЗаявкаНаМатериалы` что-нибудь похожее на «согласование». Такого права нет: согласование для платформы — это **Изменение** документа.
3. Запишите в конспект, почему нельзя просто снять у снабженца **Изменение** заявки.

**Проверка:** в конспекте записано, что согласование — смена реквизита, а не отдельное право, и почему **Изменение** у снабженца отнять нельзя.

## Шаг 2. Создайте роль-разрешение

1. В ветке **Общие → Роли** создайте роль `СогласованиеЗаявок`, синоним «Согласование заявок».
2. Не отмечайте в ней ни одного права. Флаг **Устанавливать права для новых объектов** не включайте.

Роль пустая намеренно. Права на данные руководитель снабжения получит ролями «Базовые права» и «Снабженец», а эта роль — только разрешение, о котором будет спрашивать код.

**Проверка:** в конфигурации есть пустая роль `СогласованиеЗаявок`.

## Шаг 3. Напишите функцию проверки

1. В ветке **Общие → Общие модули** создайте модуль `ПраваПользователей`. Флаг **Сервер** — включён, **Вызов сервера** — снят, **Клиент (управляемое приложение)** — снят.
2. Добавьте функцию:

```bsl
// Истина, если текущему пользователю разрешено согласовывать заявки на материалы.
Функция МожноСогласовыватьЗаявки() Экспорт

	Возврат РольДоступна("СогласованиеЗаявок") Или РольДоступна("ПолныеПрава");

КонецФункции
```

Функцию будут вызывать модуль формы с сервера и модуль объекта — обоим не нужен **Вызов сервера**. Вторая проверка, `ПолныеПрава`, оставляет согласование администратору: роли `СогласованиеЗаявок` у него нет.

**Проверка:** в общем модуле `ПраваПользователей` есть экспортная функция `МожноСогласовыватьЗаявки`, синтаксический контроль ошибок не находит.

## Шаг 4. Скройте кнопку и откажите в команде

1. Откройте модуль формы документа `ЗаявкаНаМатериалы`. В процедуре `УстановитьДоступностьЭлементов` замените строку видимости кнопки **Согласовать**:

```bsl
	Элементы.ФормаСогласовать.Видимость = ЗаявкаНовая И ПраваПользователей.МожноСогласовыватьЗаявки();
```

2. В функции `СогласоватьНаСервере` добавьте проверку первой:

```bsl
	Если Не ПраваПользователей.МожноСогласовыватьЗаявки() Тогда
		Возврат "Согласовывать заявки может только руководитель снабжения.";
	КонецЕсли;
```

Обе правки — в серверных процедурах формы, поэтому серверный общий модуль доступен им напрямую, без нового серверного вызова.

**Проверка:** видимость кнопки зависит от функции проверки, а серверная часть команды отказывает без разрешения.

## Шаг 5. Запретите согласование в модуле объекта

Откройте модуль объекта документа `ЗаявкаНаМатериалы` и замените обработчик `ПередЗаписью`, добавив функцию:

```bsl
Процедура ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)

	Если НЕ ЗначениеЗаполнено(Состояние) Тогда
		Состояние = Перечисления.СостоянияЗаявок.Новая;
	КонецЕсли;

	Если ЗаявкаСогласовывается() И Не ПраваПользователей.МожноСогласовыватьЗаявки() Тогда
		Сообщение = Новый СообщениеПользователю;
		Сообщение.Текст = "Согласовывать заявки может только руководитель снабжения";
		Сообщение.Поле = "Состояние";
		Сообщение.УстановитьДанные(ЭтотОбъект);
		Сообщение.Сообщить();
		Отказ = Истина;
	КонецЕсли;

КонецПроцедуры

// Истина, если записываемая заявка переходит в состояние «Согласована».
Функция ЗаявкаСогласовывается()

	Если Состояние <> Перечисления.СостоянияЗаявок.Согласована Тогда
		Возврат Ложь;
	КонецЕсли;

	Если ЭтоНовый() Тогда
		Возврат Истина;
	КонецЕсли;

	Возврат Ссылка.Состояние <> Перечисления.СостоянияЗаявок.Согласована;

КонецФункции
```

`Состояние` — значение, которое сейчас записывается. `Ссылка.Состояние` — значение, записанное в базе до этой записи. Если в базе уже «Согласована», запись согласованной заявки — не согласование: например, дописали комментарий. Новую заявку проверяем отдельно, до обращения к `Ссылка`: в базе её ещё нет.

**Проверка:** в модуле объекта заявки `ПередЗаписью` отказывает в записи согласования без разрешения, синтаксический контроль ошибок не находит.

## Шаг 6. Создайте руководителя снабжения

1. Обновите конфигурацию базы данных (`F7`).
2. В **Администрирование → Пользователи** создайте пользователя `Кузнецов`, полное имя «Кузнецов Олег», пароль пустой, роли «Базовые права», «Снабженец» и «Согласование заявок».

**Проверка:** у Кузнецова три роли, у Сидоровой — по-прежнему две.

## Шаг 7. Проверьте обычный путь

1. Войдите под Сидоровой. Создайте заявку на «ЖК Северный», «Песок речной» — `2`, запишите. Кнопки **Согласовать** нет.
2. Войдите под Кузнецовым. Откройте эту заявку: кнопка **Согласовать** есть. Нажмите её и запишите заявку.
3. Войдите под Сидоровой. Откройте согласованную заявку, допишите комментарий и запишите. Запись прошла: это не согласование.
4. Войдите под администратором и убедитесь, что кнопка **Согласовать** у новой заявки видна и ему.

**Проверка:** Сидорова не видит **Согласовать**, Кузнецов и администратор согласуют; правка комментария согласованной заявки Сидоровой не запрещена.

## Шаг 8. Проверьте гарантию в обход формы

Проверим, что модуль объекта держит правило, даже если форма ошиблась.

1. В процедуре `УстановитьДоступностьЭлементов` временно верните строку `Элементы.ФормаСогласовать.Видимость = ЗаявкаНовая;`. В функции `СогласоватьНаСервере` временно закомментируйте проверку из шага 4.
2. Обновите конфигурацию базы данных и войдите под Сидоровой. Создайте заявку, нажмите **Согласовать** — состояние в форме сменилось.
3. Нажмите **Записать**. Запись отклонена с сообщением у поля «Состояние»: «Согласовывать заявки может только руководитель снабжения».
4. Закройте заявку без записи. Верните обе правки шага 4 и обновите конфигурацию базы данных.

Форма ошиблась дважды, а правило устояло: модуль объекта проверяет права при любой записи.

**Проверка:** при сломанной форме запись согласования от Сидоровой отклонена модулем объекта; правки формы возвращены.

## Проверка результата

Занятие пройдено, если выполняются шесть условий:

1. В конфигурации есть роль `СогласованиеЗаявок` без прав на объекты.
2. Функция `МожноСогласовыватьЗаявки` общего модуля `ПраваПользователей` — единственное место, где проверяются роли согласования.
3. Кнопка **Согласовать** видна только тем, кому разрешено согласование; `СогласоватьНаСервере` отказывает остальным.
4. `ПередЗаписью` заявки отклоняет переход в «Согласована» без разрешения и не мешает записи уже согласованной заявки.
5. Кузнецов и администратор согласуют заявки, Сидорова — нет.
6. При сломанной форме модуль объекта всё равно не дал Сидоровой согласовать заявку.
