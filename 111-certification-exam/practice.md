# Практика. Диагностика и план подготовки

## Перед началом

Понадобится только конспект `1c-learning-notes`. Создайте в нём каталог `exam` — в нём будут жить результаты всех тренировочных билетов этапа и карточки повторения. Конфигурацию сегодня не меняем.

Приготовьте таймер. Диагностический тест выполняется на время и без подглядывания в курс: его задача — показать честную картину, а не набрать баллы.

## Шаг 2. Пройдите диагностический тест

Засеките 15 минут. Ответьте на десять вопросов, записывая в конспект номер вопроса и букву ответа. Перед каждым ответом назовите про себя контекст вопроса, как учит теория.

**1.** Разработчик добавил реквизит справочника и сохранил конфигурацию, но не обновил конфигурацию базы данных. С какой конфигурацией работают пользователи в режиме 1С:Предприятие?

- А) С основной конфигурацией, где новый реквизит уже есть
- Б) С конфигурацией базы данных, где нового реквизита ещё нет
- В) С конфигурацией из последнего файла `.cf`
- Г) С выгрузкой конфигурации в файлы

**2.** Кто может добавить новое значение перечисления?

- А) Пользователь в режиме 1С:Предприятие, если у него есть право **Добавление**
- Б) Код в модуле объекта при записи документа
- В) Разработчик в конфигураторе
- Г) Администратор в списке пользователей

**3.** Клиентская процедура формы в тонком клиенте должна найти элемент справочника по наименованию. Как это сделать правильно?

- А) Вызвать `Справочники.Товары.НайтиПоНаименованию` прямо в клиентской процедуре
- Б) Поиск по наименованию в управляемом приложении невозможен
- В) Выполнить запрос в клиентской процедуре
- Г) Вызвать серверную процедуру формы, которая выполнит поиск и вернёт ссылку

**4.** В какой процедуре нужно проверять правило «передачу на завершённый объект проводить нельзя», чтобы оно действовало при любом способе проведения?

- А) В `ОбработкаПроведения` модуля объекта документа
- Б) В обработчике команды **Провести** формы документа
- В) В `ПриОткрытии` формы документа
- Г) В параметрах выбора реквизита

**5.** Что хранит регистр накопления вида «Остатки»?

- А) Текущий остаток по каждому сочетанию измерений, который перезаписывается при проведении
- Б) Копии документов-регистраторов
- В) Движения — приходы и расходы; остаток платформа вычисляет из них
- Г) Только последний приход по каждому материалу

**6.** На складе материала ровно ноль. Что вернёт запрос к виртуальной таблице остатков по этому материалу и складу?

- А) Строку с остатком `0`
- Б) Строку с остатком `NULL`
- В) Ни одной строки
- Г) Ошибку выполнения запроса

**7.** Чем `ОБЪЕДИНИТЬ` отличается от `ОБЪЕДИНИТЬ ВСЕ`?

- А) `ОБЪЕДИНИТЬ` убирает повторяющиеся строки результата, `ОБЪЕДИНИТЬ ВСЕ` оставляет все
- Б) `ОБЪЕДИНИТЬ` соединяет таблицы по условию, `ОБЪЕДИНИТЬ ВСЕ` — без условия
- В) `ОБЪЕДИНИТЬ ВСЕ` работает только с временными таблицами
- Г) Ничем, это синонимы

**8.** Процедура показывает пользователю вопрос методом `ПоказатьВопрос`, а следующей строкой стоит `Сообщить("Готово")`. Когда появится сообщение?

- А) После того как пользователь ответит
- Б) Сразу, не дожидаясь ответа
- В) Никогда: после `ПоказатьВопрос` код не выполняется
- Г) Только если пользователь ответит «Да»

**9.** У пользователя две роли. Первая не даёт права на документ, вторая даёт **Чтение**. Может ли пользователь читать документ?

- А) Нет: отсутствие права в одной роли запрещает его во всех
- Б) Зависит от порядка ролей в списке пользователя
- В) Да, но только в привилегированном режиме
- Г) Да: права ролей складываются

**10.** Чем файл `.dt` отличается от файла `.cf`?

- А) Ничем, это разные расширения одного формата
- Б) `.dt` содержит конфигурацию и данные базы, `.cf` — только конфигурацию
- В) `.dt` содержит только данные, `.cf` — данные и конфигурацию
- Г) `.dt` — текстовая выгрузка для Git, `.cf` — бинарная

**Проверка:** на все десять вопросов записаны ответы, время записано.

## Шаг 3. Проверьте ответы

Сверьте ответы с ключом. Для каждой ошибки прочитайте колонку «Почему» и откройте указанное занятие.

| № | Ответ | Почему | Занятие |
| --- | --- | --- | --- |
| 1 | Б | пользователи работают с конфигурацией базы данных; изменения попадают в неё только обновлением (`F7`) | 3 |
| 2 | В | значения перечисления задаёт разработчик; если список должен пополнять пользователь, нужен справочник | 7 |
| 3 | Г | обращение к базе данных недоступно в клиентском коде тонкого клиента; поиск выполняют на сервере | 19, 22 |
| 4 | А | форма — подсказка, а не защита; правило учёта живёт в модуле объекта | 48, 81 |
| 5 | В | регистр накопления хранит изменения; остаток вычисляется из движений | 42, 51 |
| 6 | В | таблица остатков не возвращает строк с нулевым остатком | 65 |
| 7 | А | `ОБЪЕДИНИТЬ` убирает повторы, `ОБЪЕДИНИТЬ ВСЕ` их оставляет | 60 |

## Шаг 4. Заведите карточки повторения

Создайте файл `exam/cards.md`. На каждую ошибку диагностики заведите карточку:

| Поле | Что в нём |
| --- | --- |
| Вопрос | своими словами, не копией из билета |
| Ответ | правильный ответ одной фразой |
| Ловушка | почему ваш неверный ответ казался верным; какой контекст вы не назвали |
| Занятие | номер занятия курса |
| Повторить | даты трёх повторений: через день, через три дня, через неделю |

Если ошибок не было, заведите карточки на два вопроса, в которых вы сомневались дольше всего.

**Проверка:** в `exam/cards.md` есть карточка на каждую ошибку с колонкой «Ловушка».

## Шаг 6. Составьте план подготовки

Создайте файл `exam/plan.md`. Для каждого тренировочного билета — занятия 112, 113, 114, 115 — запишите:

1. Темы из таблицы самооценки, которые он покрывает (по таблице «Как связан курс с экзаменом» в теории).
2. Темы с оценкой `0` и `1` и переоценённые темы среди них.
3. Занятия курса, теорию которых нужно перечитать **до** билета. Перечитывайте раздел «Что важно запомнить» каждого занятия, а целиком — только занятия слабых тем.
4. Дату, когда вы пройдёте билет.

Последней строкой запланируйте пробный экзамен занятия 116 и дату записи на настоящий экзамен — не раньше, чем пробный экзамен будет пройден с запасом.

Закоммитьте каталог `exam` в конспект.

**Проверка:** в `exam/plan.md` для каждого билета названы темы, занятия для повторения и дата; запланированы пробный и настоящий экзамен.

## Проверка результата

Занятие пройдено, если выполняются пять условий:

1. Таблица самооценки по шестнадцати темам заполнена до диагностики.
2. Диагностический тест пройден на время, результат и время записаны.
3. На каждую ошибку есть карточка с ловушкой и номером занятия.
4. Самооценка сверена с диагностикой, частая ловушка названа.
5. План подготовки расписан по билетам 112–115, пробному экзамену и дате записи на экзамен.

3. Какие шесть ловушек контекста перечислены в теории? Приведите пример для двух из них.

5. Чем интервальное повторение карточек лучше перечитывания конспекта накануне экзамена?
6. Вопрос 4 диагностики предлагал проверить правило в форме, в модуле объекта или параметрами выбора. Почему экзамен и работодатель ждут ответ «в модуле объекта», и в каком случае проверка в форме всё же нужна как дополнение?

Сверьте ответы с [теорией](theory.md). Если на каждый вопрос получается ответить одним-двумя предложениями, переходите к занятию 112.
