# Теория. Конфигуратор и первые объекты

## Работа с объектом в дереве

В Конфигураторе большинство задач начинается с дерева конфигурации: выделить группу объектов, создать объект через контекстное меню, открыть его свойства двойным щелчком и сохранить изменения. У объекта есть окно свойств и, при необходимости, вложенные объекты: реквизиты, табличные части, формы, команды и модули.

Не путайте **конфигурацию** с **конфигурацией базы данных**. Первая — ваша редактируемая версия. Вторая — версия, с которой работает пользователь. После структурных изменений нужно выполнить **Конфигурация → Обновить конфигурацию базы данных** (`F7`) и затем проверить результат в «1С:Предприятии».

## Имя и синоним

У объекта есть два важных названия:

- **Имя** — технический идентификатор для кода и структуры. Оно начинается с буквы, не содержит пробелов: `Контрагенты`, `ОбъектыСтроительства`.
- **Синоним** — понятное пользователю представление в формах и командах. В нём допустимы пробелы: «Объекты строительства».

Имя лучше выбирать осмысленно с самого начала: позднее его изменение может потребовать исправить код и ссылки на объект. Синоним можно менять свободнее, если требуется улучшить интерфейс.

## Справочник

**Справочник** хранит сравнительно постоянный список однотипных сущностей: контрагентов, сотрудников, материалов, объектов строительства. Каждый элемент имеет ссылку, код, наименование и дополнительные реквизиты.

В учебном ERP-проекте справочник «Клиенты» будет содержать заказчиков, «Товары» — номенклатуру для продажи, закупки и поставки на строительные объекты, а «Сотрудники» — персонал компании.

## Реквизиты

**Реквизит** — дополнительное поле объекта. Например, у клиента могут быть телефон, email и адрес; у товара — артикул, цена и описание. У реквизита задают имя, синоним и тип данных.

В 1С есть стандартные типы `Строка`, `Число`, `Дата`, `Булево` и ссылочные типы на другие объекты. Начинайте с минимального состава полей: лишняя структура усложняет формы и дальнейшее сопровождение.

## Подсистемы и интерфейс

**Подсистема** группирует команды прикладного решения в раздел интерфейса. Например, подсистема «Строительство» позднее соберёт объекты, связанные с работами на площадках. В практической части мы создадим «Справочники компании», чтобы пользовательские команды появились в интерфейсе.

## Цикл разработки

1. Измените объект в Конфигураторе.
2. Сохраните конфигурацию (`Ctrl+S`).
3. Обновите конфигурацию базы данных (`F7`).
4. Запустите «1С:Предприятие» и проверьте пользовательский результат.

Если обновление показывает список изменений, прочитайте его: это полезная привычка перед изменением структуры рабочей базы.
