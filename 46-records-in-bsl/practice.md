# Практика. Формируем движения документа на BSL

## Перед началом

Запустите конфигуратор учебной конфигурации **«Управление строительной компанией с логистикой»**.

Понадобится документ `ПоступлениеМатериалов` с реквизитами шапки `Поставщик`, `Склад`, `Ответственный` и табличной частью `Материалы`, у которого свойство **Проведение** стоит в значении **Разрешить**. Свойство включило занятие 45; если оно выключено, вернитесь к занятию 45.

Понадобится регистр накопления `ОстаткиМатериалов` вида «Остатки» с измерениями `Материал` и `Склад` и ресурсом `Количество`, у которого `ПоступлениеМатериалов` отмечен регистратором, а флаг **Записывать движения при проведении** включён. Это результат занятий 43 и 44.

Работаем в одном месте: **Документы → ПоступлениеМатериалов → Модуль объекта**. Новых объектов метаданных сегодня не создаём, формы не трогаем, свойства документа не меняем.

После каждой правки: `Ctrl+S`, затем `F5` — платформа предложит обновить конфигурацию базы данных, согласитесь. Структура данных от правки модуля не меняется, поэтому обновление пройдёт без предупреждений о потере данных.

Проверок перед проведением сегодня не пишем: пустой склад и нулевое количество код пропустит, и это нормально — ими занимается занятие 48. Отмену проведения тоже не разбираем, это занятие 47.

Записи регистра смотрим через **Все функции → Регистры накопления → Остатки материалов**. Если пункт **Все функции** недоступен, включите его: **Главное меню → Сервис → Параметры → Отображать команду «Все функции»**.

## Шаг 1. Откройте модуль объекта документа

1. В дереве конфигурации раскройте **Документы** и выделите `ПоступлениеМатериалов`.
2. Откройте окно редактирования объекта и перейдите на вкладку **Прочее**.
3. Нажмите **Модуль объекта**. Откроется окно редактора кода — возможно, пустое, возможно, с процедурами из занятий 33 и 36.
4. Убедитесь, что в заголовке окна написано именно «Модуль объекта», а не «Модуль формы». Это разные модули, и перепутать их легко.
5. Запишите в конспект, почему код проведения пойдёт именно сюда: провести документ можно из формы, из журнала и из кода, а модуль объекта исполняется во всех трёх случаях.

**Проверка:** открыт модуль объекта документа `ПоступлениеМатериалов`, а не модуль его формы.

## Шаг 2. Создайте пустой обработчик проведения

1. Добавьте в конец модуля процедуру:

```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
	
	// Здесь будут формироваться движения по регистру ОстаткиМатериалов
	
КонецПроцедуры
```

2. Имя процедуры и оба параметра нужны платформе. `Отказ` мы используем в занятии 48, `РежимПроведения` — по смыслу занятия 45, но объявить их надо сейчас: платформа вызывает обработчик именно с такой сигнатурой.
3. Нажмите `Ctrl+S`, затем выполните **Конфигурация → Проверка → Синтаксический контроль**. Ошибок быть не должно.
4. Нажмите `F5`, откройте **Логистика → Поступления материалов** и проведите документ с цементом из занятия 45.
5. Откройте форму списка регистра `Остатки материалов`. Записей по-прежнему нет: процедура есть, но ничего не делает.

**Проверка:** обработчик добавлен, синтаксический контроль проходит, записей в регистре нет.

## Шаг 3. Скажите платформе записать набор движений

1. Замените комментарий внутри процедуры одной строкой:

```bsl
	// Указание платформе: после выхода из процедуры запиши
	// набор движений этого документа в регистр ОстаткиМатериалов
	Движения.ОстаткиМатериалов.Записывать = Истина;
```

2. Разберите, что здесь написано. `Движения` — коллекция наборов записей документа. `ОстаткиМатериалов` — набор по одному конкретному регистру; он доступен потому, что документ назначен регистратором в занятии 44. `Записывать = Истина` — не запись в базу, а указание платформе записать набор позже, после выхода из процедуры.
3. Обратите внимание на подсказку синтакс-помощника: наберите `Движения.` и посмотрите, какие регистры он предлагает. В списке только `ОстаткиМатериалов` — других связей у документа нет.
4. `Ctrl+S`, `F5`.
5. Проведите документ ещё раз и откройте форму списка регистра. Записей нет.

Это ожидаемо и очень поучительно: платформа записала набор, но набор был пустым. Указание записать есть, записывать нечего.

**Проверка:** строка `Движения.ОстаткиМатериалов.Записывать = Истина;` добавлена, регистр всё ещё пуст.

## Шаг 4. Обойдите строки табличной части

1. Допишите после этой строки цикл:

```bsl
	
	// Одна строка табличной части — одно движение прихода
	Для Каждого СтрокаМатериалов Из Материалы Цикл
		
	КонецЦикла;
```

2. Разберите две вещи в этой строке. Первая: `Материалы` — табличная часть документа, и в модуле объекта она доступна прямо по имени, без префикса `Объект.`, который мы писали в модуле формы на занятии 32. Вторая: `СтрокаМатериалов` — переменная цикла, в ней на каждом витке лежит одна строка со своими `Материал`, `Количество`, `Цена` и `Сумма`.
3. Сам цикл `Для Каждого` знаком с занятия 14, а обход строк документа — с занятия 32. Нового в языке здесь нет.
4. `Ctrl+S` и синтаксический контроль.

**Проверка:** цикл по табличной части `Материалы` добавлен, синтаксический контроль ошибок не находит.

## Шаг 5. Создайте движение на каждую строку

1. Внутри цикла добавьте создание записи и заполните измерения и ресурс:

```bsl
		Движение = Движения.ОстаткиМатериалов.Добавить();
		
		Движение.Материал = СтрокаМатериалов.Материал;
		Движение.Склад = Склад;
		Движение.Количество = СтрокаМатериалов.Количество;
```

2. `Добавить()` создаёт в наборе новую пустую запись и возвращает её. Дальше её заполняют по полям через точку — так же, как структуру на занятии 17.
3. Проследите, откуда берётся каждое значение. `Материал` и `Количество` — из строки, потому что они у каждого материала свои. `Склад` — из шапки документа, потому что он один на весь документ. Это распределение полей мы проектировали на занятии 27, и сейчас код просто читает его вслух.
4. Запишите в конспект, чего в этом фрагменте нет: мы не заполняем `Регистратор` и `НомерСтроки`. Их подставит платформа — набор с самого начала принадлежит этому документу.
5. `Ctrl+S` и синтаксический контроль.

**Проверка:** в цикле есть вызов `Добавить()` и заполнение `Материал`, `Склад`, `Количество`.

## Шаг 6. Заполните период и вид движения

Без этих двух полей запись бессмысленна: непонятно, когда изменился остаток и в какую сторону.

1. Допишите в теле цикла, сразу после `Добавить()`:

```bsl
		// Вид движения — смысл операции: материал пришёл на склад
		Движение.ВидДвижения = ВидДвиженияНакопления.Приход;
		
		// Период берём из даты документа, а не из текущей даты:
		// остаток изменился в день события
		Движение.Период = Дата;
```

2. `ВидДвиженияНакопления` — системное перечисление платформы с двумя значениями, `Приход` и `Расход`. Создавать его не нужно, оно доступно всегда. Расход появится в занятии 50.
3. Отдельно задумайтесь над периодом. Поставьте мысленно на место `Дата` вызов `ТекущаяДата()` и ответьте, что сломается: движение переедет на день проведения, и остаток на день поставки станет неверным. Проверять остатки на дату мы будем в занятии 51 — именно там эта ошибка была бы видна.
4. `Ctrl+S` и синтаксический контроль.

**Проверка:** у записи заполняются `ВидДвижения` и `Период`, причём период берётся из реквизита `Дата`.

## Шаг 7. Сверьте процедуру целиком

1. Приведите процедуру к такому виду:

```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
	
	// Набор движений будет записан после выхода из процедуры
	Движения.ОстаткиМатериалов.Записывать = Истина;
	
	// Одна строка табличной части — одно движение прихода
	Для Каждого СтрокаМатериалов Из Материалы Цикл
		
		Движение = Движения.ОстаткиМатериалов.Добавить();
		
		Движение.ВидДвижения = ВидДвиженияНакопления.Приход;
		Движение.Период = Дата;
		Движение.Материал = СтрокаМатериалов.Материал;
		Движение.Склад = Склад;
		Движение.Количество = СтрокаМатериалов.Количество;
		
	КонецЦикла;
	
КонецПроцедуры
```

2. Сосчитайте строки кода без комментариев: их меньше десяти. При этом каждая опирается на решение прошлых занятий — структура регистра из занятия 43, регистратор из 44, включённое проведение из 45, распределение полей по шапке и строкам из 27.
3. Выполните **Конфигурация → Проверка конфигурации** с проверкой логической целостности.
4. `Ctrl+S`, затем `F5`.

**Проверка:** процедура совпадает с приведённой, проверка конфигурации проходит без ошибок.

## Шаг 8. Проведите документ и найдите записи

1. Откройте **Логистика → Поступления материалов**.
2. Откройте или создайте поступление: поставщик «ООО СтройСнаб», склад «Центральный склад», в табличной части одна строка — «Цемент М500», количество `100`.
3. Нажмите **Провести и закрыть**.
4. Откройте **Все функции → Регистры накопления → Остатки материалов**.
5. В списке появилась запись. Прочитайте её по колонкам: **Период** — дата документа, **Регистратор** — ваше поступление, **Номер строки** — `1`, **Вид движения** — «Приход», **Материал** — «Цемент М500», **Склад** — «Центральный склад», **Количество** — `100`.
6. Щёлкните дважды по значению в колонке **Регистратор**: откроется сам документ. Переход из занятия 44, который тогда вёл в пустой список, теперь работает в обе стороны.
7. Если в журнале есть другие поступления, проведённые ещё на занятии 45, их записей в регистре нет и не появится само: тогда кода не было, собирать набор было некому. Чтобы движения появились, такой документ нужно провести заново — откройте его и нажмите **Провести**.
8. Запишите в конспект вывод, который из этого следует: признак `Проведён` и наличие движений — разные вещи, и признак не гарантирует, что в учёте что-то есть.

**Проверка:** в регистре `ОстаткиМатериалов` есть запись прихода `100` по цементу на «Центральный склад» с регистратором-поступлением.

## Шаг 9. Проверьте, что движений столько же, сколько строк

1. Откройте проведённое поступление и добавьте в табличную часть вторую строку: материал «Кирпич облицовочный», количество `500`.
2. Добавьте третью строку: материал «Песок речной», количество `20`.
3. Нажмите **Провести и закрыть**.
4. Обновите форму списка регистра клавишей `F5`. Записей стало три, и в колонке **Номер строки** значения `1`, `2`, `3`.
5. Сравните каждую запись со своей строкой документа: материал и количество должны совпадать, склад у всех трёх одинаковый — он из шапки.
6. Выпишите в конспект правило, которое вы только что проверили: **одна строка табличной части даёт одно движение**. Если записей больше или меньше, чем строк, ошибка в коде проведения, а не в данных.
7. Запишите в конспект и то, что мы сегодня намеренно не проверяли: документ с пустым складом или нулевым количеством код проведёт и создаст бессмысленные записи. Это задача занятия 48.

**Проверка:** в регистре три записи с номерами строк `1`, `2`, `3`, и каждая соответствует своей строке документа.

## Проверка результата

Занятие пройдено, если выполняются шесть условий:

1. В модуле объекта документа `ПоступлениеМатериалов` есть процедура `ОбработкаПроведения(Отказ, РежимПроведения)`.
2. Первой содержательной строкой процедуры стоит `Движения.ОстаткиМатериалов.Записывать = Истина;`, и вы можете объяснить, что эта строка не пишет в базу.
3. В цикле по табличной части `Материалы` на каждую строку вызывается `Добавить()` и заполняются `ВидДвижения`, `Период`, `Материал`, `Склад`, `Количество`.
4. Период движения берётся из реквизита `Дата` документа, а `Регистратор` и `НомерСтроки` в коде не заполняются вовсе.
5. После проведения документа с тремя строками в регистре `ОстаткиМатериалов` три записи прихода, совпадающие со строками документа.
6. Из записи регистра открывается документ-регистратор, а из документа — список его движений.
