# Теория. Интерфейс и права на одной странице

## Какую задачу мы решаем

Этапы 7–8 — о том, что видит пользователь и что ему разрешено. В этих темах особенно легко перепутать два уровня: интерфейс, который **подсказывает**, и механизмы, которые **гарантируют**. Скрытая кнопка, параметр выбора, недоступное поле — подсказки. Права роли, ограничение записей, проверка в модуле объекта — гарантии. Экзамен проверяет, различаете ли вы их, почти в каждом вопросе этих тем.

Страница собирает утверждения этапов 7–8 с ловушками. Эксперимент практики показывает разницу между подсказкой и гарантией на передаче материалов.

## Формы

| Утверждение | Ловушка | Занятие |
| --- | --- | --- |
| `Видимость = Ложь` скрывает элемент; `Доступность = Ложь` показывает, но не даёт с ним работать; `ТолькоПросмотр` даёт видеть и выделять, но не менять | путать скрытие с запретом | 81 |
| Форма — подсказка, а не защита: правило, которое должно выполняться, живёт в модуле объекта или в правах | считать скрытую кнопку запретом | 81, 93 |
| Параметры выбора, заданные у реквизита объекта, действуют во всех его формах; у элемента формы — только в этой форме | задавать их в каждой форме заново | 82 |
| Параметры выбора ограничивают то, что поле **предлагает**; запись из кода с любым значением они не остановят | считать параметры выбора проверкой | 82 |
| Связи параметров выбора сужают выбор по значению другого поля той же формы | писать для этого код в форме | 82 |
| `ПоказатьВопрос` не ждёт ответа; продолжение действия — в экспортной процедуре, указанной в `ОписаниеОповещения` | писать продолжение следующей строкой | 83 |
| Динамический список читает из базы порциями то, что видно на экране | загружать все документы в таблицу формы | 84 |
| Условное оформление списка проверяет условие для каждой строки | красить строки кодом в цикле | 85 |

## Права и администрирование

| Утверждение | Ловушка | Занятие |
| --- | --- | --- |
| Права ролей складываются; запретить ролью то, что разрешила другая роль, нельзя | ждать «запрещающую» роль | 92, 95 |
| Основное право действует при любом обращении, в том числе из кода; интерактивное — только для действий пользователя в интерфейсе | думать, что без интерактивного права код не удалит объект | 92 |
| `ПравоДоступа` проверяет право на объект, `РольДоступна` — наличие конкретной роли; видимость по праву не ломается при новой роли | проверять имя роли | 93 |
| Привилегированный режим отключает проверку прав в серверном коде | включать его, чтобы «починить» нехватку прав у пользователя | 93 |
| Параметры сеанса устанавливают в модуле сеанса, в `УстановкаПараметровСеанса`; новое значение пользователь получит со следующего сеанса | ждать изменения без перезахода | 94 |
| Запрос без `РАЗРЕШЕННЫЕ` к записям, часть которых пользователю запрещена, завершается ошибкой прав; с `РАЗРЕШЕННЫЕ` возвращает только разрешённые | думать, что ограничение «само отфильтрует» любой запрос | 95, 98 |
| Журнал регистрации сам записывает вход, запись, проведение; своё событие пишут `ЗаписьЖурналаРегистрации`; журнал — не учёт | считать по журналу учётные показатели | 96 |
| `.cf` — конфигурация, `.dt` — конфигурация и данные; конфигурацию на поддержке дорабатывают расширением | править типовые объекты напрямую | 97 |
| `&Перед` и `&После` добавляют код к процедуре основной конфигурации, `&Вместо` заменяет её | использовать `&Вместо`, когда нужно дополнить | 97 |

## Что важно запомнить

1. Интерфейс подсказывает, права и модуль объекта гарантируют.
2. Видимость скрывает, доступность запрещает действие, только просмотр запрещает изменение.
3. Параметры выбора реквизита действуют во всех формах, но запись из кода не проверяют.
4. После `ПоказатьВопрос` код идёт дальше; ответ приходит в обработчик оповещения.
5. Печать собирают на сервере; множественный параметр команды — массив ссылок; страницы разделяют явно.
6. Права ролей складываются; основное право действует и для кода.
7. Видимость команды проверяют `ПравоДоступа`, а не `РольДоступна`.
8. Параметр сеанса меняется со следующего входа; запрос к ограниченным данным пишут с `РАЗРЕШЕННЫЕ`.
9. `&Вместо` заменяет процедуру и опасна там, где нужно дополнение.
