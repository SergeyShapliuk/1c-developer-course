# Практика. Ветвление расчётов

## Перед началом

Работаем там же, где и на двух предыдущих занятиях. В дереве конфигурации откройте **Обработки → УчебнаяКонсоль**, затем её форму и вкладку **Модуль**. Весь код пишем внутри процедуры `Выполнить`:

```bsl
&НаКлиенте
Процедура Выполнить(Команда)

КонецПроцедуры
```

После каждой правки: `Ctrl+S`, затем `F5`, затем в приложении раздел **Разработка → Учебная консоль** и кнопка **Выполнить**. Сообщения появятся в нижней части окна приложения. Дальше — коротко: «сохраните, запустите и нажмите **Выполнить**».

Каждый шаг начинаем с чистой процедуры: предыдущий код удаляем, если не сказано иначе.

## Шаг 1. Скидка тремя ветками

Правило такое: заказ до 10 000 — без скидки, до 50 000 — скидка 5%, свыше — 10%.

```bsl
&НаКлиенте
Процедура Выполнить(Команда)

	Перем СуммаЗаказа;
	Перем Процент;

	СуммаЗаказа = 32000;

	Если СуммаЗаказа < 10000 Тогда
		Процент = 0;
	ИначеЕсли СуммаЗаказа < 50000 Тогда
		Процент = 5;
	Иначе
		Процент = 10;
	КонецЕсли;

	Сообщить("Сумма заказа: " + Строка(СуммаЗаказа));
	Сообщить("Скидка: " + Строка(Процент) + "%");
	Сообщить("К оплате: " + Строка(СуммаЗаказа - СуммаЗаказа * Процент / 100));

КонецПроцедуры
```

Сохраните, запустите и нажмите **Выполнить**. Затем проверьте все три ветки: подставьте в `СуммаЗаказа` значения `5000`, `32000` и `120000` и каждый раз запускайте заново.

Обратите внимание: во второй ветке не написано «и при этом сумма не меньше 10 000». Это не нужно — если бы сумма была меньше, сработала бы первая ветка и до второй дело бы не дошло.

**Проверка:** для 5000 скидка 0% и к оплате 5000; для 32000 — 5% и 30400; для 120000 — 10% и 108000.

## Шаг 2. Диапазон через И

Количество в заявке должно быть от 1 до 1000 включительно. Замените текст процедуры:

```bsl
Количество = 1500;

Если Количество >= 1 И Количество <= 1000 Тогда
	Сообщить("Количество принято: " + Строка(Количество));
Иначе
	Сообщить("Недопустимое количество: " + Строка(Количество) + ". Допустимо от 1 до 1000.");
КонецЕсли;
```

Одно условие «от 1 до 1000» в коде всегда распадается на два сравнения, соединённых `И`. Записать это как `1 <= Количество <= 1000` нельзя — платформа такую цепочку не понимает.

Проверьте значения `0`, `500` и `1500`.

**Проверка:** 500 принимается, 0 и 1500 отклоняются с понятным сообщением.

## Шаг 3. Единица измерения через ?()

Если единица измерения не задана, подставим «шт.». Замените текст процедуры:

```bsl
Единица = "";
Единица = ?(ЗначениеЗаполнено(Единица), Единица, "шт.");
Сообщить("Единица измерения: " + Единица);
```

Вторая строка читается так: если единица заполнена, оставить как есть, иначе взять «шт.». Это одно выражение, поэтому результат сразу присваивается той же переменной.

Теперь замените первую строку на `Единица = "мешок";` и запустите снова.

**Проверка:** с пустой единицей выводится «шт.», с заполненной — «мешок».

## Шаг 4. Вид клиента

Сравним значение перечисления, созданного на занятии 7. Замените текст процедуры:

```bsl
ВидКлиента = Перечисления.ВидыКлиентов.Поставщик;

Если ВидКлиента = Перечисления.ВидыКлиентов.Заказчик Тогда
	Сообщить("Заказчик: оформляем заявку на материалы");
ИначеЕсли ВидКлиента = Перечисления.ВидыКлиентов.Поставщик Тогда
	Сообщить("Поставщик: запрашиваем прайс и сроки");
ИначеЕсли ВидКлиента = Перечисления.ВидыКлиентов.Подрядчик Тогда
	Сообщить("Подрядчик: согласуем объём работ");
Иначе
	Сообщить("Вид клиента не определён");
КонецЕсли;
```

Значения перечисления сравнивают обычным `=`, как числа и строки. Ветка `Иначе` нужна на случай, когда вид не заполнен: тогда в переменной лежит `Неопределено` или пустое значение перечисления, и ни одно из трёх сравнений не сработает.

Проверьте все четыре варианта, подставляя в первую строку `Заказчик`, `Поставщик`, `Подрядчик`, а затем `Неопределено`.

**Проверка:** каждому виду соответствует своё сообщение, а `Неопределено` попадает в ветку `Иначе`.

## Шаг 5. Проверка перед расчётом

Считать по незаполненной цене бессмысленно. Замените текст процедуры:

```bsl
Количество = 20;
Цена = 0;

Если НЕ ЗначениеЗаполнено(Цена) Тогда
	Сообщить("Цена не заполнена — расчёт не выполнен");
Иначе
	Сообщить("Сумма: " + Строка(Количество * Цена));
КонецЕсли;
```

Проверка стоит **до** расчёта, а не внутри него. Такой порядок называют ранней проверкой: сначала отсекаем случаи, когда работать нельзя, и дальше весь код уже знает, что данные в порядке.

Проверьте значения `Цена = 0` и `Цена = 12.5`.

**Проверка:** при нулевой цене выводится предупреждение, при заполненной — сумма 250.

## Шаг 6. Зачем нужны скобки

Теперь посмотрим, как приоритет операторов меняет результат. Замените текст процедуры:

```bsl
Количество = 20;
Цена = 0;

// Правильно: «ни количество, ни цена не равны нулю»
Если НЕ (Количество = 0 ИЛИ Цена = 0) Тогда
	Сообщить("Со скобками: данные заполнены");
Иначе
	Сообщить("Со скобками: чего-то не хватает");
КонецЕсли;

// Те же слова без скобок — платформа читает это иначе
Если НЕ Количество = 0 ИЛИ Цена = 0 Тогда
	Сообщить("Без скобок: данные заполнены");
Иначе
	Сообщить("Без скобок: чего-то не хватает");
КонецЕсли;
```

Сохраните, запустите и нажмите **Выполнить**. Результаты разойдутся. Причина в приоритете: `НЕ` выполняется раньше `ИЛИ`, поэтому второе условие платформа понимает как «(количество не равно нулю) ИЛИ (цена равна нулю)». При количестве 20 и цене 0 обе части истинны, и ветка срабатывает, хотя цена не заполнена.

**Проверка:** первое сообщение — «чего-то не хватает», второе — «данные заполнены». Вы можете объяснить, почему одни и те же слова дали разный ответ.

## Проверка результата

Занятие пройдено, если выполняются четыре условия:

1. Расчёт скидки правильно работает для всех трёх диапазонов суммы.
2. Вы умеете записать проверку диапазона через `И` и знаете, почему `1 <= Х <= 1000` не работает.
3. Вы различаете значения перечисления в ветках `Если` и предусмотрели ветку `Иначе`.
4. Вы на своём коде увидели, как скобки меняют результат логического выражения.
