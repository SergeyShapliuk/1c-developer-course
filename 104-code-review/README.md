# Занятие 104. Code review чужого кода

## Цель

Научиться читать чужое изменение до слияния и находить в нём ошибки, которые автор не заметил: неверный источник данных, логику не на своём месте, лишние серверные вызовы, проверки по имени роли, модальные окна. Научиться писать замечания так, чтобы автор понял, что не так, почему и что предлагается, и проверять исправление.

## Результат занятия

Орлов предложит ветку `feature/stock-hint`: перед открытием отчёта «Остатки на складах» передача показывает остатки своих материалов. Вы проведёте ревью по чек-листу и запишете в конспект замечания с серьёзностью и предложением. Орлов исправит код: остатки будут браться из регистра одним запросом общего модуля, вопрос пользователю станет немодальным. Вы проверите исправление в базе и сольёте ветку в `main`.

## Маршрут

1. Прочитайте [теорию](theory.md) — около 30 минут.
2. Выполните [практику](practice.md) — около 70 минут.
3. Ответьте на контрольные вопросы в конце практики, не подглядывая в теорию.

## Ключевые термины

Code review, ревьюер, автор изменения, чек-лист ревью, замечание, серьёзность замечания, блокирующее замечание, пожелание, запрос изменений, повторное ревью, стандарты разработки 1С, статический анализ.
