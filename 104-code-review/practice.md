# Практика. Ревью ветки feature/stock-hint

## Перед началом

Понадобятся репозиторий `construction-erp` в ветке `main` после занятия 103, клон Орлова и учебная база. В учебной базе есть форма документа `ПередачаМатериалов` с обработчиком команды `ОстаткиСклада` (занятие 79) и процедурой `УстановитьВидимостьЭлементов` (занятие 98), общий модуль `ОстаткиМатериаловСервер` с функцией `ОстатокМатериала` (занятие 65) и пользователи Сидорова и Петров.

Убедитесь, что база совпадает с `main`: выгрузите конфигурацию и выполните `git status` — изменений нет. На шаге 7 конфигурация базы будет заменена загрузкой из файлов, поэтому выгрузите базу в новый файл `.dt`.

Как и на занятии 102, роль Орлова играете вы во втором окне терминала. Код Орлова в шаге 1 дан готовым, со всеми его ошибками: переписывать его «правильно» сразу не нужно, иначе ревьюировать будет нечего.


## Шаг 2. Получите изменение на ревью

В первом окне, в `construction-erp`:

```bash

git log --oneline main..origin/feature/stock-hint
git diff main...origin/feature/stock-hint
```

Вы видите один коммит и одно изменение — модуль формы передачи. Ревью начинается с чтения, без запуска: так вы найдёте то, что не проявилось бы на вашем тестовом документе.

Перечитайте просьбу Сидоровой в теории. Задача — коротко показать, **хватит ли материалов этого документа на складе передачи**, и предложить открыть полный отчёт.

**Проверка:** изменение ветки получено и прочитано целиком.

## Шаг 3. Пройдите чек-лист

Создайте в конспекте файл `reviews/stock-hint.md`. Пройдите вопросы чек-листа из теории по порядку и к каждому вопросу перечитайте изменение. Не останавливайтесь на первой найденной проблеме: задача ревью — найти все.

Подсказки для самых трудных вопросов:

1. **Делает ли код то, что просил заказчик?** Из какой таблицы запрос берёт количество? Что такое остаток материала в нашей конфигурации и где он хранится (занятия 42 и 65)? Что запрос сделает с передачами, непроведёнными и помеченными на удаление поступлениями?
2. **Верны ли данные для любого пользователя?** Войдите мысленно под Козловым, кладовщиком «Склада на объекте». Остатки какого склада он увидит?
3. **Сколько серверных вызовов?** Сколько раз код обратится к серверу для передачи из двадцати строк? Сколько запросов выполнит?
4. **Как проверяются права?** Что увидит Сидорова, снабженец, для которой задача и делалась?
5. **Разрешено ли это платформой?** Какое значение у свойства **Режим использования модальности** в нашей конфигурации (занятие 83)?

**Проверка:** на каждый вопрос чек-листа в конспекте есть ответ — «замечаний нет» или найденная проблема.

## Шаг 4. Запишите замечания

Оформите каждую найденную проблему по пяти частям теории: место, что не так, почему это проблема, предложение, серьёзность. Пример первого замечания:

| Часть | Текст |
| --- | --- |
| Место | `Form/Module.bsl`, функция `ОстатокНаСервере` |

| Почему это проблема | Козлов и любой кладовщик другого склада увидят остатки «Центрального склада»; переименование склада молча сломает функцию |

| Серьёзность | блокирующее |

В конце файла вынесите решение по ревью: одобрение или запрос изменений.

**Проверка:** каждое замечание содержит пять частей; решение по ревью записано.

## Шаг 5. Сверьте замечания

Только после того, как ваши замечания записаны, сверьте их со списком ниже. Отметьте, что вы нашли сами и что пропустили.

| № | Место | Проблема | Серьёзность |
| --- | --- | --- | --- |
| 1 | запрос в `ОстатокНаСервере` | остаток считается по строкам поступлений: передачи не вычитаются, учитываются непроведённые и помеченные на удаление документы; источник остатка — регистр `ОстаткиМатериалов` | блокирующее |
| 2 | `УстановитьПараметр("Склад", ...)` | склад задан строкой вместо `Объект.Склад` | блокирующее |
| 3 | `Вопрос(` | модальный вызов; в конфигурации с запретом модальности завершится ошибкой, нужен `ПоказатьВопрос` с `ОписаниеОповещения` | блокирующее |
| 4 | `РольДоступна("Кладовщик")` | проверка по имени роли: Сидорова получит «Нет прав», хотя задача для неё; видимость кнопки уже настроена по `ПравоДоступа` на занятии 98 | блокирующее |
| 5 | цикл с `ОстатокНаСервере` | серверный вызов и запрос на каждую строку; нужен один вызов и один запрос на все материалы | важное |
| 6 | `&НаСервере` у функции | функции не нужен контекст формы, а директива везёт его на сервер при каждом из многих вызовов; нужна `&НаСервереБезКонтекста` | важное |
| 7 | `Возврат Выборка.Количество` | для материала без поступлений `СУММА` вернёт `NULL`, а не `0` (занятие 57); с регистром и общим модулем вопрос исчезает | важное |
| 8 | запрос в модуле формы | запрос остатков дублирует логику общего модуля `ОстаткиМатериаловСервер`; второй источник остатка однажды разойдётся с первым | важное |

Если вы нашли проблему, которой нет в списке, оставьте её в замечаниях: список не исчерпывающий.

**Проверка:** в конспекте отмечено, какие из восьми проблем найдены самостоятельно; решение — запрос изменений.

## Шаг 6. Орлов исправляет

Во втором окне, в клоне Орлова, внесите исправления.

1. Откройте модуль общего модуля `src/cf/CommonModules/ОстаткиМатериаловСервер/Ext/Module.bsl` и добавьте в конец функцию, которая получает остатки нескольких материалов одним запросом:

```bsl
// Возвращает остатки материалов на складе: Соответствие "материал — остаток".
// Материалов без остатка в соответствии нет.
Функция ОстаткиМатериалов(Склад, Материалы) Экспорт

	Запрос = Новый Запрос;
	Запрос.Текст =
		"ВЫБРАТЬ
		|	Остатки.Материал КАК Материал,
		|	Остатки.КоличествоОстаток КАК Остаток
		|ИЗ
		|	РегистрНакопления.ОстаткиМатериалов.Остатки(, Склад = &Склад И Материал В (&Материалы)) КАК Остатки";

	Запрос.УстановитьПараметр("Склад", Склад);
	Запрос.УстановитьПараметр("Материалы", Материалы);

	Результат = Новый Соответствие;

	Выборка = Запрос.Выполнить().Выбрать();
	Пока Выборка.Следующий() Цикл
		Результат.Вставить(Выборка.Материал, Выборка.Остаток);
	КонецЦикла;

	Возврат Результат;

КонецФункции
```

2. В модуле формы передачи замените процедуру `ОстаткиСклада` и функцию `ОстатокНаСервере` следующим кодом:

```bsl
&НаКлиенте
Процедура ОстаткиСклада(Команда)

	Если Не ЗначениеЗаполнено(Объект.Склад) Тогда
		Сообщить("Сначала выберите склад передачи");
		Возврат;
	КонецЕсли;

	Материалы = Новый Массив;
	Для Каждого СтрокаМатериалов Из Объект.Материалы Цикл
		Материалы.Добавить(СтрокаМатериалов.Материал);
	КонецЦикла;

	Сообщить(ТекстОстатков(Объект.Склад, Материалы));

	Оповещение = Новый ОписаниеОповещения("ОстаткиСкладаЗавершение", ЭтотОбъект);
	ПоказатьВопрос(Оповещение, "Открыть отчёт по складу?", РежимДиалогаВопрос.ДаНет);

КонецПроцедуры

&НаКлиенте
Процедура ОстаткиСкладаЗавершение(Ответ, ДополнительныеПараметры) Экспорт

	Если Ответ <> КодВозвратаДиалога.Да Тогда
		Возврат;
	КонецЕсли;

	ПараметрыФормы = Новый Структура;
	ПараметрыФормы.Вставить("Отбор", Новый Структура("Склад", Объект.Склад));
	ПараметрыФормы.Вставить("СформироватьПриОткрытии", Истина);

	ОткрытьФорму("Отчет.ОстаткиНаСкладах.Форма", ПараметрыФормы, ЭтаФорма);

КонецПроцедуры

&НаСервереБезКонтекста
Функция ТекстОстатков(Склад, Материалы)

	Остатки = ОстаткиМатериаловСервер.ОстаткиМатериалов(Склад, Материалы);

	Текст = "Остатки на складе «" + Строка(Склад) + "»:";
	Для Каждого Материал Из Материалы Цикл
		Остаток = Остатки.Получить(Материал);
		Если Остаток = Неопределено Тогда
			Остаток = 0;
		КонецЕсли;
		Текст = Текст + Символы.ПС + Строка(Материал) + ": " + Строка(Остаток);
	КонецЦикла;

	Возврат Текст;

КонецФункции
```

Разберите, как исправление отвечает на каждое замечание. Остаток берётся из регистра функцией общего модуля — один источник для отчёта, проведения и формы. Склад — из документа. Список материалов собирается на клиенте из данных формы: они уже там, серверный вызов для этого не нужен. На сервер код обращается один раз, запрос выполняется один. Вопрос немодальный: `ОстаткиСклада` показывает окно и заканчивается, ответ придёт в `ОстаткиСкладаЗавершение` (занятие 83). Проверки роли нет: кнопку и так видят только те, у кого есть право на отчёт.

3. Закоммитьте и отправьте:

## Шаг 7. Проведите повторное ревью и проверку

Повторное ревью смотрит только новый коммит:

```bash
git fetch
git log -p -1 origin/feature/stock-hint
```

Ключ `-p` показывает изменения коммита. Сверьте их со своими замечаниями: на каждое есть ответ в коде.

Теперь проверьте исправление в базе. Ваша база совпадает с `main`, а ветка Орлова ответвилась от свежего `main`.

```bash
git switch feature/stock-hint
```

Git создаст локальную ветку `feature/stock-hint`, связанную с веткой сервера.

1. Загрузите конфигурацию из файлов `src\cf` в учебную базу, выполните `F7`.
2. Войдите под Сидоровой. Откройте проведённую передачу с «Центрального склада» и нажмите **Остатки склада**. Появилось одно сообщение со списком материалов документа и их остатками; окно с вопросом не помешало сообщению появиться.
3. Нажмите **Да**. Открылся отчёт «Остатки на складах» по «Центральному складу». Сверьте с ним числа из сообщения.
4. Войдите под Козловым и откройте передачу «Склада на объекте». Нажмите **Остатки склада**: в сообщении — склад «Склад на объекте» и его остатки. На вопрос ответьте **Нет**: отчёт не открылся.
5. Вернитесь в конфигуратор, выгрузите конфигурацию и выполните `git status`. Изменений нет.

**Проверка:** у Сидоровой и Козлова сообщение показывает остатки склада их передачи, совпадающие с отчётом; ответ «Нет» не открывает отчёт.

## Проверка результата

Занятие пройдено, если выполняются шесть условий:

1. В конспекте есть файл ревью с замечаниями по пяти частям и решением «запрос изменений».
2. Найдены самостоятельно хотя бы четыре проблемы из восьми, включая хотя бы две блокирующие.
3. В исправленном коде остатки берутся функцией `ОстаткиМатериалов` общего модуля одним запросом к регистру, склад — из документа, вопрос — через `ПоказатьВопрос`.
4. Проверка под Сидоровой и Козловым показала остатки склада их передачи, совпадающие с отчётом.
5. Повторное ревью записано, ветка слита в `main` и удалена.
6. База совпадает с `main`.
