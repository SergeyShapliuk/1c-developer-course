# Практика. Нормализация справочника «Товары»

## Самостоятельная задача

Готового решения в этом разделе нет. Прочитайте постановку, решите задачу сами и только потом открывайте разбор.

Справочник «Товары» заполнялся вручную на разных занятиях, поэтому данные в нём неровные: где-то артикул написан строчными буквами, где-то с лишними пробелами, где-то не заполнена единица измерения. Нужна обработка, которая сначала покажет масштаб беспорядка, а потом его устранит.

**Создайте обработку** с именем `НормализацияСправочников` и синонимом «Нормализация справочников». Включите её в подсистему `Разработка`, чтобы она открывалась из одноимённого раздела приложения.

**Создайте общий модуль** с именем `НормализацияСправочниковСервер` и флагами **Сервер** и **Вызов сервера**. Весь код работы с базой живёт в нём, а все процедуры, вызываемые с клиента, объявлены с `Экспорт`.

**Создайте на форме обработки две команды формы:** `Проверить` с заголовком «Проверить» и `Исправить` с заголовком «Исправить».

### Команда «Проверить»

Одним серверным вызовом собирает статистику по справочнику «Товары»: сколько элементов всего, у скольких пустой `Артикул`, у скольких пустая `ЕдиницаИзмерения`, у скольких `Цена` равна нулю. Результат выводится пользователю, данные не меняются.

### Команда «Исправить»

Одним серверным вызовом приводит данные в порядок: `Артикул` — к верхнему регистру и без пробелов по краям (подсказка: `ВРег()` и `СокрЛП()`), `ЕдиницаИзмерения` — подставляет `"шт."` там, где пусто. Записывает **только изменённые** элементы и выводит, сколько элементов изменено.

### Требования

1. Весь код работы с базой — на сервере. В клиентских процедурах не должно быть ни одного обращения к `Справочники.*`.
2. На одну команду — **один** серверный вызов. Вызов внутри цикла не допускается.
3. Элементы, помеченные на удаление, не обрабатываются. В справочнике для этого есть «Тестовый материал».
4. Пустое или некорректное значение обрабатывается через `Попытка` или `ВызватьИсключение` — не молча.
5. Результат выводится пользователю через `Сообщить()`.

### Подготовка данных

Чтобы было что нормализовать, заведите несколько товаров с нарочно неряшливыми данными: артикул из одних пробелов, артикул строчными буквами, нулевая цена, пустая единица измерения. Для этого перенесите в общий модуль `НормализацияСправочниковСервер` функцию `СоздатьТоварЕслиНет(Наименование, Артикул, Цена)` из занятия 20, добавив ей `Экспорт`, и вызовите её из «Учебной консоли». «Тестовый материал» не трогайте: он должен остаться помеченным на удаление.

## Критерии готовности

Каждое утверждение проверяется, не заглядывая в код.

1. Обработка «Нормализация справочников» открывается из раздела **Разработка**.
2. На форме обработки есть обе кнопки: **Проверить** и **Исправить**.
3. Команда **Проверить** выводит четыре числа: всего элементов, пустых артикулов, пустых единиц измерения, нулевых цен.
4. Команда **Исправить** выводит число изменённых элементов.
5. Повторный запуск **Исправить** сразу после первого выводит **ноль** изменённых.
6. Команда **Проверить** после **Исправить** показывает ноль пустых артикулов и ноль пустых единиц измерения.
7. В клиентских процедурах нет ни одного обращения к `Справочники.*`.
8. На одну нажатую команду приходится один серверный вызов — цикла с обращением к серверу внутри нет.
9. При пустом справочнике обработка не падает, а сообщает, что обрабатывать нечего.
10. Элемент «Тестовый материал», помеченный на удаление, после запуска **Исправить** остался неизменённым.

## Типичные ошибки

**1. Обращение к `Справочники.Товары` из `&НаКлиенте`.** Симптом: синтаксический контроль сообщает, что переменная или метод не обнаружены. Причина: менеджеры объектов существуют только на сервере. Исправление: перенести обращение в экспортную функцию общего модуля или в `&НаСервереБезКонтекста` функцию модуля формы, а с клиента только вызвать её.

**2. Забытый `Экспорт` в общем модуле.** Симптом: синтаксический контроль сообщает, что функция не обнаружена, хотя она есть и имя написано верно. Причина: без `Экспорт` процедура видна только внутри своего модуля. Исправление: дописать `Экспорт` в объявлении.

**3. Снятый флаг «Вызов сервера».** Симптом: синтаксический контроль сообщает, что метод недоступен из клиентского кода, хотя `Экспорт` на месте. Причина: `Экспорт` открывает функцию другим модулям, а дорогу с клиента открывает отдельный флаг. Исправление: включить **Вызов сервера** в палитре свойств общего модуля.

**4. `Записать()` для каждого элемента без проверки, изменилось ли значение.** Симптом: повторный запуск **Исправить** выводит столько же изменённых, сколько первый. Причина: запись выполняется всегда, а не только при фактическом изменении. Исправление: сравнить новое значение со старым и записывать объект только при различии — это и есть идемпотентность.

**5. Сравнение пустой строки с `Неопределено`.** Симптом: пустые артикулы не попадают в статистику, число всегда ноль. Причина: незаполненная строка — это пустая строка `""`, а не `Неопределено`, поэтому сравнение ложно всегда. Исправление: использовать `ЗначениеЗаполнено()`, а строку пропускать через `СокрЛП()`, чтобы одни пробелы считались пустым значением.

**6. `НайтиПоНаименованию` без проверки `ПустаяСсылка()`.** Симптом: при выполнении ошибка вида «поле объекта не обнаружено». Причина: если элемент не найден, функция возвращает пустую ссылку, и обращаться к её реквизитам нельзя. Исправление: сравнить результат с `Справочники.Товары.ПустаяСсылка()` до обращения к реквизитам.

**7. Серверный вызов внутри цикла.** Симптом: обработка заметно задумывается, и чем больше элементов, тем дольше. Причина: на каждый элемент выполняется отдельный переход клиент → сервер. Исправление: перенести цикл целиком на сервер, а клиенту вернуть один готовый результат.

**8. Попытка прочитать реквизит формы в `&НаСервереБезКонтекста`.** Симптом: синтаксический контроль сообщает, что переменная не определена. Причина: процедура без контекста не видит реквизитов формы. Исправление: передать значение параметром, а результат вернуть значением функции.

**9. Обработка элементов, помеченных на удаление.** Симптом: «Тестовый материал» попал в статистику или у него изменился артикул. Причина: в цикле не проверяется признак `ПометкаУдаления`. Исправление: в начале цикла пропускать такие элементы оператором `Продолжить`.

Почему сделано именно так.

Обе рабочие функции возвращают **структуру** (занятие 17), а не выводят текст сами. Сервер занимается только данными, а решение, как их показать, остаётся на клиенте; заодно структуру удобно дополнить новым полем, не ломая вызывающий код.

`Выбрать()` и `Пока Выборка.Следующий() Цикл` — перебор справочника с занятия 19. Весь цикл выполняется на сервере, поэтому серверный вызов на команду получается один, как требует занятие 22.

`Продолжить` при `Выборка.ПометкаУдаления` закрывает требование не трогать помеченные элементы (занятие 20). Проверка стоит в самом начале цикла, до увеличения счётчиков, — иначе такой элемент попал бы в статистику.

Проверка пустоты написана как `НЕ ЗначениеЗаполнено(СокрЛП(...))` (занятие 12). `СокрЛП` нужен потому, что артикул из одних пробелов формально заполнен, а по смыслу пуст.

Сравнение `НовыйАртикул = Выборка.Артикул И НоваяЕдиница = Выборка.ЕдиницаИзмерения` — это и есть идемпотентность. Если ничего не меняется, `Продолжить` отменяет и `ПолучитьОбъект()`, и `Записать()`. Именно поэтому повторный запуск выводит ноль изменённых.

Запись идёт через `Выборка.Ссылка.ПолучитьОбъект()`: выборка даёт только ссылку и значения реквизитов, а менять и записывать можно лишь объект (занятия 19 и 20).

Блок `Попытка` обнимает ровно запись одного элемента (занятие 24). Так ошибка на одном «плохом» элементе не обрывает обработку остальных, а счётчик `Ошибок` и `ОписаниеОшибки()` не дают проблеме остаться незамеченной.

`СоздатьТоварЕслиНет` переехала из модуля формы в общий модуль и получила `Экспорт` (занятие 21). Правило «сначала найти, потом создать» с занятия 20 сохранено, а `ВызватьИсключение` при пустом наименовании честно сообщает о недопустимых данных вместо тихого возврата пустой ссылки.

Почему сделано именно так.

В обоих обработчиках ровно по одному обращению к серверу — в первой строке процедуры. Дальше работа идёт с уже полученной структурой, и обращений к `Справочники.*` на клиенте нет (занятия 21 и 22).

Проверка `Статистика.Всего = 0` закрывает негативный сценарий с пустым справочником: обработка не падает, а сообщает, что обрабатывать нечего. Проверка стоит на клиенте, по уже привезённому числу, — лишнего серверного вызова для неё не нужно.

Команды независимы: ни «Проверить», ни «Исправить» не опираются на результат другой. Поэтому порядок нажатия не важен, и пункт 10 чек-листа выполняется сам собой.

`Строка()` вокруг чисел нужна потому, что конкатенация строки с числом требует явного преобразования (занятия 11 и 12).

### Подготовка данных из «Учебной консоли»

Тестовые элементы удобно заводить через обработку `УчебнаяКонсоль`, не добавляя лишних кнопок на форму нормализации:

```bsl
&НаКлиенте
Процедура Выполнить(Команда)
	НормализацияСправочниковСервер.СоздатьТоварЕслиНет("Песок речной", "   ", 0);
	НормализацияСправочниковСервер.СоздатьТоварЕслиНет("Цемент М400", "цем-01", 310);
	НормализацияСправочниковСервер.СоздатьТоварЕслиНет("Гвозди строительные", " гв-100 ", 95);
	Сообщить("Тестовые данные подготовлены");
КонецПроцедуры
```

Повторный запуск этого кода новых элементов не создаст: `СоздатьТоварЕслиНет` сначала ищет товар по наименованию и возвращает найденный. Это то же правило идемпотентности, что и в `НормализоватьТовары`.

После подготовки данных пройдите чек-лист сверху вниз и запишите фактические результаты. Если все пункты отмечены — контрольная точка пройдена, можно переходить к этапу 3.
