# Теория. Журнал регистрации

## Какую задачу мы решаем

На складе «Склад на объекте» появился отрицательный остаток щебня. Отчёт с красным минусом (занятие 77) показал проблему, оборотная ведомость (занятие 75) — документ, который её создал: передачу задним числом. Руководитель задаёт следующий вопрос: **кто** провёл эту передачу и **когда**? В документе есть реквизит «Ответственный», но это сотрудник, которого выбрали в поле, а не тот, кто нажал **Провести**.

Второй вопрос — про заявки. Заявку на «ЖК Северный» отклонили, прораб звонит снабженцу: «кто отклонил и почему?» Состояние в заявке говорит, что она отклонена, но не говорит, кем.

Ответ на такие вопросы хранит не учёт, а **журнал регистрации**.

## Журнал регистрации

**Журнал регистрации** — протокол работы информационной базы. Каждая запись — **событие**: когда, какой пользователь, на каком компьютере, в каком приложении, что произошло, с какими данными.

Многое платформа записывает сама.

| Событие | Когда записывается |
| --- | --- |
| Сеанс. Начало, Сеанс. Завершение | пользователь вошёл и вышел |
| Сеанс. Аутентификация | попытка входа, в том числе неудачная |
| Данные. Добавление, Данные. Изменение | объект записан |
| Данные. Проведение, Данные. Отмена проведения | документ проведён или проведение отменено |
| Данные. Удаление | объект удалён |

Пометка на удаление для платформы — тоже запись объекта, поэтому и она оставляет в журнале событие с пользователем и временем.

Поэтому на вопрос «кто провёл передачу» ответ уже есть: событие «Данные. Проведение» с этой передачей в колонке данных и пользователем в колонке пользователя. Есть одно условие: пользователь должен быть. События учебной базы до занятия 91 записаны без пользователя — у базы тогда не было понятия «кто».

У каждого события есть **уровень**: **Ошибка**, **Предупреждение**, **Информация**, **Примечание**. Какие уровни вообще записывать, задаёт **настройка журнала регистрации** в конфигураторе. Если запись событий выключена, отвечать будет нечем.

## Как искать

Журнал быстро вырастает до десятков тысяч событий, и читать его подряд бесполезно. События **отбирают**: по периоду, по пользователю, по виду события, по объекту метаданных — например, только документ `ПередачаМатериалов`, — по конкретным данным. Хороший вопрос к журналу похож на хороший запрос: сначала сформулировать, что ищем, потом поставить отбор.

## Своё событие

Платформа записывает, **что** объект записан, но не **почему**. Отклонение заявки для неё — обычное «Данные. Изменение», неотличимое от правки комментария. Если событие важно для бизнеса, его записывают сами методом `ЗаписьЖурналаРегистрации`:

```bsl
ЗаписьЖурналаРегистрации("Снабжение.ОтклонениеЗаявки",
	УровеньЖурналаРегистрации.Информация,
	Метаданные.Документы.ЗаявкаНаМатериалы,
	Ссылка,
	"Объект строительства: " + Строка(ОбъектСтроительства));
```

| Параметр | Значение |
| --- | --- |
| имя события | строка, по которой событие найдут; через точку — группа и действие, как у событий платформы |
| уровень | `Информация` — штатное событие, `Ошибка` — сбой |
| объект метаданных | вид данных, по которому будут отбирать |
| данные | ссылка на сам документ |
| комментарий | то, что нужно человеку, читающему журнал |

Пользователя, время и компьютер платформа добавит сама.

## Где записывать событие

Заявку отклоняют командой формы (занятия 37 и 83), но решение становится фактом, только когда заявку **записали**. Пользователь может нажать **Отклонить** и закрыть форму без записи — тогда отклонения не было. Поэтому событие пишут в модуле объекта, а не в форме.

Модуль объекта решает две задачи в два момента.

1. **`ПередЗаписью`** — понять, что заявка **переходит** в состояние «Отклонена». Здесь ещё можно сравнить новое состояние с записанным в базе (`Ссылка.Состояние`), как на занятии 93. Проверка «переходит ли в состояние» нужна теперь дважды — для согласования и для отклонения, — поэтому её обобщают одной функцией с параметром-состоянием.
2. **`ПриЗаписи`** — записать событие. Этот обработчик выполняется после записи объекта в базу: если запись отменили в `ПередЗаписью` или раньше, события не будет. У нового документа здесь уже есть ссылка.

Передать вывод из первого обработчика во второй помогает **`ДополнительныеСвойства`** — структура у записываемого объекта, которая живёт одну запись. Её можно заполнить в `ПередЗаписью` и прочитать в `ПриЗаписи`.

Модуль объекта выбран и потому, что так событие запишется при отклонении любым путём — из формы, из обработки, из кода.

## Журнал — не учёт

Журнал регистрации хранится отдельно от данных базы, его можно сократить, очистить, настроить так, что часть событий не попадёт в него вовсе. Поэтому на журнал не опираются в учётной логике: «сколько заявок отклонено за месяц» считают по состоянию заявок, а не по событиям журнала. Журнал отвечает на вопросы расследования: кто, когда, с какого компьютера.

## Где живёт логика

| Что | Где | Почему |
| --- | --- | --- |
| Кто вошёл, кто записал и провёл | события платформы | записываются без кода |
| Какие события записывать | настройка журнала регистрации | решение администратора |
| Отклонение заявки как событие | `ПриЗаписи` модуля объекта заявки | событие — факт записи, а не нажатие кнопки |
| Распознавание перехода в состояние | функция модуля объекта, вызываемая из `ПередЗаписью` | одна проверка для согласования и отклонения |
| Число отклонённых заявок | запрос к заявкам | журнал — не учётные данные |

## Что важно запомнить

1. Журнал регистрации — протокол работы базы: событие, пользователь, время, компьютер, данные.
2. Платформа сама записывает вход и выход, неудачную аутентификацию, запись, проведение, отмену проведения и пометку удаления.
3. В журнале ищут отбором: по периоду, пользователю, событию, объекту метаданных и данным.
4. Своё событие пишут методом `ЗаписьЖурналаРегистрации`, когда платформенного «записано» недостаточно, чтобы понять, что произошло.
5. Событие о факте записи пишут в `ПриЗаписи` модуля объекта, а распознают в `ПередЗаписью`; вывод передают через `ДополнительныеСвойства`.
6. Журнал регистрации не заменяет учётные данные: учётные вопросы решают запросом к данным.
