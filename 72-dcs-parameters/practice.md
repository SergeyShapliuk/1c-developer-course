# Практика. Дата остатков и выбор склада

## Перед началом

Запустите конфигуратор учебной конфигурации **«Управление строительной компанией с логистикой»** и откройте основную схему компоновки данных отчёта `ОстаткиНаСкладах`. После занятия 71 её структура — **Отчет → Склад → Материал**.

Понадобится общий модуль `ОстаткиМатериаловСервер` с функцией `ОстатокМатериала` из занятия 65: с ней будем сверять отчёт.

Выберите в журнале **Логистика → Передачи материалов** одну проведённую передачу цемента с «Центрального склада» и запишите в конспект её дату. В примерах ниже это `05.10.2026`. Если в этот же день по цементу проводились и другие документы, выберите передачу из другого дня: сверка будет проще.

После каждой правки: `Ctrl+S`, затем `F5`, раздел **Логистика → Отчеты → Остатки на складах**, кнопка **Сформировать**.

## Шаг 1. Получите ожидаемые числа в консоли

1. Откройте модуль формы обработки `УчебнаяКонсоль` и добавьте процедуру:

```bsl
&НаСервере
Процедура ВывестиОстаткиНаНачалоДня()

	Цемент = Справочники.Товары.НайтиПоНаименованию("Цемент М500");
	Склад = Справочники.Склады.НайтиПоНаименованию("Центральный склад");

	Сообщить("На начало 05.10: " + ОстаткиМатериаловСервер.ОстатокМатериала(Цемент, Склад, '20261005'));
	Сообщить("На начало 06.10: " + ОстаткиМатериаловСервер.ОстатокМатериала(Цемент, Склад, '20261006'));
	Сообщить("Сейчас: " + ОстаткиМатериаловСервер.ОстатокМатериала(Цемент, Склад));

КонецПроцедуры
```

2. Подставьте дату своей передачи и следующий за ней день. Вызовите процедуру из `Выполнить` вместо прежних вызовов, запустите, нажмите **Выполнить**.
3. Запишите три числа в конспект.

Разница между первыми двумя числами — движения цемента за день передачи. Если других документов в этот день не было, она равна количеству передачи.

**Проверка:** в конспекте три ожидаемых остатка цемента «Центрального склада», и разница первых двух объяснена.

## Шаг 2. Найдите параметр, которого нет в запросе

1. В редакторе схемы откройте вкладку **Параметры**.
2. В списке уже есть параметр `Период`, хотя в тексте запроса набора данных нет ни одного `&`. Его добавила система компоновки — это первый параметр таблицы остатков.
3. Посмотрите его свойства: **Тип** — дата, **Значение** — пустое.

**Проверка:** на вкладке **Параметры** есть `Период`, текст запроса не изменился.

## Шаг 3. Настройте параметр для пользователя

1. В строке параметра `Период` впишите **Заголовок** — «Остатки на начало дня».
2. Откройте редактирование **Типа** и установите состав даты **Дата** — без времени.
3. Если у параметра отмечено **Ограничение доступности**, снимите отметку: дату выбирает пользователь.
4. Перейдите на вкладку **Настройки**, выделите узел **Отчет** и откройте внизу закладку **Параметры**. В ней строка «Остатки на начало дня» с флажком использования.
5. Выделите эту строку, в контекстном меню выберите **Свойства элемента пользовательских настроек**.
6. Отметьте **Включать в пользовательские настройки**, режим редактирования — **Быстрый доступ**. Нажмите **ОК**.
7. Сохраните, запустите отчёт.

Над кнопкой **Сформировать** появилось поле «Остатки на начало дня» с флажком.

**Проверка:** на форме отчёта есть поле даты с подписью «Остатки на начало дня».

## Шаг 4. Сверьте остатки на дату

1. Не отмечая флажок даты, сформируйте отчёт. Остаток цемента «Центрального склада» должен совпасть с числом «Сейчас» из конспекта.
2. Отметьте флажок, выберите дату передачи, сформируйте. Остаток цемента должен совпасть с числом «На начало 05.10».
3. Выберите следующий день, сформируйте. Остаток должен совпасть с числом «На начало 06.10».

Передача пятого октября попала в остаток на начало шестого, но не в остаток на начало пятого. Это граница периода занятия 65, и подпись поля говорит о ней пользователю прямо.

**Проверка:** три остатка цемента в отчёте совпадают с тремя числами консоли.

## Шаг 5. Добавьте отбор по складу

1. Вернитесь в схему, вкладка **Настройки**, узел **Отчет**, закладка **Отбор**.
2. Нажмите **Добавить** и выберите поле `Склад`. Вид сравнения — **Равно**, значение оставьте пустым.
3. Снимите флажок использования у этого элемента отбора: по умолчанию отчёт показывает все склады.
4. В контекстном меню элемента выберите **Свойства элемента пользовательских настроек**, отметьте **Включать в пользовательские настройки**, режим — **Быстрый доступ**.
5. Сохраните, запустите отчёт. Над результатом теперь два поля: дата и склад.
6. Сформируйте без склада — видны все склады. Выберите «Центральный склад», отметьте флажок, сформируйте — остался один склад.
7. Сравните остатки «Центрального склада» с выводом процедуры `ВывестиОстаткиСклада` занятия 65.

Откройте текст запроса набора данных. В нём по-прежнему нет `ГДЕ`. Условие на склад система компоновки добавила сама — и, поскольку `Склад` измерение регистра, поставила его в параметры виртуальной таблицы.

**Проверка:** отчёт показывает один склад при включённом отборе и все — при выключенном, остатки совпадают с консолью.

## Шаг 6. Посмотрите, почему склад — не параметр запроса

1. В тексте запроса набора данных добавьте в конец условие:

```bsl
ГДЕ
	ОстаткиМатериаловОстатки.Склад = &Склад
```

2. Откройте вкладку **Параметры** — появился параметр `Склад`.
3. Посмотрите, где стоит условие: после `ИЗ` таблицы остатков, в `ГДЕ`. Таблица остатков сначала посчитает остатки по всем складам, и только потом условие отбросит лишние строки. На занятии 64 такое место для условия на измерение мы назвали ошибкой. Отбор из шага 5 система компоновки поставила в параметры виртуальной таблицы — туда, где ему место.
4. Вернитесь на вкладку **Настройки**, закладка **Отбор**, и раскройте список видов сравнения у элемента отбора по складу: **Равно**, **Не равно**, **В списке** и другие. Параметр `&Склад` в условии `ГДЕ` умеет только «равно»: «эти два склада» им не выразить. Запишите оба недостатка условия в запросе в конспект.
5. Удалите условие `ГДЕ` из текста запроса. Если параметр `Склад` остался на вкладке **Параметры**, удалите и его.

**Проверка:** в конспекте записаны два недостатка условия в запросе — место после расчёта таблицы и единственный вид сравнения, — и запрос возвращён в прежний вид.

## Шаг 7. Проверьте, что пользователь сохранил свой выбор

1. В приложении выберите в отчёте склад «Центральный склад» и дату, сформируйте.
2. Закройте отчёт и откройте его снова из раздела **Логистика**.
3. Убедитесь, что выбранные склад и дата сохранились.

Кладовщик выбирает свой склад один раз. Разработчик для этого не написал ни строки: пользовательские настройки платформа сохраняет сама.

4. Снимите флажки даты и склада, чтобы отчёт снова показывал все склады на сегодня.

**Проверка:** после повторного открытия отчёта выбор склада и даты сохранился.

## Проверка результата

Занятие пройдено, если выполняются шесть условий:

1. У параметра `Период` заголовок «Остатки на начало дня», тип — дата без времени, ограничения доступности нет.
2. Параметр и отбор по складу включены в пользовательские настройки в режиме **Быстрый доступ** и видны на форме отчёта.
3. Без даты отчёт показывает текущие остатки, с датой — остатки на начало дня, и все три сверки с консолью сходятся.
4. Отбор по складу выключен по умолчанию, и без него отчёт показывает все склады.
5. В тексте запроса набора данных нет `ГДЕ` и нет параметра `Склад`.
6. Выбор пользователя сохраняется между открытиями отчёта.

4. Почему отбор по складу не замедляет отчёт, хотя в запросе нет условия на склад?
