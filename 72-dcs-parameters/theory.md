# Теория. Параметры и отборы

## Какую задачу мы решаем

Отчёт «Остатки на складах» отвечает на один вопрос — «сколько всего сейчас на всех складах». У его пользователей вопросы уже:

- кладовщик «Центрального склада» хочет видеть только свой склад, а не листать чужой;
- бухгалтеру к сверке нужны остатки на начало месяца, а не на сегодня;
- снабженцу по-прежнему нужны все склады сейчас.

Писать три отчёта не нужно: вопрос один, меняются условия. В консоли на занятии 65 условия передавались параметрами запроса, которые устанавливал код. В отчёте кода нет — условия должен задавать сам пользователь. Для этого у системы компоновки есть два инструмента: **параметры** и **отборы**.

## Параметр данных

**Параметр данных** — значение, которое система компоновки передаёт в запрос набора данных, как `Запрос.УстановитьПараметр` на занятии 55. Параметры перечислены на вкладке **Параметры** схемы.

Параметр в схеме появляется двумя путями.

1. **Из текста запроса.** Каждое `&Имя` в запросе набора данных становится параметром схемы с тем же именем.
2. **Из виртуальной таблицы.** Если набор данных обращается к виртуальной таблице без явных параметров, система компоновки сама добавляет её параметры. Для таблицы остатков это `Период` — тот же первый параметр, что на занятии 65.

Поэтому параметр `Период` уже есть в схеме отчёта, хотя в тексте запроса его нет. Если пользователь не задал значение, система компоновки не передаёт параметр в таблицу, и та возвращает текущий остаток. Если задал — остаток на этот момент.

## Свойства параметра

| Свойство | Зачем |
| --- | --- |
| **Заголовок** | подпись поля для пользователя |
| **Тип** | какие значения допустимы; для даты — ещё и состав: только дата или дата и время |
| **Значение** | значение по умолчанию |
| **Ограничение доступности** | если отмечено, пользователь параметр не видит и не меняет |

Ограничение доступности ставят параметрам, значение которых вычисляет сама схема или код, а не человек. Параметр `Период` пользователь должен видеть, поэтому ограничения у него нет.

## Дата параметра — снова граница

На занятии 65 выяснилось: дата в параметре периода таблицы остатков означает **начало** этого момента, движения с таким же периодом в остаток не входят. Если пользователь выберет `06.10.2026`, отчёт покажет остатки на `06.10.2026 0:00:00` — без документов, проведённых шестого октября.

В консоли эту ловушку закрывал `Новый Граница(…, ВидГраницы.Включая)`. В отчёте мы закроем её словами, а не кодом: параметр будет называться «Остатки на начало дня», а тип — только дата, без времени. Пользователь видит ровно то, что получит: «на начало шестого октября» означает «по пятое включительно». Подписи, которые честно описывают поведение, — тоже инструмент разработчика.

## Отбор

**Отбор** — условие на поле отчёта: «склад равен „Центральный склад“», «остаток меньше нуля». Отборы задают на закладке **Отбор** настроек. Каждый элемент отбора — это поле, **вид сравнения** (равно, не равно, в списке, больше, заполнено и другие) и значение. Флажок слева включает и выключает элемент, не удаляя его.

Отбор — часть настроек, а не данных. Запрос набора данных не знает, что пользователь выбрал склад: условие добавляет система компоновки перед выполнением. И добавляет его умно.

## Куда система компоновки ставит отбор

На занятиях 64–65 правило было жёстким: условие на измерение виртуальной таблицы пишут в её параметрах, условие на ресурс — в `ГДЕ`. В отчёте это правило соблюдает система компоновки.

- Отбор по `Склад` — по измерению регистра. Система компоновки перенесёт его в условие виртуальной таблицы, и остатки будут считаться только по выбранному складу.
- Отбор по `Остаток` — по ресурсу. Его система компоновки применит к уже посчитанным остаткам, как `ГДЕ`.

Поэтому в набор данных не пишут `ГДЕ Склад = &Склад`. Такое условие в тексте превратит склад в обязательный параметр: без значения отчёт не сможет ответить на вопрос «все склады», и снабженец останется без своего отчёта.

## Параметр или отбор

| Вопрос | Инструмент |
| --- | --- |
| Значение нужно запросу, чтобы вообще посчитать данные: дата остатков, начало и конец периода | параметр |
| Значение отбирает строки по полю, и «без отбора» тоже имеет смысл: склад, материал, объект | отбор |

Условия, которые пользователь менять **не должен**, — тоже не отбор. Если отчёт должен показывать только проведённые документы, `Проведен` пишут в `ГДЕ` запроса: снятый пользователем флажок отбора не должен превращать черновики в учёт.

## Пользовательские настройки

По умолчанию все настройки — параметры, отборы, поля, структура — меняются только в окне **Настройки** формы отчёта. Это много щелчков ради выбора склада. Разработчик решает, какие элементы вынести ближе к пользователю.

У каждого элемента настроек есть **свойства элемента пользовательских настроек**:

- **Включать в пользовательские настройки** — пользователь вообще может менять этот элемент;
- **Режим редактирования**:
  - **Быстрый доступ** — поле выводится прямо на форме отчёта, над результатом;
  - **Обычный** — элемент доступен в окне **Настройки**;
  - **Недоступный** — пользователь элемент не меняет.

Быстрый доступ дают тому, что меняют каждый раз: дате и складу. Обычный — тому, что меняют изредка. Чем больше полей на форме, тем труднее найти нужное, поэтому быстрый доступ — для двух-трёх главных вопросов, не для всего подряд.

Пользовательские настройки сохраняются между открытиями отчёта: кладовщик один раз выберет свой склад и при следующем открытии увидит его снова.

## Где живёт логика

Дата и склад — не код и не запрос, а настройки. Разработчик в схеме решает три вещи: какие параметры нужны данным, какие отборы допустимы и что вынести на форму. Пользователь в режиме приложения выбирает значения. Твёрдое правило учёта — например, «только проведённые» — остаётся в запросе, где пользователь его не отключит.

## Что важно запомнить

1. Параметр данных передаётся в запрос набора данных; он появляется из `&Имя` в тексте или из параметров виртуальной таблицы, которые система компоновки добавляет сама.
2. Незаданный параметр `Период` таблицы остатков не передаётся, и отчёт показывает текущий остаток.
3. Дата в периоде таблицы остатков — начало момента; подпись «на начало дня» и тип «только дата» честно сообщают это пользователю.
4. Отбор — условие на поле в настройках; отбор по измерению система компоновки переносит в параметры виртуальной таблицы сама.
5. Параметр нужен данным, отбор отбирает строки; правило, которое пользователь менять не должен, пишут в `ГДЕ` запроса.
6. Быстрый доступ выносит элемент настроек на форму отчёта; его дают двум-трём главным вопросам.
