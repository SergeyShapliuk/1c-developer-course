# Теория. Конфигуратор и дерево конфигурации

## Окно Конфигуратора

**Конфигуратор** — режим, в котором разработчик описывает прикладное решение. На занятии 2 вы уже заходили в него и видели главное меню.

Важные пункты меню:

- **Конфигурация** — работа с описанием решения: открыть, сохранить, обновить конфигурацию базы данных;
- **Администрирование** — пользователи, права, выгрузка и загрузка информационной базы;
- **Отладка** — запуск приложения для проверки и пошаговое исполнение кода;
- **Правка** и **Окна** — обычные команды редактирования и управления окнами.

Сразу после входа рабочая область может быть пустой. Описание решения открывается командой **Конфигурация → Открыть конфигурацию**. В части версий платформы конфигурация открывается автоматически при входе в Конфигуратор — тогда отдельная команда не нужна, окно с деревом уже на экране.

## Дерево конфигурации

**Дерево конфигурации** — главный инструмент разработчика. Это навигатор по описанию решения: всё, что вы создадите за курс, появится в этом дереве.

Устроено оно так. Самая верхняя строка со значком жёлтого кубика — **корневой узел**, то есть сама конфигурация. Ниже перечислены **группы объектов** — ветки, в каждой из которых лежат объекты одного вида:

- **Справочники** — списки однотипных сущностей;
- **Документы** — записи о произошедших событиях;
- **Перечисления** — фиксированные наборы вариантов;
- **Константы** — отдельные общие значения;
- **Отчёты** — представление данных пользователю;
- **Обработки** — выполнение действий над данными;
- **Регистры сведений** и **Регистры накопления** — хранение состояний и итогов;
- а также **Подсистемы**, **Общие модули**, **Роли**, **Планы видов характеристик** и другие.

Что означает каждая группа, разберём на занятии 4. Пока достаточно знать: дерево — это оглавление решения, а группы в нём присутствуют всегда, даже когда пусты. Пустая группа — не ошибка, а приглашение создать первый объект. Раскрывается группа щелчком по плюсу или треугольнику слева от названия; если она не раскрывается, в ней ничего нет.

## Палитра свойств

У каждого объекта в дереве есть набор свойств: имя, синоним, тип, поведение. Эти свойства показывает **палитра свойств** — отдельное окно со списком «свойство — значение».

Открыть палитру можно двумя способами: двойным щелчком по объекту в дереве или командой **Дополнительно → Свойства** в контекстном меню объекта (контекстное меню вызывается правой кнопкой мыши).

Свойств у объекта бывает несколько десятков. Пугаться этого не нужно: большинство имеет разумные значения по умолчанию и заполнять их не требуется. В курсе мы всегда называем конкретные свойства, которые нужно изменить, — остальные оставляйте как есть.

## Конфигурация и конфигурация базы данных

Это самое важное различие занятия, и его стоит понять сразу.

В одной информационной базе платформа хранит **две версии описания решения**.

**Конфигурация** — ваша редактируемая версия, та самая, которую вы видите в дереве. Это черновик разработчика: в нём можно добавить объект, передумать и удалить его, и пользователей это никак не затронет.

**Конфигурация базы данных** — версия, по которой реально построены таблицы данных и с которой работает пользователь в режиме «1С:Предприятие».

| | Конфигурация | Конфигурация базы данных |
| --- | --- | --- |
| Кто видит | Разработчик в Конфигураторе | Пользователь в режиме «1С:Предприятие» |
| Назначение | Черновик, его правят | Рабочая версия, по ней построены таблицы |
| Чем меняется | Правкой в дереве и `Ctrl+S` | Командой обновления (`F7`) |

Пока вы правите конфигурацию, пользователь продолжает работать со старой рабочей версией. Чтобы изменения дошли до него, нужно выполнить **Конфигурация → Обновить конфигурацию базы данных**. Только в этот момент платформа перестраивает таблицы данных под новое описание.

Отсюда частая ошибка новичка: объект создан, а в приложении его нет. Почти всегда причина одна — не выполнено обновление конфигурации базы данных.

## Три клавиши

Запомните три горячие клавиши — ими вы будете пользоваться на каждом занятии.

| Клавиша | Команда меню | Что делает |
| --- | --- | --- |
| `Ctrl+S` | **Конфигурация → Сохранить конфигурацию** | Сохраняет ваш черновик в Конфигураторе. Пользователю изменения ещё не видны. |
| `F7` | **Конфигурация → Обновить конфигурацию базы данных** | Переносит изменения в конфигурацию базы данных и перестраивает таблицы. |
| `F5` | **Отладка → Начать отладку** | Запускает режим «1С:Предприятие», чтобы проверить результат. |

Разница между `Ctrl+S` и `F7` — прямое следствие предыдущего раздела. Сохранение фиксирует черновик, обновление вводит его в действие.

## Цикл разработки

Любое изменение в 1С проходит один и тот же путь:

1. Изменить объект в Конфигураторе — создать новый или поправить свойства существующего.
2. Сохранить конфигурацию (`Ctrl+S`).
3. Обновить конфигурацию базы данных (`F7`) и подтвердить изменения.
4. Запустить режим «1С:Предприятие» (`F5`) и проверить результат глазами пользователя.

Этот цикл повторяется десятки раз за занятие. Выполняйте его целиком: пропущенный шаг 3 даёт ощущение «ничего не работает», пропущенный шаг 4 оставляет ошибку незамеченной.

Отдельно про шаг 3. Если при обновлении платформа показывает окно со списком изменений — **прочитайте этот список**, а не нажимайте «Принять» рефлекторно. В учебной базе ошибка стоит недорого, но привычка вырабатывается именно сейчас: в рабочей базе предприятия тот же список — последняя возможность заметить, что вместе с нужной правкой уходит потеря данных.

## Что важно запомнить

1. Дерево конфигурации — навигатор по описанию решения: корневой узел сверху, ниже группы объектов, которые присутствуют всегда, даже пустые.
2. Палитра свойств открывается двойным щелчком по объекту; заполнять нужно только названные в задании свойства.
3. Конфигурация — редактируемая версия разработчика, конфигурация базы данных — рабочая версия пользователя.
4. `Ctrl+S` сохраняет черновик, `F7` вводит изменения в действие, `F5` запускает проверку.
5. Цикл разработки: изменить, сохранить, обновить конфигурацию базы данных, проверить в пользовательском режиме.
6. Список изменений при обновлении нужно читать — это привычка, которая защищает рабочие базы.
