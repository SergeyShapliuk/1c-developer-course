# Теория. Временные таблицы и пакетный запрос

## Какую задачу мы решаем

Запрос исполнения заявок с занятия 62 считает правильно, но с ним неудобно работать. Его читают изнутри наружу, промежуточный результат нельзя проверить, не разобрав запрос на части, а если те же суммы поступлений понадобятся во втором отчёте, вложенный запрос придётся скопировать.

Снабженец уже просит второй ответ на тех же данных: какие заявки обеспечены полностью и их можно закрывать. Нужен способ посчитать промежуточные итоги **один раз**, сохранить их под именем, проверить и использовать несколько раз. Это **временные таблицы**.

## Временная таблица

Слово `ПОМЕСТИТЬ` после списка полей говорит платформе: результат не возвращай, а сохрани в **временную таблицу** с указанным именем.

```bsl
ВЫБРАТЬ
	ЗаявкаМатериалы.Ссылка КАК Заявка,
	ЗаявкаМатериалы.Материал КАК Материал,
	СУММА(ЗаявкаМатериалы.Количество) КАК Количество
ПОМЕСТИТЬ ВТ_Заказано
ИЗ
	Документ.ЗаявкаНаМатериалы.Материалы КАК ЗаявкаМатериалы
СГРУППИРОВАТЬ ПО
	ЗаявкаМатериалы.Ссылка,
	ЗаявкаМатериалы.Материал
```

Дальше в следующих запросах `ВТ_Заказано` используется как обычная таблица: `ИЗ ВТ_Заказано КАК Заказано`. Приставка `ВТ_` — общепринятое соглашение, а не требование платформы: по ней сразу видно, что таблица временная, а не таблица базы.

Временная таблица живёт, пока жив **менеджер временных таблиц**, в котором она создана, и видна только этому сеансу. В базе данных она не остаётся, другие пользователи её не видят.

## Пакетный запрос

Несколько запросов можно записать в одном тексте через точку с запятой `;`. Такой текст называют **пакетным запросом**, а каждый запрос в нём — запросом пакета. Платформа выполняет их по порядку, и каждый следующий видит временные таблицы, созданные предыдущими.

```bsl
ВЫБРАТЬ … ПОМЕСТИТЬ ВТ_Заказано ИЗ …
;
ВЫБРАТЬ … ПОМЕСТИТЬ ВТ_Поступило ИЗ …
;
ВЫБРАТЬ …
ИЗ
	ВТ_Заказано КАК Заказано
		ЛЕВОЕ СОЕДИНЕНИЕ ВТ_Поступило КАК Поступило
		ПО …
```

Сравните с вложенными запросами: та же предварительная группировка, но шаги стоят друг за другом, каждый со своим именем. Читать такой текст можно сверху вниз, как рассказ: сначала посчитали заказанное, потом поступившее, потом сопоставили.

## Выполнить и ВыполнитьПакет

У пакетного запроса два способа получить результат.

- `Выполнить()` возвращает результат **последнего** запроса пакета. Обычно только он и нужен.
- `ВыполнитьПакет()` возвращает **массив** результатов всех запросов пакета по порядку. Результат запроса с `ПОМЕСТИТЬ` — таблица из одной строки с полем `Количество`: сколько строк попало во временную таблицу.

`ВыполнитьПакет` — главный инструмент отладки. Если итог неверен, можно посмотреть, сколько строк попало в каждую временную таблицу, и сразу увидеть, на каком шаге данные потерялись.

## Менеджер временных таблиц

Чтобы временная таблица пережила один запрос и пригодилась в следующем, нужен общий **менеджер временных таблиц**:

```bsl
МенеджерВТ = Новый МенеджерВременныхТаблиц;

Запрос1 = Новый Запрос;
Запрос1.МенеджерВременныхТаблиц = МенеджерВТ;
// Текст с ПОМЕСТИТЬ ВТ_Исполнение …
Запрос1.Выполнить();

Запрос2 = Новый Запрос;
Запрос2.МенеджерВременныхТаблиц = МенеджерВТ;
// Текст, который читает ВТ_Исполнение …
```

Пока переменная `МенеджерВТ` существует, существуют и её таблицы. Это позволяет посчитать тяжёлую часть один раз, а затем построить на ней несколько разных ответов, между которыми ещё и выполняется код на встроенном языке.

Внутри одного пакета менеджер не нужен: все запросы пакета и так видят таблицы друг друга. Если запросу менеджер не назначен, платформа создаёт свой и уничтожает его вместе с таблицами после выполнения.

## Уборка и индексы

Запрос `УНИЧТОЖИТЬ ВТ_Заказано` удаляет временную таблицу раньше, чем закончится жизнь менеджера. Это вежливость по отношению к памяти сервера в длинных пакетах, где промежуточные таблицы больше не нужны.

`ИНДЕКСИРОВАТЬ ПО Заявка, Материал` после `ПОМЕСТИТЬ` строит индекс временной таблицы по полям, по которым её потом соединяют. На больших объёмах это ускоряет соединение; на учебных данных разницы не видно, но в рабочих конфигурациях так пишут почти всегда.

## Таблица значений как источник

Источником временной таблицы может быть не только таблица базы, но и параметр — таблица значений из встроенного языка:

```bsl
ВЫБРАТЬ
	Т.Материал КАК Материал,
	Т.Количество КАК Количество
ПОМЕСТИТЬ ВТ_Строки
ИЗ
	&ТаблицаСтрок КАК Т
```

Так данные, которых ещё нет в базе — например, строки документа, открытого в форме и не записанного, — превращаются во временную таблицу и соединяются с таблицами базы. Одно условие: у колонок переданной таблицы значений должны быть заданы типы, иначе платформа не поймёт, что в них лежит.

## Что важно запомнить

1. `ПОМЕСТИТЬ` сохраняет результат запроса во временную таблицу, которой можно пользоваться в следующих запросах.
2. Пакетный запрос — несколько запросов через `;`; каждый видит временные таблицы предыдущих.
3. `Выполнить()` возвращает результат последнего запроса пакета, `ВыполнитьПакет()` — массив результатов всех.
4. `МенеджерВременныхТаблиц` сохраняет таблицы между разными запросами одного сеанса.
5. Временные таблицы делают многошаговый расчёт читаемым сверху вниз и проверяемым по шагам; поэтому их предпочитают вложенным запросам в `ИЗ`.
