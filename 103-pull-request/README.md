# Занятие 103. Pull request, слияние и выпуск версии

## Цель

Научиться предлагать готовую задачу к слиянию так, чтобы её было легко проверить, сливать её в `main` и выпускать из `main` версию конфигурации для рабочей базы. Разобраться, что пишут в описании pull request, чем отличаются диапазоны `main..ветка` и `main...ветка`, зачем свойство конфигурации **Версия**, тег и список изменений.

## Результат занятия

В конспекте появится описание pull request задачи «Завершённые объекты». Ветка `feature/closed-sites` слита в `main` коммитом слияния и удалена. Конфигурация получит версию `1.1.0`, в репозитории появятся теги `v1.0.0` и `v1.1.0`, а рядом с репозиторием — поставочный файл `construction-erp-1.1.0.cf`. Копия рабочей базы, восстановленная из `.dt` занятия 100, обновится этим файлом и покажет в окне «О программе» версию `1.1.0`. Если у вас есть учётная запись GitHub, тот же pull request будет открыт там и сам отметится как слитый.

## Маршрут

1. Прочитайте [теорию](theory.md) — около 30 минут.
2. Выполните [практику](practice.md) — около 70 минут; дополнительная часть с GitHub — ещё около 20 минут.
3. Ответьте на контрольные вопросы в конце практики, не подглядывая в теорию.

## Ключевые термины

Pull request, merge request, описание pull request, ревьюер, одобрение, запрос изменений, диапазон `main..ветка`, диапазон `main...ветка`, слияние `--no-ff`, удаление ветки, свойство **Версия**, номер версии, тег, `git tag -a`, поставочный файл, список изменений версии.
