# Теория. Процедуры, функции и параметры

## Зачем выделять процедуру

На занятиях 11–14 весь код лежал в одном обработчике `Выполнить`. Пока там три строки, это терпимо. Но код растёт, и появляются три проблемы: один и тот же расчёт повторяется в нескольких местах, в длинном обработчике не видно замысла, а правку приходится вносить сразу в нескольких местах — и одно из них обязательно забудут.

Решение — вынести кусок работы в отдельную именованную часть модуля: расчёт живёт в одном месте, его имя объясняет смысл, правка делается однажды.

## Процедура

**Процедура** выполняет действие и не возвращает значения:

```bsl
&НаКлиенте
Процедура ВывестиПриветствие()
	Сообщить("Расчёт начат");
КонецПроцедуры
```

Вызывают её отдельным оператором: `ВывестиПриветствие();`. Директива `&НаКлиенте` пока ставится у всего нашего кода — почему именно так, разберём на занятии 21.

## Функция

**Функция** возвращает значение. Для этого внутри пишут `Возврат` и выражение:

```bsl
&НаКлиенте
Функция РассчитатьСумму(Количество, Цена)
	Возврат Количество * Цена;
КонецФункции
```

`Возврат` немедленно заканчивает функцию: код после него не выполняется. Вызов функции — это выражение, его результат можно присвоить или подставить прямо в другое выражение:

```bsl
Сумма = РассчитатьСумму(20, 12.5);
Сообщить("Итого: " + Строка(РассчитатьСумму(20, 12.5)));
```

Отсюда простой признак при чтении чужого кода: если результат вызова куда-то девается — присваивается, складывается, передаётся дальше, — перед вами функция. Если вызов стоит отдельной строкой и заканчивается `;` — это процедура.

## Как выбрать

Правило одно: нужен **результат** для дальнейших расчётов — пишите функцию; нужно только **действие** (вывести сообщение, записать значение) — пишите процедуру.

## Параметры

**Параметры** — значения, которые процедура получает извне. Они перечисляются в скобках после имени, а при вызове подставляются **по порядку**:

```bsl
Сумма = РассчитатьСумму(20, 12.5);  // Количество = 20, Цена = 12.5
```

Поменяете аргументы местами — получите `РассчитатьСумму(12.5, 20)`. Платформа не возразит: она не знает, что значит «количество», и просто перемножит числа. Ошибку такого рода не находит ни синтаксический контроль, ни приложение.

Имена параметров принадлежат только самой процедуре. Снаружи переменная может называться `КоличествоМешков`, внутри параметр — `Количество`; это по-прежнему одно и то же значение, просто у него два имени в двух разных местах.

## Значение по умолчанию

Параметру можно задать значение, которое подставится, если при вызове его не указали:

```bsl
&НаКлиенте
Функция РассчитатьСуммуСНДС(Сумма, Ставка = 20)
	Возврат Сумма + Сумма * Ставка / 100;
КонецФункции
```

Теперь оба вызова допустимы:

```bsl
Сообщить(Строка(РассчитатьСуммуСНДС(1000, 10)));  // 1100
Сообщить(Строка(РассчитатьСуммуСНДС(1000)));       // 1200, ставка взята 20
```

Параметры со значением по умолчанию обязаны идти **последними**: иначе платформа не поняла бы, какому параметру соответствует пропуск.

## Знач и передача по ссылке

По умолчанию параметр передаётся **по ссылке**. Это значит, что присваивание параметру внутри процедуры меняет и ту переменную, которая была указана при вызове:

```bsl
&НаКлиенте
Процедура УвеличитьНаДесять(ТекущееЗначение)
	ТекущееЗначение = ТекущееЗначение + 10;
КонецПроцедуры
```

Вызов:

```bsl
Значение = 5;
УвеличитьНаДесять(Значение);
Сообщить(Строка(Значение));  // 15 — переменная снаружи изменилась
```

Ключевое слово `Знач` перед параметром делает его **копией**. Внутри процедуры копию можно менять как угодно, снаружи это ничего не затронет:

```bsl
&НаКлиенте
Процедура УвеличитьНаДесять(Знач ТекущееЗначение)
	ТекущееЗначение = ТекущееЗначение + 10;
КонецПроцедуры
```

Тот же вызов теперь выведет 5.

Передача по ссылке — способ вернуть из процедуры результат, когда функция не подходит. Но она же источник неприятных ошибок: процедура с невинным названием меняет переменную, и в месте вызова этого не видно. Отсюда привычка: если процедура не должна менять переданное значение, напишите `Знач` — читатель сразу увидит обещание ничего не портить.

## Экспорт — только упоминание

Ключевое слово `Экспорт` после списка параметров делает процедуру доступной из других модулей. Нам это пока не нужно: все наши процедуры лежат в одном модуле формы и видят друг друга и так. Общие модули и `Экспорт` разберём на занятии 21.

## Где живут процедуры

Все процедуры и функции занятия пишем в том же модуле формы, рядом с обработчиком `Выполнить`: выше или ниже него. Порядок объявления в модуле не важен — функцию можно вызвать из процедуры, которая написана раньше неё. Удобно держать обработчики команд в начале модуля, а вспомогательные расчёты — в конце.

Одно ограничение: процедуру нельзя написать внутри другой процедуры. Каждая начинается после `КонецПроцедуры` или `КонецФункции` предыдущей.

## Что важно запомнить

1. Процедура выполняет действие, функция возвращает значение через `Возврат`.
2. Нужен результат для расчёта — функция; нужно только действие — процедура.
3. Аргументы подставляются по порядку; имена параметров внутри процедуры свои и не связаны с именами снаружи.
4. Параметры со значением по умолчанию идут последними и позволяют вызывать процедуру короче.
5. По умолчанию параметр передаётся по ссылке, и присваивание внутри меняет переменную снаружи; `Знач` делает параметр копией.
6. Процедуры нельзя вкладывать друг в друга, но порядок их объявления в модуле не важен.
