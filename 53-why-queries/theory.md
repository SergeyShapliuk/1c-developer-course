# Теория. Зачем нужны запросы

## Какую задачу мы решаем

К концу этапа 4 учёт материалов работает: заявки фиксируют потребность, поступления и передачи проводятся, регистр `ОстаткиМатериалов` хранит движения. Но на любой вопрос о данных мы отвечаем руками.

Снабженец спрашивает: какие материалы и в каком количестве заказаны для «ЖК Северный»? Чтобы ответить, нужно открыть каждую заявку, посмотреть объект строительства и выписать строки. Кладовщик спрашивает, сколько цемента на складе, — и мы ставим отбор в форме списка регистра и складываем приход с расходом в уме, как на занятии 51.

Программа должна получать такие ответы сама. Для этого у платформы есть отдельный механизм — **запрос**.

## Чтение объектами и чтение запросом

Читать данные из кода мы уже умеем. На занятии 19 мы перебирали товары выборкой менеджера, на занятии 20 получали объект по ссылке и читали его реквизиты. Этот способ называют **объектным чтением**: из базы достаётся объект целиком, а дальше код сам решает, что из него взять.

Для одного элемента это удобно. Для вопроса «что заказано для объекта» — нет. Код пришлось бы писать так: перебрать все заявки, у каждой проверить объект строительства, у подходящих пройти строки табличной части и сложить количества по материалам. Каждое обращение к реквизиту — отдельное чтение из базы, и работа, которую умеет делать сервер базы данных, выполняется в цикле на встроенном языке.

**Запрос** устроен наоборот. Мы описываем, **какие данные нужны**, а не **как их собрать**, и отдаём описание платформе. Платформа сама решает, какие таблицы прочитать, как отобрать строки и сложить числа, и возвращает готовую таблицу с ответом.

| Что сравниваем | Объектное чтение | Запрос |
| --- | --- | --- |
| Что описывает код | порядок действий: открыть, проверить, сложить | нужный результат: какие поля, откуда, при каком условии |
| Кто выполняет работу | цикл на встроенном языке | платформа и сервер базы данных |
| Сколько обращений к базе | по одному на объект и реквизит | одно на весь запрос |
| Может ли изменить данные | да: объект можно записать | нет: запрос только читает |

Последняя строка важна. **Запрос только читает данные.** Создать элемент, изменить реквизит или записать движение запросом нельзя — для этого остаются объекты, менеджеры и наборы записей из этапов 2–4. Запрос — инструмент для вопросов, а не для изменений.

## Язык запросов

Описание нужных данных пишется на **языке запросов**. Это отдельный язык со своими ключевыми словами, хотя похож на встроенный и тоже бывает русским и английским. Простейший запрос выглядит так:

```bsl
ВЫБРАТЬ
	Товары.Наименование,
	Товары.ЕдиницаИзмерения
ИЗ
	Справочник.Товары КАК Товары
```

Читается он почти дословно: выбрать наименование и единицу измерения из справочника «Товары». Слово `ВЫБРАТЬ` открывает список полей, слово `ИЗ` — источник данных. Подробно текст запроса и его части разберёт занятие 54.

Обратите внимание на имя источника: `Справочник.Товары`, в единственном числе. Это не менеджер `Справочники.Товары` из занятия 19, а **таблица базы данных**, в которой платформа хранит элементы справочника. Так же в запросе называются и другие таблицы: `Документ.ЗаявкаНаМатериалы`, `Документ.ПоступлениеМатериалов`, `РегистрНакопления.ОстаткиМатериалов`.

## Объект «Запрос» во встроенном языке

Текст на языке запросов сам по себе ничего не делает. Его нужно передать платформе через объект встроенного языка `Запрос`:

```bsl
Запрос = Новый Запрос;
Запрос.Текст = "ВЫБРАТЬ Товары.Наименование ИЗ Справочник.Товары КАК Товары";
Результат = Запрос.Выполнить();
Выборка = Результат.Выбрать();
Пока Выборка.Следующий() Цикл
	Сообщить(Выборка.Наименование);
КонецЦикла;
```

Разберём цепочку по шагам.

1. `Новый Запрос` создаёт объект запроса.
2. Свойство `Текст` получает текст на языке запросов в виде обычной строки встроенного языка.
3. Метод `Выполнить()` отправляет запрос платформе и возвращает **результат запроса** — готовую таблицу с ответом.
4. Метод `Выбрать()` превращает результат в **выборку** — курсор, который проходит по строкам результата по одной.
5. `Следующий()` переводит выборку на очередную строку и возвращает `Ложь`, когда строки кончились. К полям текущей строки обращаются через точку: `Выборка.Наименование`.

Цикл `Пока … Следующий()` вам уже знаком: так же устроена выборка менеджера справочника на занятии 19. Разница в том, что теперь в выборке лежат не объекты, а строки готового ответа, и в них есть только те поля, которые перечислены после `ВЫБРАТЬ`.

## Где живёт запрос

Запрос обращается к базе данных, а база данных доступна только на сервере. Поэтому **объект `Запрос` существует только в серверном коде**. В процедуре с директивой `&НаКлиенте` его нет вовсе: синтаксический контроль сообщит, что такой тип не определён.

Отсюда первое архитектурное правило этапа: запрос пишут в процедуре `&НаСервере`, `&НаСервереБезКонтекста` или в серверном общем модуле, а клиентский код только вызывает её. Это то же разделение клиента и сервера, что на занятии 22, и запрос его не отменяет, а подчёркивает.

На занятиях 53–63 мы будем писать запросы в серверных процедурах формы обработки `УчебнаяКонсоль` и выводить ответ сообщениями. Начиная с занятия 64, запросы переедут туда, где им место в рабочей конфигурации: в формы и модули документов.

## Что важно запомнить

1. Объектное чтение описывает порядок действий, запрос — нужный результат; работу по отбору и сложению делает платформа.
2. Запрос только читает данные и не может их изменить.
3. Текст запроса пишется на языке запросов; источники в нём — таблицы базы: `Справочник.Товары`, а не менеджер `Справочники.Товары`.
4. Цепочка выполнения: `Новый Запрос` → `Текст` → `Выполнить()` → `Выбрать()` → цикл по `Следующий()`.
5. Запрос выполняется только на сервере; клиентский код вызывает серверную процедуру с запросом.
