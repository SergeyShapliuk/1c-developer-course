# Теория. Поля и ресурсы схемы

## Какую задачу мы решаем

Кладовщик открыл отчёт «Остатки на складах» из занятия 69 и задал два вопроса, на которые отчёт не ответил.

Первый: «Сколько всего материалов лежит на складах?» Строки есть, а итога под ними нет — складывать приходится на калькуляторе.

Второй: «Сто — это мешки или тонны?» Единица измерения хранится в справочнике `Товары`, а в отчёте её нет: запрос её не выбирал.

Оба вопроса решаются без нового кода — нужно понять, как схема компоновки видит данные. Для этого разберём две её части: **поля набора данных** и **ресурсы**.

## Поле набора данных

Каждое поле результата запроса становится **полем набора данных**. На вкладке **Наборы данных** они перечислены в таблице над текстом запроса. У поля три главных свойства.

| Свойство | Что значит | Пример |
| --- | --- | --- |
| **Поле** | имя поля в запросе — псевдоним после `КАК` | `Остаток` |
| **Путь к данным** | имя, по которому поле знает вся остальная схема: настройки, ресурсы, оформление | `Остаток` |
| **Заголовок** | текст, который пользователь увидит в шапке колонки и в настройках | «Остаток на складе» |

При автозаполнении путь к данным совпадает с именем поля, а заголовок платформа строит из имени. Менять путь к данным без нужды не стоит: на него ссылаются все остальные части схемы. Заголовок, наоборот, меняют свободно — это текст для человека.

Изменить заголовок в схеме лучше, чем подбирать «красивый» псевдоним в запросе. Псевдоним — имя для программы, он не может содержать пробелы и должен оставаться стабильным. Заголовок — подпись для пользователя, и её можно поправить в любой момент, ничего не сломав.

## Доступные поля и поля через точку

Всё, что схема может показать пользователю, называется **доступными полями**. В них входят поля набора данных — и не только.

Если поле имеет ссылочный тип, например `Материал` типа `СправочникСсылка.Товары`, в доступных полях его можно раскрыть: появятся реквизиты элемента справочника — `Наименование`, `Код`, `ЕдиницаИзмерения`. Это то же обращение через точку, что и в запросе на занятии 57, только пишет его не разработчик в тексте запроса, а система компоновки: если пользователь выбрал поле `Материал.ЕдиницаИзмерения`, она сама дополнит запрос перед выполнением.

Отсюда практическое правило: **в запросе набора данных выбирают ссылки, а не все реквизиты подряд**. Реквизиты связанных объектов отчёт получит через точку, когда они кому-то понадобятся, и не будет тянуть их из базы, когда не нужны.

Это и есть ответ на вопрос занятия 43: единица измерения не хранится в регистре, она живёт в справочнике `Товары`, а рядом с количеством её показывает тот, кто выводит данные, — сегодня это отчёт.

## Ресурс

Поле набора данных выводится в детальной строке как есть. А что должно стоять в строке итога? Для `Склад` и `Материал` ответа нет: «итого по складам» — бессмысленная фраза. Для `Остаток` ответ есть: сумма остатков всех строк.

Поле, у которого есть правило подсчёта на уровне итогов, называется **ресурсом**. Ресурсы описывают на вкладке **Ресурсы** схемы: указывают поле и **выражение ресурса** — агрегатную функцию над этим полем.

| Выражение | Что даёт в строке итога |
| --- | --- |
| `Сумма(Остаток)` | сумму значений по всем строкам группы |
| `Количество(Материал)` | число строк группы |
| `Максимум(Остаток)`, `Минимум(Остаток)` | наибольшее, наименьшее значение |
| `Среднее(Остаток)` | среднее значение |

Функции те же, что агрегатные функции запроса на занятии 59, но считает их система компоновки — по каждой группе отчёта и по отчёту в целом.

Если у отчёта есть хотя бы один ресурс, система компоновки выводит **общий итог**: строку итога по всему отчёту. Поля, не являющиеся ресурсами, в ней пусты.

## Ресурс и итоги запроса

На занятии 61 итог по всем строкам давала секция `ИТОГИ … ПО ОБЩИЕ`, а агрегатная функция в ней писалась так же: `СУММА(Потребность)`. Ресурс схемы — тот же приём, перенесённый из запроса в схему.

Разница в том, кто решает, по каким полям считать итоги. В запросе контрольные точки перечислял разработчик, и изменить их можно было только правкой текста. В схеме разработчик объявляет только **что** суммировать, а **по каким группам** — решают настройки, которые может менять пользователь. Поэтому в наборе данных схемы секцию `ИТОГИ` не пишут: её работу делают ресурсы.

## Поле или ресурс: граница

Поля отчёта делятся на две роли.

- **Группировочные поля** — те, по которым строки собирают в группы: склад, материал, позже — объект строительства и период. Ресурсом они не бывают: суммировать склады нельзя.
- **Ресурсы** — то, что считают внутри групп: остаток, количество, позже — стоимость. Группировать по ресурсу система компоновки не даст: группа «все строки с остатком 100» не имеет смысла.

Как и при проектировании регистра на занятии 43, вопрос один: имеет ли смысл складывать это значение? Если да — это кандидат в ресурсы. Если по значению собирают строки — это поле группировки.

## Где живёт логика

Заголовки, единица измерения и итог отчёта не требуют ни строчки кода. Заголовки — свойство поля схемы, единица — доступное поле через точку, итог — ресурс. Тот же результат можно получить кодом: соединить в запросе справочник, посчитать сумму в цикле и вывести её последней строкой. Но тогда пользователь не сможет ни убрать единицу измерения, ни получить итог по другому складу без разработчика.

## Что важно запомнить

1. Поля набора данных берутся из результата запроса; путь к данным — имя поля для схемы, заголовок — подпись для пользователя.
2. Через точку в доступных полях отчёт показывает реквизиты связанных объектов, не меняя текст запроса; в запросе выбирают ссылки.
3. Ресурс — поле с выражением подсчёта для строк итога: `Сумма`, `Количество`, `Максимум`, `Минимум`, `Среднее`.
4. Общий итог появляется в отчёте, когда в схеме есть хотя бы один ресурс.
5. Ресурс схемы заменяет секцию `ИТОГИ` запроса: разработчик объявляет, что считать, а по каким группам — решают настройки.
6. По ресурсу не группируют; поле, которое имеет смысл складывать, — кандидат в ресурсы, поле, по которому собирают строки, — в группировки.
