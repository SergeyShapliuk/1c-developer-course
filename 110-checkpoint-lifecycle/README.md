# Занятие 110. Контрольная точка: доработка от задачи до приёмки

## Цель

Это **контрольная точка** этапа 9 и восьмая в курсе. Нового материала здесь нет: нужно самостоятельно провести исправление дефекта через весь жизненный цикл доработки — от отчёта об ошибке занятия 107 до новой версии в копии рабочей базы, — используя то, что изучено в занятиях 99–109, а затем принять свою работу по чек-листу.

## Результат занятия

Отмена проведения поступления, материал которого уже передан, больше не уводит остаток склада в минус: она отклоняется с понятным сообщением, и пометка такого поступления на удаление — тоже. В обработке `ТестыСнабжения` два новых теста, и все проверки пройдены. Исправление прошло ветку, pull request и самопроверку по чек-листу ревью. Конфигурация получила версию `1.2.0` с тегом, поставочным файлом и списком изменений, а копия рабочей базы `УСК_Рабочая` обновлена до неё. Плюс заполненный чек-лист с фактическими результатами.

## Маршрут

1. Прочитайте [теорию](theory.md) — около 20 минут. Она не про новые возможности, а про то, когда доработку можно считать готовой.
2. Выполните [практику](practice.md): сначала решите задачу сами, потом пройдите чек-лист.
3. **Раздел «Разбор и эталонный вариант» открывайте только после своей попытки.** Готовое решение, прочитанное заранее, не научит его находить: контрольная точка проверяет умение, а не память.

## Ключевые термины

Контрольная точка, критерии готовности доработки, карточка задачи, критерии приёмки, тест до исправления, `ОбработкаУдаленияПроведения`, ветка исправления, pull request, чек-лист ревью, регрессионный набор, версия, тег, поставочный файл, список изменений, приёмка.
