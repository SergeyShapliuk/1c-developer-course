# Теория. Вложенные запросы

## Какую задачу мы решаем

Снабженцу нужно два ответа, которые одним простым запросом не получить.

Первый: какие заявки висят без движения — по ним не пришло вообще ничего? Чтобы ответить, надо знать список заявок, по которым поступления **были**, и взять все остальные.

Второй остался от занятия 59. Группировка по строке заявки исправила размножение строк, но сломалась там, где материал записан в заявке двумя строками: каждая строка получала в пару все поступления, и поступившее считалось дважды. Правильный порядок действий такой: сначала сложить заказанное по заявке и материалу, отдельно — поступившее по заявке и материалу, и только потом соединить два готовых итога.

В обоих случаях один запрос должен опираться на результат другого. Это **вложенный запрос**.

## Что такое вложенный запрос

Вложенный запрос — полноценный запрос `ВЫБРАТЬ … ИЗ …`, записанный в скобках внутри другого запроса. Платформа выполняет его как часть внешнего и использует результат там, где он стоит. Встречаются два места.

## Вложенный запрос в условии

Операция `В` с занятия 55 принимала список из параметра. Вместо параметра в скобках можно написать запрос, который этот список вернёт:

```bsl
ВЫБРАТЬ
	Заявки.Ссылка КАК Заявка
ИЗ
	Документ.ЗаявкаНаМатериалы КАК Заявки
ГДЕ
	НЕ Заявки.Ссылка В
		(ВЫБРАТЬ
			Поступления.ДокументОснование
		ИЗ
			Документ.ПоступлениеМатериалов КАК Поступления
		ГДЕ
			Поступления.Проведен)
```

Внутренний запрос возвращает основания всех проведённых поступлений. Внешний оставляет заявки, которых в этом списке нет. Вложенный запрос в условии должен возвращать **одно поле** — с ним и сравнивается значение.

## Вложенный запрос в источнике

Вложенный запрос можно поставить в секцию `ИЗ` вместо таблицы. Тогда его результат становится временным источником, которому дают псевдоним, и с ним работают как с обычной таблицей: выбирают поля, соединяют, ставят условия.

```bsl
ИЗ
	(ВЫБРАТЬ
		ЗаявкаМатериалы.Ссылка КАК Заявка,
		ЗаявкаМатериалы.Материал КАК Материал,
		СУММА(ЗаявкаМатериалы.Количество) КАК Количество
	ИЗ
		Документ.ЗаявкаНаМатериалы.Материалы КАК ЗаявкаМатериалы
	СГРУППИРОВАТЬ ПО
		ЗаявкаМатериалы.Ссылка,
		ЗаявкаМатериалы.Материал) КАК Заказано
```

Внутри скобок строки заявок уже сложены по заявке и материалу: две строки цемента в одной заявке стали одной. Псевдоним `Заказано` даёт результату имя, и снаружи к его полям обращаются как `Заказано.Материал`, `Заказано.Количество`. Поля вложенного запроса доступны снаружи только под своими псевдонимами.

Так решается вторая задача. Делаем такой же вложенный запрос `Поступило` по строкам поступлений — с группировкой по `Ссылка.ДокументОснование` и материалу — и соединяем `Заказано` с `Поступило` левым соединением по заявке и материалу. С каждой стороны на пару «заявка — материал» приходится ровно одна строка, и размножаться нечему.

Этот приём называют **предварительной группировкой**: сначала свернуть каждую сторону до нужного ключа, затем соединять. Он нужен всякий раз, когда соединяются две таблицы, у которых на один ключ может приходиться несколько строк.

## Почему вложенные запросы трудно читать

Посмотрите на итоговый запрос исполнения заявок в практике. В нём три `ВЫБРАТЬ`, две группировки, соединение, и читать его приходится изнутри наружу: сначала понять, что делают скобки, потом — что делается с их результатом. Ошибку внутри скобок не видно снаружи: если вложенный запрос посчитал неверно, внешний честно соединит неверные числа.

Есть и практическая проблема. Проверить промежуточный результат — что именно вернул вложенный запрос — нельзя, не вырезав его в отдельный запрос. А если тот же промежуточный результат нужен дважды, его приходится писать дважды.

Поэтому опытные разработчики 1С используют вложенный запрос в условии `В` охотно — он короткий и понятный, а вложенные запросы в `ИЗ` стараются заменять **временными таблицами**. Они дают тот же результат, но по шагам, которые можно проверить по отдельности. Им посвящено занятие 63.

## Что важно запомнить

1. Вложенный запрос — запрос в скобках внутри другого запроса; его результат используется там, где он стоит.
2. В условии `В (ВЫБРАТЬ …)` вложенный запрос возвращает одно поле — список значений для сравнения.
3. В секции `ИЗ` вложенный запрос становится источником с псевдонимом; снаружи доступны только его поля под их псевдонимами.
4. Предварительная группировка — сложить каждую сторону до ключа соединения и только потом соединять; так исчезает размножение строк.
5. Вложенные запросы в `ИЗ` трудно читать и проверять по частям; для многошаговых расчётов удобнее временные таблицы.
