# Теория. Как принимают формы и печатные формы

## Зачем нужна контрольная точка этапа

Занятия 81–89 разбирали интерфейс по одному механизму: видимость и доступность, параметры выбора, вопросы пользователю, динамический список, условное оформление, элементы из кода, макет, команда печати, печать пачки документов. Каждый раз было понятно, какой механизм применять: его только что объяснили.

В рабочей задаче подсказки нет. Кладовщик говорит: «в журнале поступлений ничего не понятно, а приходный ордер я пишу от руки». Разработчик сам решает, что из этого — колонка динамического списка, что — условное оформление, что — поведение формы, что — печатная форма, где живёт каждая часть и нужен ли код. Контрольная точка проверяет именно это.

## Интерфейс принимают по действиям пользователя

Ошибка в форме редко вызывает сообщение. Колонка показывает не ту сумму, выделение срабатывает не на тех строках, лист печатается, но вторая накладная начинается посреди первой страницы. Поэтому интерфейс, как запрос на занятии 68 и отчёт на занятии 80, принимают по **проверяемым утверждениям** — только здесь это утверждения о том, что пользователь видит и что может сделать.

| Плохо | Хорошо |
| --- | --- |
| «Сделал форму списка» | «Сумма поступления в журнале совпадает с суммой строк документа, у документа без строк — ноль» |
| «Добавил условное оформление» | «Выделены только поступления без заявки, и выделение не снять из настроек списка» |
| «Сделал печать» | «Три выделенных поступления печатаются одним окном, каждое с новой страницы, непроведённое пропущено с сообщением» |
| «Скрыл поле основания» | «У поступления без заявки поля основания нет, у поступления по заявке оно видно и открывает заявку» |

## Сверка с документом

У интерфейса есть надёжный эталон — сам документ. Каждое число журнала и каждая строка печатной формы должны совпадать с тем, что видно в форме документа. Сверяют не «похоже», а по каждому полю: номер, дата, поставщик, склад, основание, каждая строка материалов, единица измерения, итог.

Сверяют и отсутствие лишнего. Непроведённое поступление не должно напечататься. Поступление по заявке не должно выделяться как «без заявки». Помеченное на удаление — должно остаться в журнале со своим значком.

## Типичные ошибки интерфейса — и где их ловить

**Колонка, размножившая документы.** Строки табличной части присоединены к документам без предварительной группировки, и поступление из трёх строк занимает в журнале три строки (занятие 84). Ловится документом с несколькими строками.

**Пустота вместо нуля.** У поступления без строк в колонке суммы пусто, потому что нет `ЕСТЬNULL` (занятие 84). Ловится только что созданным пустым поступлением.

**Правило оформления в настройках списка.** Выделение сделано в настройках динамического списка, и кладовщик снимает его командой **Настроить список** (занятие 85). Ловится попыткой снять выделение из режима пользователя.

**Видимость, настроенная один раз.** Поле основания скрыто в палитре и не показывается даже у поступления по заявке, или видимость считается только для новых документов (занятие 81). Ловится открытием обоих видов поступлений.

**Чтение через ссылку в цикле.** Печать пачки читает каждое поступление через ссылку: работает, но на сотне документов — сотни обращений к базе (занятие 89). Ловится чтением кода: в функции печати нет обращений к ссылке внутри цикла.

**Накладные слиплись.** Нет разрыва страниц, и второй ордер начинается на первой странице (занятие 89). Ловится предварительным просмотром.

**Печать черновика.** Непроведённое поступление печатается как настоящее (занятие 89). Ловится выделением непроведённого документа.

**Печать в модуле формы.** Функция сборки листа лежит в модуле формы документа, и из журнала её не вызвать (занятия 87–88). Ловится попыткой напечатать из журнала.

## Где лежит логика — тоже предмет приёмки

Работающий интерфейс в неправильной архитектуре принимать нельзя: следующая форма, которой понадобится то же самое, получит копию кода.

- **Данные для журнала** — в запросе динамического списка, а не в коде формы.
- **Обязательное выделение** — в условном оформлении формы, а не в настройках списка и не в коде.
- **Поведение формы** — одной процедурой модуля формы, вызванной при создании формы.
- **Оформление листа** — в макете; **сборка листа** — в функции модуля менеджера; **показ** — в модуле команды объекта.
- **Правило «печатать только проведённые»** — в запросе печати.

## На какие занятия опирается задача

- Занятие 81 — видимость элементов по данным, процедура настройки формы.
- Занятие 82 — параметры выбора поставщика.
- Занятие 84 — форма списка, динамический список, произвольный запрос.
- Занятие 85 — условное оформление формы.
- Занятие 87 — макет, области, параметры, модуль менеджера.
- Занятие 88 — команда объекта, модуль команды.

- Занятия 36–37 и 49 — поступление, его основание и проведение.

## Что важно запомнить

1. Контрольная точка проверяет умение разложить требование пользователя по механизмам и местам, поэтому готового решения в постановке нет.
2. Интерфейс принимают по проверяемым утверждениям о том, что пользователь видит и может сделать.
3. Эталон для сверки — сам документ: каждое число и каждая строка журнала и листа совпадают с формой документа.
4. У каждой типичной ошибки есть документ или действие, которое её проявляет: несколько строк, пустой документ, команда **Настроить список**, оба вида поступлений, предварительный просмотр, черновик, печать из журнала.
5. Архитектура — часть приёмки: данные в запросе списка, выделение в условном оформлении формы, поведение одной процедурой формы, печать в макете, модуле менеджера и модуле команды.
