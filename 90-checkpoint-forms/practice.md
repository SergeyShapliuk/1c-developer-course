# Практика. Интерфейс поступления материалов

## Самостоятельная задача

Готового решения в этом разделе нет. Прочитайте постановку, решите задачу сами и только потом открывайте разбор.

Кладовщик принимает материалы от поставщиков и оформляет документы «Поступление материалов». У него три жалобы. В журнале поступлений видно только дату и номер, и чтобы понять, от кого и по какой заявке пришёл груз, нужно открывать документ. Снабженец не замечает поступлений без заявки — незапланированных закупок, о которых он должен знать. Приходный ордер, который подписывают кладовщик и водитель поставщика, пишут от руки.

Работайте в учебной конфигурации **«Управление строительной компанией с логистикой»**. Документ `ПоступлениеМатериалов`, его ввод на основании заявки, проведение и параметры выбора поставщика уже есть с занятий 36–37, 49 и 82 — их не меняйте.

Задача разбита на пять этапов. **Доводите этап до его проверки и только потом переходите к следующему.**

### Этап 1. Данные проверки

1. Найдите в журнале поступлений два проведённых поступления по рабочей заявке «ЖК Южный» из занятия 68 и проведённое поступление цемента `50` на «Склад на объекте» без заявки.
2. Выпишите в конспект по каждому: номер, дату, поставщика, склад, основание, строки материалов, сумму строк.

**Проверка этапа:** данные трёх поступлений записаны до того, как изменена хоть одна форма.

### Этап 2. Журнал поступлений

Журнал показывает по каждому поступлению: дату, номер, поставщика, склад, заявку-основание, объект строительства этой заявки, число строк материалов и сумму. Поступление без строк показывает нули. Помеченные на удаление и проведённые поступления отмечены, как в стандартном журнале. Открытие, создание и копирование документов работают.

**Проверка этапа:** числа журнала совпадают с конспектом этапа 1.

### Этап 3. Выделение и форма

1. В журнале поступления без заявки выделены так, что снабженец замечает их сразу. Пользователь не может снять это выделение.
2. В форме поступления поле «Заявка-основание» видно только у поступлений по заявке.

**Проверка этапа:** выделены ровно поступления без заявки; поле основания видно у поступления по заявке и скрыто у поступления без неё.

### Этап 4. Приходный ордер

Команда **Приходный ордер** есть и в форме поступления, и в журнале. Она печатает выделенные поступления одним окном, каждое с новой страницы. На ордере: номер и дата, поставщик, склад, основание — представление заявки или слова «без заявки», таблица «№ — Материал — Ед. — Количество — Цена — Сумма», итог, места для подписей «Принял» с ответственным и «Сдал». Непроведённые поступления не печатаются, и пользователь узнаёт, сколько пропущено; если проведённых среди выделенных нет — предупреждение без пустого окна. Несохранённое поступление не печатается.

**Проверка этапа:** ордера трёх поступлений совпадают с конспектом этапа 1.

### Требования

1. Колонки журнала — из произвольного запроса динамического списка; ни одной строки кода в форме списка.
2. Выделение поступлений без заявки — в условном оформлении формы списка.
3. Видимость поля основания — в процедуре модуля формы поступления, вызванной из `ПриСозданииНаСервере`.
4. Оформление ордера — в макете документа; сборка листа — в экспортной функции модуля менеджера одним пакетным запросом, без чтения через ссылку в цикле; показ — в модуле команды объекта с множественным параметром.
5. Правило «печатать только проведённые» — в запросе печати.

## Критерии готовности

Каждое утверждение проверяется, не заглядывая в конфигуратор.

1. Журнал показывает восемь колонок; число позиций и сумма каждого поступления совпадают с его строками, у поступления без строк — нули, одна строка журнала на документ.
2. Объект строительства в журнале — объект заявки-основания; у поступления без заявки он пуст.
3. Выделены только поступления без заявки, и выделение нельзя снять в настройках списка.
4. Поле «Заявка-основание» видно только у поступлений по заявке.
5. Ордера выделенных проведённых поступлений печатаются одним окном, каждый с новой страницы, данные совпадают с документами.
6. Непроведённые поступления не печатаются; пользователь получает сообщение о пропущенных или предупреждение, если печатать нечего.
7. Несохранённое поступление не печатается.
8. Команда **Приходный ордер** есть в форме и в журнале, хотя в формы её не перетаскивали.

2. Почему параметры выбора поставщика заданы у реквизита документа, и почему они не заменяют проверку в `ПередЗаписью`?

7. Почему лист собирают в модуле менеджера, а показывают в модуле команды, и почему для пачки документов данные берут одним запросом?

## Типичные ошибки

**1. Поступление размножилось в журнале.** Симптом: поступление из двух строк занимает две строки журнала, сумма в каждой — сумма одной строки. Причина: табличная часть присоединена к документам без вложенного запроса с группировкой по ссылке. Исправление: сгруппировать строки по `Ссылка` во вложенном запросе и присоединить левым соединением (занятие 84).

**2. Пусто вместо нуля.** Симптом: у поступления без строк колонки «Позиций» и «Сумма» пусты. Причина: нет `ЕСТЬNULL` вокруг полей вложенного запроса. Исправление: `ЕСТЬNULL(…, 0)` (занятия 57 и 84).

**3. Журнал не открывает документ.** Симптом: двойной щелчок по строке ничего не делает или выдаёт ошибку. Причина: в запросе списка нет поля `Ссылка` или не задана основная таблица. Исправление: основная таблица — `Документ.ПоступлениеМатериалов`, `Ссылка` — первое поле запроса (занятие 84).

**4. Выделение снимается пользователем.** Симптом: кладовщик убрал выделение командой **Настроить список**. Причина: правило создано в настройках динамического списка. Исправление: перенести правило в условное оформление формы (занятие 85).

**5. Поле основания не появляется.** Симптом: у поступления, созданного на основании заявки, нет поля «Заявка-основание». Причина: видимость выключена в палитре или вычисляется только для новых документов. Исправление: процедура видимости, вызванная из `ПриСозданииНаСервере` для любого документа (занятие 81).

**6. Ордера на одной странице.** Симптом: второй ордер начинается под подписями первого. Причина: нет разрыва страниц. Исправление: `ВывестиГоризонтальныйРазделительСтраниц` перед каждым ордером, кроме первого (занятие 89).

**7. Напечатан черновик.** Симптом: непроведённое поступление напечаталось. Причина: в запросе печати нет условия `Проведен`. Исправление: условие в обоих запросах пакета (занятие 89).

**8. Чтение через ссылку в цикле.** Симптом: печать работает, но в функции в цикле по поступлениям стоят обращения вида `Поступление.Материалы` или `Строка.Материал.ЕдиницаИзмерения`. Причина: подход занятия 87 перенесён на пачку документов. Исправление: пакетный запрос шапок и строк, раскладка строк методом `НайтиСтроки` (занятие 89).

**9. Печать только из формы.** Симптом: в журнале нет команды печати. Причина: печать сделана командой формы документа. Исправление: команда объекта с параметром `ДокументСсылка.ПоступлениеМатериалов` в группе «Командная панель формы. Важное» (занятие 88).

### Форма списка поступлений

Форма `ФормаСписка` документа `ПоступлениеМатериалов` назначена основной формой списка. Динамический список: основная таблица `Документ.ПоступлениеМатериалов`, произвольный запрос:

```bsl
	Поступление.Дата КАК Дата,
	Поступление.Номер КАК Номер,

	Поступление.Склад КАК Склад,
	Поступление.ДокументОснование КАК ДокументОснование,
	Поступление.ДокументОснование.ОбъектСтроительства КАК ОбъектСтроительства,
```

Колонки таблицы: `Дата`, `Номер`, `Поставщик`, `Склад`, `ДокументОснование` с заголовком «Заявка-основание», `ОбъектСтроительства`, `КоличествоСтрок` с заголовком «Позиций», `СуммаПоступления` с заголовком «Сумма».

Почему сделано именно так.

Это запрос журнала заявок занятия 84 для другого документа. `ПометкаУдаления` и `Проведен` выбраны, чтобы журнал показывал значки, как стандартный. Объект строительства получен через точку от основания: у поступления без заявки основание пустое, и объект тоже пуст — так и должно быть.

### Условное оформление журнала

Одно правило в условном оформлении формы списка: **Цвет фона** — светло-жёлтый; условие — `Список.ДокументОснование` **Не заполнено**; оформляемые поля — таблица `Список`.

Почему сделано именно так.

Поступление без заявки — не ошибка, а событие, о котором снабженец должен знать. Поэтому фон, а не красный текст: строка заметна, но не кричит «тревога». Правило в форме, а не в настройках списка, потому что оно обязательное (занятие 85).

### Форма поступления

В модуле формы документа `ПоступлениеМатериалов`:

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)

	УстановитьВидимостьЭлементов();

КонецПроцедуры

// Настраивает видимость элементов по данным поступления.
&НаСервере
Процедура УстановитьВидимостьЭлементов()

	Элементы.ДокументОснование.Видимость = ЗначениеЗаполнено(Объект.ДокументОснование);

КонецПроцедуры
```

Почему сделано именно так.

Основание заполняется только при вводе на основании (занятия 36–37) и после этого не меняется: поле закрыто флагом **ТолькоПросмотр**. Поэтому видимость достаточно вычислить при создании формы. `ПриСозданииНаСервере` выполняется и для нового документа, и для открытого из журнала, а при вводе на основании — после того как `ОбработкаЗаполнения` уже заполнила основание.

Одна строка вынесена в отдельную процедуру по правилу занятия 81: следующее правило поведения формы встанет рядом, а не в обработчик события.

Поле скрыто, а не закрыто: у поступления без заявки в нём нечего читать, а пустое поле «Заявка-основание» наводит на мысль, что основание забыли указать.

### Макет приходного ордера

Макет `ПФ_ПриходныйОрдер` документа `ПоступлениеМатериалов`, колонки «№», «Материал», «Ед.», «Количество», «Цена», «Сумма».

| Область | Содержимое |
| --- | --- |
| `Шапка` | шаблон `Приходный ордер № [Номер] от [Дата]`; строки «Поставщик:» — параметр `Поставщик`, «Склад:» — `Склад`, «Основание:» — `Основание` |
| `ШапкаТаблицы` | тексты шести колонок, рамки |

| `Подвал` | «Итого:» — параметр `Итого` с форматом `ЧДЦ=2`; шаблон `Принял: ______________ [Ответственный]        Сдал: ______________` |

```bsl
		|	Документ.ПоступлениеМатериалов.Материалы КАК Строки
		|ГДЕ
		|	Строки.Ссылка В (&Поступления)
		|	И Строки.Ссылка.Проведен
		|УПОРЯДОЧИТЬ ПО
		|	НомерСтроки";
	Запрос.УстановитьПараметр("Поступления", Поступления);

	Результаты = Запрос.ВыполнитьПакет();
	Шапки = Результаты[0].Выгрузить();
	ТаблицаСтрок = Результаты[1].Выгрузить();

	Пропущено = Поступления.Количество() - Шапки.Количество();
	Если Пропущено > 0 Тогда
		Сообщить("Непроведённые поступления не печатаются, пропущено: " + Пропущено);
	КонецЕсли;

	Макет = ПолучитьМакет("ПФ_ПриходныйОрдер");
	ТабДок = Новый ТабличныйДокумент;

	Для Каждого Шапка Из Шапки Цикл

		Если ТабДок.ВысотаТаблицы > 0 Тогда
			ТабДок.ВывестиГоризонтальныйРазделительСтраниц();
		КонецЕсли;

		Область = Макет.ПолучитьОбласть("Шапка");
		Область.Параметры.Заполнить(Шапка);
		Область.Параметры.Дата = Формат(Шапка.Дата, "ДЛФ=D");
		Если Шапка.Основание = "" Тогда
			Область.Параметры.Основание = "без заявки";
		КонецЕсли;
		ТабДок.Вывести(Область);

		ТабДок.Вывести(Макет.ПолучитьОбласть("ШапкаТаблицы"));

		ОбластьСтроки = Макет.ПолучитьОбласть("Строка");
		СтрокиПоступления = ТаблицаСтрок.НайтиСтроки(Новый Структура("Ссылка", Шапка.Ссылка));
		Итого = 0;
		Для Каждого СтрокаМатериала Из СтрокиПоступления Цикл
			ОбластьСтроки.Параметры.Заполнить(СтрокаМатериала);
			ТабДок.Вывести(ОбластьСтроки);
			Итого = Итого + СтрокаМатериала.Сумма;
		КонецЦикла;

		Область = Макет.ПолучитьОбласть("Подвал");
		Область.Параметры.Итого = Итого;
		Область.Параметры.Ответственный = Шапка.Ответственный;
		ТабДок.Вывести(Область);

	КонецЦикла;

	Возврат ТабДок;

КонецФункции
```

Почему сделано именно так.

Это функция `ПечатьНакладных` занятия 89 для другого документа. Основание выбрано в запросе функцией `ПРЕДСТАВЛЕНИЕ` (занятие 66): для печати нужен текст, а не ссылка. У поступления без заявки представление пустой ссылки — пустая строка, и код заменяет её словами «без заявки». Итог считается в цикле по строкам, которые уже получены запросом, — без обращения к базе.

### Команда объекта

Команда `ПечатьПриходногоОрдера` документа `ПоступлениеМатериалов`: заголовок «Приходный ордер», группа «Командная панель формы. Важное», тип параметра `ДокументСсылка.ПоступлениеМатериалов`, режим **Множественный**.

```bsl
&НаКлиенте
Процедура ОбработкаКоманды(ПараметрКоманды, ПараметрыВыполненияКоманды)

	Источник = ПараметрыВыполненияКоманды.Источник;
	Если Источник <> Неопределено И Источник.Модифицированность Тогда
		ПоказатьПредупреждение(Неопределено, "Запишите и проведите поступление перед печатью приходного ордера.");
		Возврат;

		Возврат;

	ТабДок.Показать("Приходные ордера");

КонецПроцедуры
```

Почему сделано именно так.

Команда тонкая, как на занятиях 88–89: какие документы печатать, решает платформа по выделенным строкам; что печатать, решает запрос модуля менеджера; клиент только проверяет несохранённые изменения источника и показывает результат.
