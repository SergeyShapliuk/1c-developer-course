# Теория. Параметры выбора

## Какую задачу мы решаем

На занятии 36 поступление материалов получило реквизит `Поставщик` с типом `СправочникСсылка.Клиенты`. Отдельного справочника поставщиков в проекте нет: все контрагенты живут в справочнике `Клиенты`, а кто из них кто, говорит реквизит `ВидКлиента` — «Заказчик», «Поставщик» или «Подрядчик» (занятия 7 и 8).

Поэтому поле «Поставщик» предлагает всех: и поставщика цемента, и заказчика, для которого компания строит дом. Кладовщик ошибается на один щелчок, и в учёте появляется поступление цемента «от заказчика». Тогда же мы записали технический долг: ограничить выбор в поле. Механизм для этого называется **параметрами выбора**.

## Как поле выбирает значение

Когда пользователь нажимает кнопку выбора в поле ссылочного типа, платформа открывает **форму выбора** справочника — список элементов, из которого берут один. Когда пользователь начинает печатать наименование прямо в поле, платформа ищет совпадения сама и показывает выпадающий список — это **ввод по строке**.

Оба пути смотрят на одно и то же: какие элементы справочника вообще можно предложить. Параметры выбора отвечают именно на этот вопрос.

## Параметры выбора

**Параметры выбора** — список пар «имя — значение», которые платформа передаёт форме выбора и учитывает при вводе по строке. Самый частый параметр — отбор по реквизиту выбираемого объекта:

| Имя | Значение | Смысл |
| --- | --- | --- |
| `Отбор.ВидКлиента` | `Поставщик` | предлагать только клиентов, у которых вид — «Поставщик» |

Имя начинается с `Отбор.`, за точкой — имя реквизита справочника. Значение выбирают из допустимых значений этого реквизита: для перечисления — одно из его значений.

Отбор из параметров выбора пользователь в форме выбора не снимет: это условие разработчика, а не настройка списка. Поэтому заказчик в поле «Поставщик» не попадёт ни из формы выбора, ни при вводе по строке.

## У реквизита или у элемента формы

Свойство **Параметры выбора** есть в двух местах.

- **У реквизита объекта** — в палитре свойств реквизита `Поставщик` документа `ПоступлениеМатериалов`. Ограничение действует в любой форме, где этот реквизит редактируют: в своей форме документа, в автогенерируемой, в любой будущей.
- **У элемента формы** — в палитре свойств поля на форме. Ограничение действует только в этой форме.

Правило «поставщиком может быть только поставщик» — свойство модели данных, а не одного экрана. Его задают у реквизита. Параметры выбора элемента формы нужны, когда ограничение действительно касается одной формы: например, специальная форма приёмки, в которой выбирают только поставщиков одного региона.

## Связи параметров выбора

Иногда отбор зависит не от постоянного значения, а от другого поля той же формы: выбрать сотрудника только из отдела, указанного выше, или договор только выбранного контрагента. Для этого есть соседнее свойство — **Связи параметров выбора**: оно берёт значение отбора из другого реквизита. В учебном проекте такой зависимости пока нет. Достаточно знать, что механизм тот же, а значение отбора приходит не из конфигурации, а из данных формы.

## Выбор — не проверка

Параметры выбора ограничивают то, что **предлагают пользователю**. Они не проверяют данные.

- Код, который создаёт поступление и записывает в `Поставщик` любого клиента, параметров выбора не увидит: формы нет, выбора нет.
- Если вид клиента изменят уже после выбора, документ останется с прежним контрагентом.
- Поступления, записанные до сегодняшнего занятия, никто не перепроверит.

Гарантию даёт только проверка при записи. На занятии 33 мы разобрали, что `ОбработкаПроверкиЗаполнения` вызывается при интерактивной записи, а `ПередЗаписью` — при любой. Правило «поставщик должен быть поставщиком» должно работать и при записи из кода, поэтому его место — `ПередЗаписью` модуля объекта поступления.

Две части решения дополняют друг друга: параметры выбора не дают ошибиться в форме, проверка в модуле объекта не даёт записать ошибку никаким путём.

## Где живёт логика

| Что | Где | Почему |
| --- | --- | --- |
| Какие клиенты предлагаются в поле «Поставщик» | параметры выбора реквизита документа | действует во всех формах без кода |
| Ограничение выбора для одной особой формы | параметры выбора элемента этой формы | касается только этого экрана |
| Запрет записать поступление от непоставщика | `ПередЗаписью` модуля объекта | срабатывает при любой записи, с формы и из кода |

## Что важно запомнить

1. Параметры выбора задают, какие значения поле предлагает в форме выбора и при вводе по строке; отбор по реквизиту записывают как `Отбор.ИмяРеквизита`.
2. Пользователь не может снять отбор, заданный параметрами выбора.
3. Параметры выбора реквизита объекта действуют во всех формах, параметры элемента — только в одной; правило модели данных задают у реквизита.
4. Связи параметров выбора берут значение отбора из другого поля формы.
5. Параметры выбора ограничивают предложение, а не данные; гарантию даёт проверка в `ПередЗаписью` модуля объекта.
