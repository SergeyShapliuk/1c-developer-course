# Практика. Ищем, где остаток уходит в минус

## Перед началом

Работаем в тестовой базе `УСК_Тест` после занятия 106. Остаток доски обрезной на «Складе испытаний» — `50`: поступление `100`, передачи `45` и `5`. Флаг «Завершён» у «ЖК Пробного» снят. Если остаток другой, найдите причину по протоколу занятия 106 или восстановите `УСК_Тест` из `.dt` и пройдите сценарий занятия 106 заново.

Учебная база сегодня не меняется. Конфигурация `УСК_Тест` тоже не меняется: найденные дефекты не исправляем.

В конспекте создайте файл `tests/negative.md` для результатов и каталог `bugs` для отчётов об ошибке.

## Шаг 1. Проверьте классы и границы количества

Для каждой строки таблицы сначала впишите в конспект ожидаемый результат, потом проверьте. Используйте одну передачу доски со «Склада испытаний» на «ЖК Пробный»: создайте её, меняйте количество в единственной строке и нажимайте **Провести**. После строки, где документ провёлся, отмените проведение, чтобы остаток снова стал `50`.

| Количество | Класс или граница | Ожидаемый результат |
| --- | --- | --- |
| `-1` | не больше нуля | |
| `0` | граница: ноль | |
| `0,001` | граница: наименьшее допустимое | |
| `20` | от нуля до остатка | |
| `50` | граница: ровно остаток | |
| `50,001` | граница: чуть больше остатка | |
| `70` | больше остатка | |

Обратите внимание на сообщение для `50,001`: сколько материала, по словам программы, недостаёт.

Когда таблица пройдена, пометьте передачу на удаление.

**Проверка:** семь строк с ожидаемым и фактическим результатом; `50,001` не проводится, `50` проводится.

## Шаг 2. Пройдите переходы состояний передачи

Создайте новую передачу доски `10` на «ЖК Пробный». Пройдите переходы по порядку и после каждого сверьте остаток в «Остатках на складах» с ожидаемым, который вы впишете заранее.

| № | Действие | Ожидаемое состояние документа | Ожидаемый остаток |
| --- | --- | --- | --- |
| 1 | провести | проведён | |
| 2 | провести повторно без изменений | проведён | |
| 3 | пометить на удаление | помечен, не проведён | |
| 4 | снять пометку удаления | записан, не проведён | |
| 5 | провести | проведён | |
| 6 | отменить проведение и пометить на удаление | помечен, не проведён | |

Переход 3 стоит прочитать внимательно: платформа предупредит, что проведение будет отменено, и после подтверждения отменит его сама — остаток возвращается. Переход 4 не возвращает движения: снятая пометка не проводит документ.

**Проверка:** шесть переходов дали ожидаемые состояния и остатки; итоговый остаток — `50`.

## Шаг 3. Составьте таблицу путей

Перенесите в конспект таблицу «Инвариант и пути к нему» из теории. Добавьте в неё колонку «Проверено на деле» — заполните её в шагах 4–6.

**Проверка:** в конспекте таблица из восьми путей изменения остатка.

## Шаг 4. Проверьте передачу задним числом

1. Создайте передачу доски `60` со «Склада испытаний» на «ЖК Пробный» с датой неделю назад.
2. Нажмите **Провести** и подтвердите предупреждение о неоперативном проведении.
3. Документ проведён. Сформируйте «Остатки на складах» на сегодня: остаток доски `-10`.
4. Отмените проведение и пометьте передачу на удаление. Остаток снова `50`.
5. Найдите в конспекте запись занятия 67 о проведении задним числом. Запишите в `tests/negative.md`: поведение — осознанное ограничение, ссылка на занятие 67, и сформулируйте вопрос к заказчику, если считаете, что ограничение стоит пересмотреть.

**Проверка:** передача задним числом проводится и уводит остаток в минус; это записано как осознанное ограничение со ссылкой на решение, а не как дефект.

## Шаг 5. Отмените проведение поступления после расхода

Требование этапов 4 и 5: остаток материала на складе не уходит в минус. Проверим путь, который никто не защищал.

1. Откройте поступление доски `100` из ТК-01 занятия 106. Из этих `100` уже передано `50`.
2. Запишите ожидаемый результат по требованию: отмена проведения отклонена, пользователь видит причину.
3. Выполните **Ещё → Отмена проведения**.
4. Сформируйте «Остатки на складах»: остаток доски `-50`. Отмена прошла без единого сообщения.
5. Проведите поступление снова. Остаток `50`.
6. Пометьте то же поступление на удаление. Остаток снова `-50`: пометка отменила проведение тем же путём. Снимите пометку и проведите поступление. Остаток `50`.

**Проверка:** отмена проведения и пометка на удаление поступления уводят остаток в минус; ожидаемый результат был записан до проверки.

## Шаг 6. Перепроведите поступление с меньшим количеством

1. В поступлении из шага 5 поставьте количество `40` и проведите.
2. Остаток доски `-10`: передано `50`, поступило теперь `40`.
3. Верните количество `100` и проведите. Остаток `50`.

Заполните в таблице путей колонку «Проверено на деле» для шагов 4–6.

**Проверка:** перепроведение поступления с меньшим количеством уводит остаток в минус; таблица путей заполнена.

## Шаг 7. Проверьте чужой склад

1. Войдите в `УСК_Тест` под Петровым. Его склад — «Центральный склад» (занятие 94).
2. Создайте передачу, смените склад на «Склад испытаний», добавьте доску `1` и нажмите **Записать**.
3. Запись отклонена с сообщением о нарушении прав доступа: ограничение роли «Кладовщик» на право **Добавление** не пускает передачу с чужого склада (занятие 95).
4. Закройте документ без записи.

**Проверка:** Петров не может записать передачу с «Склада испытаний»; результат записан как пройденный негативный сценарий.

## Шаг 8. Напишите отчёты об ошибке

Создайте в конспекте два файла: `bugs/receipt-unpost-negative.md` и `bugs/receipt-repost-negative.md`. Заполните каждый по частям из теории.

Первый отчёт:

1. **Заголовок.** «Отмена проведения поступления уводит остаток склада в минус».
2. **Окружение.** Версия конфигурации `1.1.0`, последний коммит `main` по `git log --oneline -1 main`, база `УСК_Тест`, пользователь «Администратор», тонкий клиент.
3. **Шаги воспроизведения** — с нуля, на новых данных, а не на «Складе испытаний»:
   1. Провести поступление материала `10` на склад, на котором этого материала нет.
   2. Провести передачу этого материала `8` с того же склада.
   3. Отменить проведение поступления.
4. **Ожидаемый результат.** Отмена проведения отклонена с сообщением о нехватке материала; основание — инвариант «остаток не уходит в минус» (занятия 52 и 67).
5. **Фактический результат.** Проведение отменено без сообщений; «Остатки на складах» показывают `-8`.
6. **Серьёзность.** Высокая: учёт показывает несуществующее состояние склада.
7. **Приоритет.** Предложите свой и объясните; окончательно его решает заказчик.

Допишите, что пометка проведённого поступления на удаление воспроизводит тот же дефект: это тот же путь, а не новый дефект.

Второй отчёт заполните сами по образцу — для перепроведения с меньшим количеством.

Пройдите шаги воспроизведения первого отчёта в `УСК_Тест` на новых данных и убедитесь, что они дают описанный результат.

**Проверка:** два отчёта по семи частям; шаги первого воспроизведены с нуля.

## Шаг 9. Дополните регрессионный набор

1. В репозитории `construction-erp` откройте `tests/regression.md` и добавьте тест-кейсы:
   - граница `50,001` при остатке `50` — отказ;
   - пометка проведённой передачи на удаление возвращает остаток;
   - отмена проведения поступления после расхода — отказ; статус «известный дефект», ссылка на отчёт;
   - кладовщик не записывает передачу с чужого склада.
2. Закоммитьте в `main`:

```bash
git add tests/regression.md
git commit -m "Add negative regression test cases"
git push
```

Тест-кейс на известный дефект в наборе нужен именно сейчас: когда дефект исправят, он сразу покажет, что исправление работает, а потом — что дефект не вернулся.

**Проверка:** в `tests/regression.md` четыре новых тест-кейса, коммит отправлен на сервер.

## Проверка результата

Занятие пройдено, если выполняются шесть условий:

1. Для границ количества и переходов состояний передачи ожидаемый результат записан до проверки, фактический — после.
2. Таблица путей изменения остатка заполнена результатами проверки на деле.
3. Передача задним числом записана как осознанное ограничение со ссылкой на решение занятия 67.
4. Есть два отчёта об ошибке — на отмену проведения и на перепроведение поступления, — с шагами с нуля, проверенными в `УСК_Тест`.
5. Конфигурация `УСК_Тест` и учебной базы не изменилась: дефекты не исправлены в обход цикла доработки.
6. В регрессионном наборе проекта есть негативные тест-кейсы, включая тест-кейс на известный дефект.
