# Теория. Элементы формы из кода

## Какую задачу мы решаем

Утром снабженцу нужно узнать одно: по каким объектам есть заявки, которые ждут согласования, и сколько их. Журнал заявок из занятий 84–85 это показывает, но для ответа его нужно отсортировать, отфильтровать и пересчитать глазами.

Снабженец просит «панель»: окно, в котором по каждому такому объекту есть кнопка с подписью «ЖК Южный: на согласовании 2». Нажал — открылись заявки этого объекта.

Разработчик не может нарисовать эти кнопки в редакторе формы. Он не знает, сколько объектов будет завтра, как они будут называться и у каких из них будут заявки на согласовании. Число кнопок и их подписи — **данные**, а не конфигурация. Такие элементы создают из кода.

## Элементы, команды и реквизиты формы — коллекции

На занятии 30 форма разделилась на три слоя: реквизиты, элементы, команды. В модуле формы каждый слой — коллекция, и в каждую можно добавлять из кода.

| Коллекция | Что добавляет | Метод |
| --- | --- | --- |
| `Элементы` | поля, кнопки, группы, декорации | `Элементы.Добавить(Имя, Тип, Родитель)` |
| `Команды` | команды формы | `Команды.Добавить(Имя)` |

Кнопка формы, как и на занятиях 34 и 81, — это элемент, который вызывает команду. Поэтому кнопку из кода создают в два хода: сначала команду, потом кнопку, связанную с ней.

```bsl
Команда = Команды.Добавить("ОткрытьЗаявкиОбъекта1");
Команда.Действие = "Подключаемый_ОткрытьЗаявкиОбъекта";
Команда.Заголовок = "ЖК Южный: на согласовании 2";

Кнопка = Элементы.Добавить("КнопкаОткрытьЗаявкиОбъекта1", Тип("КнопкаФормы"), Элементы.ГруппаОбъекты);
Кнопка.ИмяКоманды = "ОткрытьЗаявкиОбъекта1";
```

- `Команда.Действие` — **имя** процедуры-обработчика строкой. Это то же, что свойство **Действие** команды в палитре, куда платформа вписывает имя, когда вы нажимаете лупу.
- Третий параметр `Элементы.Добавить` — **родитель**: группа, внутри которой появится элемент. Группу удобно нарисовать в редакторе заранее: она задаёт место на форме, а код только наполняет её.
- `Кнопка.ИмяКоманды` связывает кнопку с командой.

Имена элементов и команд в форме должны быть уникальными. Поэтому к имени добавляют номер: `ОткрытьЗаявкиОбъекта1`, `ОткрытьЗаявкиОбъекта2`.

## Где и когда создают элементы

Элементы и команды формы добавляют **на сервере**, чаще всего в `ПриСозданииНаСервере`: форма ещё не показана, и пользователь увидит её уже собранной. Там же есть доступ к базе — к данным, по которым строятся кнопки.

Созданные из кода элементы живут, пока открыта форма. В конфигурации их нет: при следующем открытии `ПриСозданииНаСервере` построит их заново по данным этой минуты.

## Один обработчик на все кнопки

У всех кнопок панели одно действие — открыть заявки объекта. Отличается только объект. Поэтому обработчик один, а нужный объект он находит по **имени нажатой команды**: платформа передаёт команду в параметр `Команда`, и `Команда.Имя` говорит, какую кнопку нажали.

Где взять объект по имени команды? Его запоминают при создании кнопки в **реквизите формы**. Реквизит формы переживает переход с сервера на клиент, а локальная переменная серверной процедуры — нет (занятие 22). Подходит тип `СписокЗначений` (занятие 18): значение — объект строительства, представление — имя команды.

Имя обработчика в типовых конфигурациях начинают с приставки `Подключаемый_`. Платформе приставка не нужна, она нужна читателю: такой процедуры нет ни в одной команде редактора формы, её подключили из кода, и искать, кто её вызывает, нужно в коде.

## Пересоздание элементов

Панель показывает данные момента открытия. Снабженец согласовал две заявки — панель устарела. Команда **Обновить** должна перестроить кнопки.

Добавить новые кнопки поверх старых нельзя: имена совпадут, и платформа откажет. Поэтому обновление идёт в три шага: удалить созданные элементы и команды методами `Элементы.Удалить` и `Команды.Удалить`, очистить реквизит со списком объектов, создать всё заново той же процедурой, что и при открытии.

Удаляют только то, что создано кодом. Группа, надпись и команда **Обновить**, нарисованные в редакторе, остаются.

## Когда кнопки из кода — плохая идея

Кнопка на каждую строку данных хороша, пока строк мало: пять-десять объектов, которые снабженец узнаёт по названию. Если объектов сотни, панель превратится в стену кнопок, и правильным ответом будет таблица — динамический список с отбором и сортировкой из занятия 84.

Создание элементов из кода нужно, когда **структура формы** зависит от данных: число кнопок, число полей, набор колонок. Когда от данных зависят только строки, хватает таблицы, и код не нужен.

## Где живёт логика

| Что | Где | Почему |
| --- | --- | --- |
| Какие объекты и сколько заявок на согласовании | функция серверного общего модуля `СправкиСнабженцаСервер` | это запрос к данным, как на этапе 5 |
| Создание и пересоздание кнопок | серверные процедуры модуля формы обработки | это структура экрана, а элементы создают на сервере |
| Открытие журнала с отбором | клиентский подключаемый обработчик | открытие формы — действие клиента |
| Соответствие кнопки и объекта | реквизит формы `СписокЗначений` | доживает до клиента, в отличие от переменной |

## Что важно запомнить

1. Элементы и команды из кода создают, когда их число или подписи зависят от данных.
2. Кнопку создают в два хода: `Команды.Добавить` с действием и заголовком, затем `Элементы.Добавить` с типом `КнопкаФормы`, родителем и `ИмяКоманды`.
3. Создают элементы на сервере, обычно в `ПриСозданииНаСервере`; в конфигурации их нет, они живут, пока открыта форма.
4. Один подключаемый обработчик обслуживает все кнопки и узнаёт нажатую по `Команда.Имя`; соответствие кнопки и данных хранят в реквизите формы.
5. При обновлении сначала удаляют созданные элементы и команды, потом создают заново той же процедурой.
6. Если от данных зависят только строки, а не структура формы, вместо элементов из кода нужна таблица.
