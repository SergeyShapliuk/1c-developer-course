# Теория. Строки табличной части в коде

## Какую задачу мы решаем

В занятии 31 снабженец ввёл заявку на два материала и обе суммы остались нулевыми. Считать их руками он не будет: при двадцати строках это гарантированные ошибки, а при исправлении количества сумма молча останется старой. Цену он тоже не обязан помнить — она уже лежит в справочнике `Товары`.

Значит, система должна делать три вещи сама:

- при выборе материала подставлять его цену из справочника;
- при изменении количества или цены пересчитывать сумму строки;
- показывать итог по всей заявке, чтобы было видно, на какие деньги заявка.

Всё это — работа с данными табличной части из кода. Отдельного механизма для неё в платформе нет: строки табличной части обрабатываются теми же средствами, что и коллекции из занятия 17.

## Строки табличной части — ещё одна коллекция

Табличная часть в коде ведёт себя как коллекция строк. Обходится она привычным `Для Каждого` из занятия 14:

```bsl
Для Каждого СтрокаМатериала Из Объект.Материалы Цикл
	Сообщить(СтрокаМатериала.Материал);
КонецЦикла;
```

`Объект` — реквизит формы, в котором лежит сам документ (занятие 30). `Объект.Материалы` — его табличная часть. Переменная `СтрокаМатериала` на каждом витке цикла получает очередную строку, а её реквизиты читаются через точку: `СтрокаМатериала.Количество`.

Это тот же приём, что с массивом структур в занятии 17. Разница в том, что набор «колонок» задан в метаданных и изменить его кодом нельзя: строке табличной части `Материалы` можно присвоить только `Материал`, `Количество`, `Цена` и `Сумма`.

У коллекции строк есть и методы, знакомые по таблице значений из занятия 18: `Количество()` возвращает число строк, `Добавить()` добавляет строку в конец, `Удалить()` удаляет строку, `Итог("Сумма")` складывает значения одной числовой колонки.

## Чем коллекция строк отличается от таблицы значений

Внешне похоже, но путать эти две вещи нельзя.

| | `ТаблицаЗначений` | Табличная часть документа |
| --- | --- | --- |
| Где живёт | только в памяти | в базе данных вместе с документом |
| Колонки | создаются кодом | заданы в метаданных |
| Доступность | в нашем сценарии только на сервере (занятие 18) | данные формы доступны и на клиенте |
| Что с ней станет | исчезнет после процедуры | сохранится при записи документа |

Практический вывод: табличную часть не нужно куда-то «сохранять» отдельно. Вы меняете строки — меняются данные формы; пользователь нажимает **Записать** — изменения попадают в базу. Отдельной команды сохранения строк нет.

## Как добраться до нужной строки

Когда пользователь правит одну ячейку, обходить все строки не нужно: пересчитать надо ту, в которой он стоит. Для этого есть два новых для нас понятия.

**`Элементы`** — коллекция элементов формы, доступная в модуле формы по имени. `Элементы.Материалы` — та самая таблица на форме, которую мы вывели в занятии 31.

**`ТекущиеДанные`** — свойство таблицы формы, возвращающее строку, в которой стоит курсор. Это не копия, а сама строка: записав в неё значение, вы меняете данные документа.

```bsl
&НаКлиенте
Процедура МатериалыКоличествоПриИзменении(Элемент)
	СтрокаМатериала = Элементы.Материалы.ТекущиеДанные;
	СтрокаМатериала.Сумма = СтрокаМатериала.Количество * СтрокаМатериала.Цена;
КонецПроцедуры
```

Имя обработчика платформа составила сама из имени таблицы, имени колонки и имени события — так работает кнопка с лупой из занятия 23, и переименовывать результат не следует.

Одна осторожность: `ТекущиеДанные` может вернуть `Неопределено`, если текущей строки нет. В обработчике `ПриИзменении` колонки такого не бывает — пользователь только что правил ячейку, значит строка есть. Но в коде, который вызывается не из события строки, проверка на `Неопределено` обязательна.

## Откуда берётся цена

Цена материала уже есть в системе: это реквизит `Цена` справочника `Товары` из занятия 8. Второй раз вводить её руками — значит заводить второй источник правды, который разойдётся с первым.

Достать её можно разыменованием через ссылку (занятие 19):

```bsl
&НаСервереБезКонтекста
Функция ЦенаМатериала(Материал)
	Возврат Материал.Цена;
КонецФункции
```

Разыменование `Материал.Цена` — это обращение к данным базы: платформа читает элемент справочника по ссылке. Поэтому функция серверная, как требует занятие 22. Контекст формы ей не нужен — она получает ссылку параметром и возвращает число, — и директива у неё `&НаСервереБезКонтекста`.

Важная деталь: цена **копируется** в строку документа, а не читается из справочника каждый раз. Это осознанный выбор. Заявка должна помнить цену, по которой её оформляли: если завтра в справочнике поставят другую цену, старая заявка не должна измениться. Такое копирование значения в документ в учётных системах обычное дело, и у нашего способа хранения цены есть свои ограничения — одно значение, без истории. К этому мы вернёмся на этапе 4.

## Когда считать: в событии, а не при записи

Сумму можно было бы посчитать один раз при записи документа. Так делать не нужно.

Пользователь должен видеть результат сразу, как только ввёл количество: сумма и итог — это обратная связь, по которой он проверяет себя. Если сумма появится только после записи, человек будет записывать документ, чтобы посмотреть, что получилось, и исправлять — вместо того чтобы сразу ввести правильно.

Отсюда правило: **расчёт, который помогает пользователю вводить данные, выполняют в момент ввода**. Событие `ПриИзменении` колонки для этого и существует. В занятии 33 мы добавим вторую линию обороны — проверку в момент записи, — но она отвечает на другой вопрос: не «что показать», а «можно ли это принять».

## Где живёт пересчёт и почему

Теперь главный вопрос занятия. Пересчёт суммы строки — чей он? Варианты из занятия 21: модуль формы, модуль объекта, общий модуль.

| Что именно делаем | Где место | Почему |
| --- | --- | --- |
| Реагируем на правку ячейки, показываем итог | Модуль формы | Это поведение экрана: без формы события `ПриИзменении` не существует |
| Храним формулу «сумма = количество × цена» | Общий модуль | Нужна больше чем в одном месте, уже написана в занятии 21 |
| Гарантируем согласованность при любой записи | Модуль объекта | Записать документ можно и из кода, минуя форму — занятие 33 |

Обработчик `МатериалыКоличествоПриИзменении` в модуле объекта попросту не заработает: там нет ни формы, ни курсора, ни текущей строки. А итог по заявке — это реквизит формы, он нигде не хранится и вне формы смысла не имеет.

Формулу же в модуле формы повторять незачем: функция `УчебныеФункции.РассчитатьСумму` написана в занятии 21 и доступна отсюда. Общий модуль `УчебныеФункции` серверный, поэтому каждый её вызов с клиента — это серверный вызов (занятие 22). На одну правку строки один вызов — для учебной задачи нормально; приём, который пересчитывает все строки за один вызов, мы разберём в занятии 34.

## Что важно запомнить

1. Табличная часть в коде — это коллекция строк, обходимая обычным `Для Каждого`.
2. Набор реквизитов строки задан в метаданных, кодом его не изменить.
3. Табличная часть хранится в базе вместе с документом, а `ТаблицаЗначений` живёт только в памяти.
4. `Элементы.Материалы.ТекущиеДанные` возвращает строку под курсором; записанные в неё значения меняют документ.
5. Имена обработчиков вида `МатериалыКоличествоПриИзменении` платформа составляет сама — их не переименовывают.
6. Цена берётся из `Товары` разыменованием на сервере и копируется в строку, чтобы документ помнил цену на момент оформления.
7. Расчёты для удобства ввода делают в событиях формы, а проверки допустимости данных — при записи.
8. Логика экрана живёт в модуле формы, переиспользуемая формула — в общем модуле.
