# Теория. Динамический список

## Какую задачу мы решаем

Снабженец начинает утро с журнала **Логистика → Заявки на материалы**. Ему нужно понять, какие заявки ждут согласования, на какие объекты и на какие суммы. Журнал, который платформа построила сама, показывает дату и номер — и почти ничего больше. Чтобы узнать сумму заявки, её приходится открывать: сумма живёт в строках табличной части, а не в шапке документа.

Двадцать заявок — двадцать открытий формы. Нужен журнал, в котором видно главное по каждой заявке сразу: объект, состояние, приоритет, сумма.

## Форма списка

На занятии 9 мы различали форму элемента и форму списка. У документа то же самое: **форма документа** показывает один документ, **форма списка** — все документы этого вида. Журнал в разделе **Логистика** — это и есть форма списка.

Пока своей формы списка нет, платформа строит её сама, как строила форму документа до занятия 30. Чтобы управлять колонками, создают свою форму списка и назначают её **основной формой списка** документа — так же, как на занятии 30 назначали основную форму объекта.

## Динамический список

Главный реквизит формы списка — `Список` с типом **ДинамическийСписок**. Это не таблица значений и не массив строк. Динамический список — описание того, **какие** данные показать; сами данные он читает из базы по мере надобности.

| Что сравниваем | Таблица значений на форме | Динамический список |
| --- | --- | --- |
| Когда читаются данные | все сразу, кодом | порциями, по мере прокрутки |
| Сколько строк в памяти | все | только видимые и немного вокруг |
| Кто сортирует и ищет | код разработчика | база данных, по щелчку пользователя |
| Нужен ли код для показа | да | нет |

Порционное чтение — главное свойство динамического списка. В рабочей базе заявок десятки тысяч. Если бы форма читала их все при открытии, журнал открывался бы минуту. Динамический список читает одну страницу: те строки, которые видны на экране, и немного вокруг них. Пользователь прокручивает — список дочитывает следующую порцию.

## Основная таблица

У динамического списка есть свойство **Основная таблица** — таблица базы, строки которой он показывает. Для журнала заявок это `Документ.ЗаявкаНаМатериалы`.

Основная таблица даёт списку **ключ**: каждая строка списка — это ссылка на документ. Поэтому платформа сама умеет открыть документ по двойному щелчку, создать новый, скопировать, пометить на удаление. Мы не пишем для этого ни строки кода — всё работает так же, как в автогенерируемом журнале.

## Произвольный запрос

Пока динамический список работает по основной таблице, его колонки — это реквизиты шапки документа и их реквизиты через точку. Сумма заявки к ним не относится: её нужно сложить по строкам табличной части.

Для этого у динамического списка есть флаг **Произвольный запрос**. С ним данные списка описывает запрос на знакомом с этапа 5 языке запросов, а основная таблица по-прежнему задаёт ключ. Сумма заявки получается так же, как на занятиях 58–62: строки табличной части группируют по ссылке на документ во вложенном запросе и левым соединением присоединяют к таблице документов. `ЕСТЬNULL` превращает отсутствующую сумму заявки без строк в ноль (занятие 57).

У запроса динамического списка есть ограничения.

- **Один запрос.** Пакеты и временные таблицы (занятие 63) в динамическом списке не используются: он сам добавляет к запросу отбор, сортировку и порцию строк, и ему нужен один запрос.
- **Без итогов.** Секция `ИТОГИ` (занятие 61) не нужна: список не выводит итоги по группировкам.
- **Ключ на месте.** В запросе должна быть ссылка основной таблицы — по ней список узнаёт, какой документ открыть.

## Цена вычисляемой колонки

Порционное чтение спасает от загрузки всех документов, но не от тяжёлого запроса. Чтобы показать двадцать строк журнала, отсортированных по сумме, базе придётся посчитать сумму **каждой** заявки, иначе она не узнает, какие двадцать первые. На учебной базе это незаметно. На базе с сотнями тысяч заявок колонка, которую считают группировкой строк, может замедлить журнал.

Поэтому в рабочих конфигурациях часто идут другим путём: хранят сумму документа в реквизите шапки — например, `СуммаДокумента`, — и заполняют её в `ПередЗаписью` модуля объекта. Такое хранение данных, которые можно вычислить, называется **денормализацией**. Она ускоряет чтение, но требует, чтобы реквизит всегда пересчитывался при записи. Для учебного проекта мы считаем сумму запросом, а выбор между двумя путями оставляем вопросом архитектуры.

## Где живёт логика

| Что | Где | Почему |
| --- | --- | --- |
| Какие колонки видит снабженец | своя форма списка документа | это представление журнала |
| Как посчитать сумму заявки для журнала | произвольный запрос динамического списка | данные для показа, без кода |
| Чтение, сортировка, поиск, порции | платформа | динамический список делает это сам |
| Сумма, нужная для учёта или проверок | модуль объекта или серверный запрос | журнал — представление, а не источник правил |

## Что важно запомнить

1. Журнал документов — форма списка; свою форму списка назначают основной формой списка документа.
2. Динамический список читает данные из базы порциями и сам выполняет сортировку и поиск; кода для показа не нужно.
3. Основная таблица даёт списку ключ — ссылку, и с ней работают открытие, создание, копирование и пометка удаления.
4. Произвольный запрос нужен, когда колонки не берутся из реквизитов основной таблицы напрямую; это один запрос без пакетов и итогов, и ссылка в нём обязательна.
5. Вычисляемая колонка стоит запроса по всем документам при сортировке по ней; в рабочих конфигурациях такие значения часто хранят в шапке — это денормализация.
