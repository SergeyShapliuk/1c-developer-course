# Теория. Как код меняет данные

## Создание элемента

На занятии 19 мы только читали. Теперь будем менять. Новый элемент справочника создаёт менеджер:

```bsl
НовыйТовар = Справочники.Товары.СоздатьЭлемент();
НовыйТовар.Наименование = "Кирпич облицовочный";
НовыйТовар.Артикул = "KR-001";
НовыйТовар.Цена = 18.90;
НовыйТовар.Записать();
```

`СоздатьЭлемент()` возвращает объект типа `СправочникОбъект.Товары` — пустую карточку в памяти, и реквизиты заполняются там же.

Ключевой момент: **до вызова `Записать()` в базе ничего нет**. Пока код не дошёл до этой строки, элемент существует только в памяти, и если процедура завершится раньше, он просто исчезнет. `Записать()` — граница, после которой данные появляются в базе и становятся видны в приложении.

После записи платформа присваивает элементу код и у объекта появляется заполненная `Ссылка`:

```bsl
Сообщить("Создан элемент с кодом " + НовыйТовар.Код);
СсылкаНаТовар = НовыйТовар.Ссылка;
```

## Изменение элемента

Изменение состоит из трёх шагов: найти, получить объект, записать.

```bsl
Товар = Справочники.Товары.НайтиПоНаименованию("Цемент М500");

Если НЕ Товар.ПустаяСсылка() Тогда
	Объект = Товар.ПолучитьОбъект();
	Объект.Цена = Объект.Цена * 1.1;
	Объект.Записать();
КонецЕсли;
```

Почему здесь обязателен `ПолучитьОбъект()`? Потому что ссылка — только указатель, записать через неё нечего. Менять можно лишь то, что загружено в память, то есть объект.

По той же причине нельзя изменить элемент через выборку: `Выборка.Цена` доступна только для чтения. Если при переборе выборкой нужно что-то изменить, у текущего элемента берут ссылку и получают объект:

```bsl
Пока Выборка.Следующий() Цикл
	Объект = Выборка.Ссылка.ПолучитьОбъект();
	Объект.ЕдиницаИзмерения = "шт.";
	Объект.Записать();
КонецЦикла;
```

## Пометка удаления

Удалить элемент из базы одним действием платформа сознательно не предлагает. Обычный способ — **пометка удаления**:

```bsl
Объект = Товар.ПолучитьОбъект();
Объект.УстановитьПометкуУдаления(Истина);
```

Отдельный вызов `Записать()` после этого не нужен: метод сам записывает объект.

Причина в ссылках. На элемент справочника могут ссылаться другие данные: у склада есть ответственный сотрудник, у объекта строительства — заказчик. Если мгновенно убрать элемент из базы, эти ссылки станут указывать в пустоту и при открытии покажут «объект не найден».

Поэтому удаление разделено на два этапа. Сначала элемент помечают: он остаётся в базе и отображается в списках перечёркнутым. Затем администратор запускает обработку **Все функции → Стандартные → Удаление помеченных объектов**. Она проверяет, не ссылается ли кто-нибудь на помеченные элементы, и удаляет только те, на которые ссылок нет; про остальные сообщает, где они используются.

## Непосредственное удаление

У объекта есть и метод `Удалить()`: он убирает элемент из базы сразу, никаких ссылок не проверяя. В прикладном коде он почти не применяется — ровно потому, что оставляет битые ссылки. Его место — служебные обработки, когда разработчик точно знает, что делает.

## Сначала найти, потом создать

Самая частая ошибка начинающего — код, который при каждом запуске создаёт новый элемент. Запустили три раза — в справочнике три «Кирпича облицовочного», и различить их нельзя.

Правильный порядок всегда один: **сначала поискать, и только если не нашли — создавать**.

```bsl
Товар = Справочники.Товары.НайтиПоНаименованию("Кирпич облицовочный");

Если Товар.ПустаяСсылка() Тогда
	// элемента нет — создаём
Иначе
	// элемент уже есть — ничего не делаем
КонецЕсли;
```

Свойство кода, при котором повторный запуск не меняет результат, называется **идемпотентностью**. Сколько раз ни запусти — состояние базы одно и то же: один «Кирпич облицовочный», а не три.

Это важно не из эстетики: код запускают повторно постоянно — разработчик проверяет правку, обработка срабатывает по расписанию, пользователь нажимает кнопку дважды из нетерпения.

## Запись — дорогая операция

`Записать()` — не присваивание переменной. Платформа проверяет заполнение обязательных реквизитов, пишет данные в базу, обновляет служебные таблицы, оповещает открытые формы.

Отсюда правило: **не записывайте то, что не изменилось**. Сравните значение с нужным и вызывайте `Записать()` только при расхождении:

```bsl
Если НЕ ЗначениеЗаполнено(Объект.ЕдиницаИзмерения) Тогда
	Объект.ЕдиницаИзмерения = "шт.";
	Объект.Записать(); // только для тех элементов, где реквизит был пуст
КонецЕсли;
```

Если из тысячи элементов реквизит пуст у десяти, такой код выполнит десять записей вместо тысячи.

## Что важно запомнить

1. `СоздатьЭлемент()` создаёт объект только в памяти; до `Записать()` в базе ничего нет.
2. Изменять можно только объект, полученный через `ПолучитьОбъект()`; ссылка и выборка доступны для чтения.
3. После записи элемент получает код, и у объекта заполнена `Ссылка`.
4. Пометка удаления сохраняет элемент в базе; реально удаляет его обработка удаления помеченных объектов, предварительно проверив ссылки.
5. `Удалить()` удаляет сразу и без проверки ссылок, поэтому в прикладном коде почти не используется.
6. Сначала найти, потом создавать — иначе повторный запуск наплодит дубли.
7. Идемпотентный код при повторном запуске даёт тот же результат, что при первом.
8. `Записать()` — дорогая операция, поэтому записывают только изменившиеся объекты.
