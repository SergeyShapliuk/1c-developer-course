# Теория. Команды документа

## Какую задачу мы решаем

В конце занятия 32 мы оставили честный долг. Пользователь удаляет строку из заявки — и итог по заявке остаётся старым, потому что удаление строки не вызывает ни одного из написанных обработчиков `ПриИзменении`. Пересчитать заявку целиком нечем: события на это нет.

Есть и вторая задача. Снабженец ввёл заявку на двадцать строк и хочет перед записью увидеть сводку: сколько строк, на какую сумму, нет ли строк, из-за которых проверка из занятия 33 откажется записывать документ. Платформа такой сводки не даст — это наше прикладное требование.

Обе задачи устроены одинаково: пользователь должен иметь **кнопку, по которой система делает что-то со всем документом сразу**. Механизм для этого — команда, знакомая по занятию 23. Разница в том, что теперь она живёт на документе, а работа по кнопке затрагивает не одно поле, а всю табличную часть.

## Три вида команд на документе

Виды команд те же, что в занятии 23; меняется только то, какому объекту они принадлежат.

| Вид команды | Где создают | Где становится видна | Когда выбирать |
| --- | --- | --- | --- |
| Команда формы | В самой форме, вкладка **Команды** | Только в этой форме | Действие нужно ровно на одном экране |
| Команда объекта | У документа, вкладка **Команды** | Во всех формах документа и в его журнале | Действие относится к документу, а не к экрану |
| Общая команда | **Общие → Общие команды** | У нескольких объектов, можно вывести в раздел | Одно действие нужно в разных местах |

У документа команд обычно больше, чем у справочника, и путаница возникает чаще. Поэтому разберём первые два вида подробно: выбор между ними — главный вопрос этого занятия.

## Команда формы или команда объекта

**Команда формы** принадлежит форме. Её обработчик пишут в модуле этой формы, и ему доступно всё, что есть у формы: реквизит `Объект` с данными документа, реквизиты формы вроде `ИтогоПоЗаявке` из занятия 32, коллекция `Элементы`, текущая строка таблицы.

**Команда объекта** принадлежит документу. Её код живёт в собственном модуле команды, и форма ему не видна: команда получает **ссылку** на документ и работает с данными из базы. Зато она появляется сразу везде, где этот документ показан, — и в форме, и в списке, где пользователь может отметить сразу несколько заявок.

Отсюда простое правило выбора: **если действие работает с тем, что пользователь сейчас набрал на экране, это команда формы; если с тем, что уже записано в базу, — команда объекта**.

Наш пересчёт заявки — явный случай команды формы. Он меняет данные, которые пользователь ещё не записал, и обновляет реквизит формы с итогом. Команда объекта с этим не справилась бы: в базе лежит старая версия заявки, а несохранённых правок из формы она не видит. Печать заявки или отметка её исполненной, наоборот, относятся к записанному документу — это работа для команды объекта, и такие сценарии появятся в занятиях 35 и 37.

## Стандартные команды: Записать и Записать и закрыть

Открытая форма документа уже имеет кнопки, которых мы не делали. Это **стандартные команды** — команды, которые платформа создаёт для объекта сама, зная его тип. Писать для них код не нужно и нельзя; управлять можно только их видимостью и размещением в командном интерфейсе формы.

- **Записать** сохраняет документ в базу и оставляет форму открытой. Пользователь продолжает работу, но введённое уже не потеряется.
- **Записать и закрыть** делает то же и закрывает форму. Это основной способ завершить ввод документа.

Важно для занятия 33: обе эти команды — интерактивная запись. Нажав любую из них, пользователь запускает `ОбработкаПроверкиЗаполнения`, а затем `ПередЗаписью` в модуле объекта. Своя команда никакой записи сама не делает: она только меняет данные формы, а записывать их пользователь будет стандартной командой.

Есть и третья стандартная команда, **Провести**, — её у нашей заявки пока нет, потому что соответствующее свойство документа выключено. Что она делает и зачем нужна, разберём на этапе 4, начиная с занятия 39: пока у системы просто нет места, куда документ мог бы что-то записать, кроме самого себя.

## Один вызов вместо двадцати

Обработчик команды формы всегда клиентский: кнопку нажимают на клиенте. Но работа по кнопке у нас серверная — сумма строки считается функцией `УчебныеФункции.РассчитатьСумму` из общего серверного модуля (занятие 21).

Написать можно так — и так писать не нужно:

```bsl
Для Каждого СтрокаМатериала Из Объект.Материалы Цикл
	СтрокаМатериала.Сумма = УчебныеФункции.РассчитатьСумму(СтрокаМатериала.Количество, СтрокаМатериала.Цена);
КонецЦикла;
```

В клиентском обработчике каждый виток этого цикла — отдельный серверный вызов, то есть отдельное обращение по сети. На двадцати строках получится двадцать обращений, и пользователь увидит задержку. Занятие 22 называло это главной ошибкой клиент-серверного кода.

Правильный приём — **перенести весь цикл на сервер и вызвать его один раз**:

```bsl
&НаКлиенте
Процедура ПересчитатьЗаявку(Команда)
	Сводка = ПересчитатьЗаявкуНаСервере();
	ИтогоПоЗаявке = Сводка.Итого;
КонецПроцедуры
```

Клиентский обработчик состоит из одной содержательной строки: он зовёт серверную процедуру и забирает результат. Сколько бы строк ни было в заявке, обращение к серверу одно.

## Почему серверная процедура с контекстом

Директива у серверной части будет `&НаСервере`, а не `&НаСервереБезКонтекста` из занятия 32. Причина в данных: процедура должна **изменить** `Объект.Материалы` — реквизит формы, а без контекста реквизиты формы недоступны.

Плата за это известна из занятия 22: платформа повезёт на сервер и обратно данные формы целиком. Для заявки это приемлемо, а правило звучит так: **без контекста — когда хватает параметров и результата; с контекстом — когда надо менять данные формы**.

Результат удобно вернуть структурой (занятие 17): в ней сразу и итог, и число строк, и число строк без материала. Одно возвращаемое значение, сколько бы показателей ни понадобилось:

```bsl
Сводка = Новый Структура("ВсегоСтрок, СтрокБезМатериала, Итого", 0, 0, 0);
```

Сообщения пользователю при этом остаются на клиенте — форма уже на экране, и показать их есть кому (занятие 23).

## Где живёт код команды

Соберём ответ на архитектурный вопрос занятия в таблицу.

| Что делаем | Где место | Почему |
| --- | --- | --- |
| Реакция на нажатие кнопки, вывод сообщений, обновление итога | Модуль формы, `&НаКлиенте` | Это поведение экрана |
| Обход всех строк и расчёт сумм | Модуль формы, `&НаСервере` | Нужен контекст формы и серверный общий модуль |
| Формула «сумма = количество × цена» | Общий модуль | Правило одно на всю конфигурацию |
| Запрет записать плохую заявку | Модуль объекта | Должен работать при любой записи (занятие 33) |

Последняя строка таблицы важнее остальных. Наша кнопка **сообщает** о проблемных строках — это подсказка, которую пользователь может проигнорировать. Запрещает запись не она, а модуль объекта. Команда и проверка не заменяют друг друга: одна помогает ввести, другая гарантирует результат.

## Что важно запомнить

1. Команда формы принадлежит форме и видит её данные; команда объекта принадлежит документу и работает с записанными данными.
2. Действие над несохранёнными данными экрана — всегда команда формы.
3. Стандартные команды **Записать** и **Записать и закрыть** платформа создаёт сама, кода они не требуют.
4. Нажатие **Записать** — интерактивная запись, значит срабатывают обработчики модуля объекта из занятия 33.
5. Стандартной команды **Провести** у заявки пока нет; этот механизм разбирается на этапе 4.
6. Цикл с серверными вызовами внутри клиентского обработчика заменяют одним вызовом серверной процедуры.
7. Директива `&НаСервере` нужна, когда процедура меняет данные формы; без контекста данные формы недоступны.
8. Несколько показателей из серверной процедуры возвращают одной структурой.
