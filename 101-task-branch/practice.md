# Практика. Ветка feature/closed-sites

## Перед началом

Запустите конфигуратор учебной базы под пользователем «Администратор» и выгрузите базу в новый файл `.dt`: сегодня меняется структура справочника.

Понадобятся репозиторий `construction-erp` из занятия 100 и карточка задачи `tasks/closed-sites.md` из занятия 99 в конспекте. Откройте терминал в каталоге `construction-erp` и убедитесь, что вы в ветке `main` и изменений нет:

```bash
git status
```

Если `git status` показывает изменения, выясните их происхождение до начала работы: выполните `git diff` и сравните с тем, что вы делали после занятия 100.

## Шаг 1. Создайте ветку задачи

```bash
git switch -c feature/closed-sites
git branch
```

`git switch -c` создаёт ветку от текущего коммита `main` и переключается в неё. `git branch` показывает обе ветки, текущая отмечена звёздочкой.

База разработки сейчас соответствует `main`: в неё ничего не загружали после занятия 100. С этой минуты все изменения базы будут попадать в ветку задачи.

**Проверка:** текущая ветка — `feature/closed-sites`.

## Шаг 2. Добавьте реквизит Завершен

1. В конфигураторе раскройте **Справочники → ОбъектыСтроительства → Реквизиты** и нажмите **Добавить**.
2. Задайте **Имя** — `Завершен`, **Синоним** — «Завершён», **Тип** — `Булево`.
3. Если у справочника есть своя форма элемента, откройте её и перетащите реквизит `Завершен` в дерево элементов. Если формы нет, платформа покажет новый реквизит в автоматической форме сама.
4. Нажмите `Ctrl+S`, затем `F7`. Платформа предупредит о реорганизации таблицы справочника — это тот риск, который вы записали в карточку на занятии 99. Примите изменения.

**Проверка:** у справочника `ОбъектыСтроительства` есть реквизит `Завершен` типа `Булево`, база данных обновлена.

## Шаг 3. Выгрузите и закоммитьте реквизит

1. Выполните **Конфигурация → Выгрузить конфигурацию в файлы** в каталог `src\cf`, с флагом выгрузки только изменений, если он есть.
2. В терминале посмотрите, что изменилось:

```bash
git status
git diff
```

В списке изменённых файлов — `src/cf/Catalogs/ОбъектыСтроительства.xml`, а если вы правили форму элемента, ещё и её `Form.xml`. В `git diff` найдите добавленный блок реквизита: строки со знаком `+`, где встречаются имя `Завершен`, синоним «Завершён» и тип `xs:boolean`. Всё это — одно ваше действие в конфигураторе.

3. Закоммитьте:

```bash
git add src/cf/Catalogs
git commit -m "Add completed flag to construction sites"
```

Команда `git add src/cf/Catalogs` добавляет в индекс только каталог справочников. Это способ собрать коммит из нужного: если бы в выгрузке оказалось ещё что-то, в коммит оно бы не попало.

**Проверка:** `git log --oneline` показывает коммит `Add completed flag to construction sites`, `git status` чист.

## Шаг 4. Задайте параметр выбора

1. Раскройте **Документы → ПередачаМатериалов → Реквизиты** и выделите `ОбъектСтроительства`.
2. В свойстве **Параметры выбора** добавьте строку: **Имя** — `Отбор.Завершен`, **Значение** — `Ложь`. Так же, как на занятии 82 для поставщика.
3. `Ctrl+S`, `F7`.
4. Выгрузите конфигурацию в `src\cf`.
5. Посмотрите изменения:

```bash
git status
git diff
```

Изменился один файл — `src/cf/Documents/ПередачаМатериалов.xml`. В `git diff` — строки параметра выбора у реквизита `ОбъектСтроительства`. Модуль объекта и форма не изменились: параметр выбора — свойство реквизита, и форма получает его сама (занятие 82).

6. Закоммитьте:

```bash
git add src/cf/Documents/ПередачаМатериалов.xml
git commit -m "Hide completed sites from transfer choice"
```

**Проверка:** в истории ветки два коммита, `git status` чист.

## Шаг 5. Добавьте проверку в проведение

1. Откройте модуль объекта документа `ПередачаМатериалов` и найдите в `ОбработкаПроведения` проверку незаполненного объекта строительства — блок с сообщением «Не указан объект строительства» (занятие 52).
2. Сразу после его `КонецЕсли;`, перед проверкой пустой табличной части, вставьте:

```bsl
	Если ЗначениеЗаполнено(ОбъектСтроительства) И ОбъектСтроительства.Завершен Тогда
		Сообщение = Новый СообщениеПользователю;
		Сообщение.Текст = "Объект строительства «" + Строка(ОбъектСтроительства)
			+ "» завершён: передавать на него материалы нельзя";
		Сообщение.Поле = "ОбъектСтроительства";
		Сообщение.УстановитьДанные(ЭтотОбъект);
		Сообщение.Сообщить();
		Отказ = Истина;
	КонецЕсли;
```

Проверка стоит среди проверок документа, до раннего `Возврат` и до формирования движений: она дешёвая и смотрит на сам документ, как проверки занятия 48. Условие `ЗначениеЗаполнено` нужно, чтобы не обращаться к реквизиту пустой ссылки: о пустом объекте пользователю уже сообщил предыдущий блок.

3. Выполните синтаксический контроль, `Ctrl+S`, `F7`.
4. Выгрузите конфигурацию и посмотрите изменения:

```bash
git diff
```

Теперь `git diff` показывает обычный код: в `ObjectModule.bsl` добавлены ровно те строки, что вы вставили. Сравните, насколько легче читать это изменение, чем изменение XML в шагах 3 и 4.

5. Закоммитьте:

```bash
git add src/cf/Documents/ПередачаМатериалов/Ext/ObjectModule.bsl
git commit -m "Refuse transfers to completed sites"
```

**Проверка:** в истории ветки три коммита, синтаксический контроль ошибок не находит.

## Шаг 6. Проверьте задачу в приложении

Пройдите критерии приёмки из карточки задачи под администратором.

1. Создайте объект строительства «ЖК Восточный». Флаг «Завершён» не ставьте.
2. Создайте передачу с «Центрального склада» на «ЖК Восточный», «Песок речной» — `1`, и нажмите **Записать**, не проводя. Это черновик, который пригодится на пункте 5.
3. Откройте «ЖК Восточный» и поставьте флаг «Завершён». Запишите.
4. Создайте новую передачу. В форме выбора объекта строительства «ЖК Восточного» нет; при вводе «Вост» по строке платформа его не предлагает. Закройте передачу без записи.
5. Откройте черновик из пункта 2 и нажмите **Провести**. Проведение отклонено, сообщение «Объект строительства «ЖК Восточный» завершён…» стоит у поля «Объект строительства».
6. Снимите флаг «Завершён» у «ЖК Восточного» и проведите черновик. Документ проведён.
7. Отмените проведение черновика и пометьте его на удаление. «ЖК Восточный» снова отметьте завершённым: он понадобится на следующих занятиях.
8. Регрессия: создайте передачу на «ЖК Северный», «Песок речной» — `1`, и проведите. Документ проводится, как раньше. Отмените проведение и пометьте передачу на удаление.

**Проверка:** все восемь пунктов дали ожидаемый результат; запишите их в карточку задачи напротив критериев приёмки.

## Шаг 7. Поймайте случайное изменение

1. Откройте форму документа `ПередачаМатериалов` и у поля «Ответственный» поменяйте **Заголовок** на «Ответственный (тест)». `Ctrl+S`.
2. Выгрузите конфигурацию и выполните `git status`. Изменился `Form.xml` формы документа — файл, которого задача не касается.
3. Попробуйте отменить изменение средствами Git:

```bash
git restore src/cf/Documents/ПередачаМатериалов/Forms/ФормаДокумента/Ext/Form.xml
git status
```

`git status` чист.

4. Снова выгрузите конфигурацию и выполните `git status`. Изменение вернулось: в базе заголовок по-прежнему «Ответственный (тест)», и выгрузка честно записала его в файл.
5. Исправьте причину: в конфигураторе верните заголовку поля текст «Ответственный», `Ctrl+S`, выгрузите конфигурацию.
6. Выполните `git status`. Изменений нет.

Если после пункта 5 Git всё ещё видит изменение в `Form.xml`, выполните `git diff` по этому файлу и найдите, чем он отличается от закоммиченного. Если найти и исправить отличие в конфигураторе не получается, верните базу к состоянию репозитория загрузкой конфигурации из файлов из каталога `src\cf` и выполните `F7`.

**Проверка:** случайное изменение исправлено в конфигураторе, повторная выгрузка не показывает изменений.

## Шаг 8. Прочитайте историю ветки

```bash
git log --oneline
git log --oneline --stat main..HEAD
git show HEAD
```

`git log --oneline` показывает всю историю: коммит занятия 100 и три коммита задачи. Запись `main..HEAD` означает «коммиты, которые есть в текущей ветке, но нет в `main`», то есть ровно работу по задаче. Ключ `--stat` добавляет к каждому коммиту список изменённых файлов. `git show HEAD` показывает последний коммит целиком: автора, дату, сообщение и изменения.

Убедитесь, что `main` не изменилась:

```bash
git log --oneline main
```

В `main` по-прежнему один коммит.

**Проверка:** в `main..HEAD` три коммита, у каждого один изменённый файл или файлы одного объекта; в `main` один коммит.

## Проверка результата

Занятие пройдено, если выполняются шесть условий:

1. В репозитории есть ветка `feature/closed-sites` с тремя коммитами задачи; `main` не изменилась.
2. У справочника `ОбъектыСтроительства` есть реквизит `Завершен`, у реквизита `ОбъектСтроительства` передачи — параметр выбора `Отбор.Завершен` = `Ложь`.
3. Передача на завершённый объект не проводится, сообщение стоит у поля «Объект строительства».
4. Завершённый объект не предлагается в новой передаче ни в форме выбора, ни при вводе по строке.
5. Передачи на незавершённые объекты проводятся, как раньше.
6. После выгрузки `git status` чист: случайных изменений в базе нет.
