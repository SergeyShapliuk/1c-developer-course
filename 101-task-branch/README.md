# Занятие 101. Ветка под задачу и коммиты

## Цель

Научиться вести доработку в отдельной ветке и сохранять её в истории понятными шагами. Разобраться, какие файлы выгрузки меняет каждое действие в конфигураторе, как отличить нужное изменение от случайного и почему `git restore` не откатывает базу.

## Результат занятия

В репозитории `construction-erp` появится ветка `feature/closed-sites` с тремя коммитами: реквизит `Завершен` справочника `ОбъектыСтроительства`, параметр выбора у реквизита `ОбъектСтроительства` передачи и проверка в её `ОбработкаПроведения`. В приложении завершённый объект не предлагается в новой передаче, и передача на него не проводится. Ветка `main` при этом не изменилась.

## Маршрут

1. Прочитайте [теорию](theory.md) — около 25 минут.
2. Выполните [практику](practice.md) — около 60 минут.
3. Ответьте на контрольные вопросы в конце практики, не подглядывая в теорию.

## Ключевые термины

Ветка под задачу, имя ветки, атомарный коммит, сообщение коммита, `git switch -c`, `git diff`, `git show`, `git log --stat`, диапазон `main..HEAD`, случайное изменение, `git restore`, соответствие базы и ветки.
