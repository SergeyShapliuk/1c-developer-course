# Практика. Счётчик, который помнит нажатия

## Перед началом

Запустите конфигуратор учебной конфигурации **«Управление строительной компанией с логистикой»**.

В дереве конфигурации откройте обработку `УчебнаяКонсоль` (синоним «Учебная консоль»), затем её форму, а в редакторе формы — вкладку **Модуль**. Весь код занятия пишем в этом модуле, в процедуре `Выполнить` и в процедурах, которые добавим рядом.

После каждой правки кода порядок один и тот же:

1. Сохраните конфигурацию — `Ctrl+S`.
2. Запустите приложение — `F5`.
3. В разделе **Разработка** откройте «Учебную консоль».
4. Нажмите кнопку **Выполнить** и прочитайте сообщения.

Сообщения выводятся в служебное окно внизу приложения. Если окно закрыто, оно появится само при первом сообщении.

## Шаг 1. Добавьте реквизит формы «Счётчик»

Реквизит формы — это данные, которые принадлежат форме и могут быть показаны пользователю.

1. Откройте форму обработки `УчебнаяКонсоль` и перейдите на вкладку **Реквизиты**.
2. Нажмите кнопку **Добавить реквизит** (зелёный плюс над списком).
3. В палитре свойств задайте **Имя** — `Счётчик`.
4. Задайте **Тип** — `Число`, **Длина** — `10`, **Точность** — `0`.
5. Перетащите реквизит `Счётчик` из списка реквизитов на форму (левая панель редактора формы). На форме появится поле.
6. Выделите это поле и в палитре свойств поставьте флажок **Только просмотр**: значение будет менять код, а не пользователь.

**Проверка:** на вкладке **Реквизиты** есть `Счётчик` типа `Число`, и на форме появилось поле, которое нельзя редактировать вручную.

## Шаг 2. Процедура без параметров, которая видит реквизит

Теперь напишем процедуру, которая увеличивает `Счётчик`. Параметров у неё не будет вообще.

Перейдите на вкладку **Модуль** и приведите его к такому виду:

```bsl
&НаКлиенте
Процедура Выполнить(Команда)
	
	УвеличитьСчётчик();
	
КонецПроцедуры

&НаКлиенте
Процедура УвеличитьСчётчик()
	
	// Счётчик — реквизит формы, он часть контекста формы.
	// Поэтому процедура видит его без параметра.
	Счётчик = Счётчик + 1;
	
КонецПроцедуры
```

Сохраните, запустите, нажмите **Выполнить** четыре раза. В поле на форме вы увидите `1`, `2`, `3`, `4`.

Разберём, почему это работает. Процедура `УвеличитьСчётчик` принадлежит форме. Реквизит `Счётчик` тоже принадлежит форме. Всё, что принадлежит форме, доступно её процедурам напрямую — это и называется контекстом формы.

**Проверка:** значение в поле растёт на единицу при каждом нажатии кнопки.

## Шаг 3. Переменная модуля

Теперь сделаем счётчик, которого пользователь не увидит.

В самое начало модуля, **выше первой процедуры**, добавьте строку объявления, а в `Выполнить` — работу с переменной:

```bsl
Перем ЧислоВызовов;

&НаКлиенте
Процедура Выполнить(Команда)
	
	УвеличитьСчётчик();
	
	// Если переменная ещё ничего не хранит, в ней Неопределено (занятие 12).
	Если НЕ ЗначениеЗаполнено(ЧислоВызовов) Тогда
		ЧислоВызовов = 0;
	КонецЕсли;
	
	ЧислоВызовов = ЧислоВызовов + 1;
	Сообщить("Процедура Выполнить вызвана раз: " + Строка(ЧислоВызовов));
	
КонецПроцедуры
```

Сохраните, запустите, нажмите **Выполнить** три раза. В сообщениях появятся `1`, `2`, `3`.

Сравните два счётчика. Оба помнят нажатия, но `Счётчик` виден на форме, а `ЧислоВызовов` — нет: его значение можно узнать только через `Сообщить`. Закройте приложение и запустите заново: оба обнулятся, потому что переменная модуля и реквизит формы живут, пока открыта форма.

**Проверка:** число в сообщении увеличивается с каждым нажатием, а на форме этой переменной нет.

## Шаг 4. Локальная переменная и ошибка компиляции

Теперь намеренно сделаем ошибку, чтобы увидеть её своими глазами.

1. Добавьте локальную переменную внутрь `УвеличитьСчётчик` и попробуйте вывести её из `Выполнить`:

```bsl
&НаКлиенте
Процедура Выполнить(Команда)
	
	УвеличитьСчётчик();
	Сообщить("Шаг прибавки: " + Строка(ШагПрибавки)); // так нельзя
	
КонецПроцедуры

&НаКлиенте
Процедура УвеличитьСчётчик()
	
	ШагПрибавки = 1; // локальная переменная процедуры УвеличитьСчётчик
	Счётчик = Счётчик + ШагПрибавки;
	
КонецПроцедуры
```

2. Выполните **Конфигурация → Проверка → Синтаксический контроль**.
3. Прочитайте сообщение об ошибке: платформа сообщает, что переменная `ШагПрибавки` не определена. Обратите внимание на момент: ошибку нашли при проверке, приложение даже не запускалось.

Теперь исправим правильно. Значение, которое нужно обеим процедурам, надо **вернуть из функции и передать параметром** — так, как мы делали на занятии 15:

```bsl
&НаКлиенте
Процедура Выполнить(Команда)
	
	Шаг = ПолучитьШагПрибавки();
	УвеличитьСчётчик(Шаг);
	Сообщить("Шаг прибавки: " + Строка(Шаг));
	
КонецПроцедуры

&НаКлиенте
Функция ПолучитьШагПрибавки()
	
	Возврат 1;
	
КонецФункции

&НаКлиенте
Процедура УвеличитьСчётчик(Шаг)
	
	Счётчик = Счётчик + Шаг;
	
КонецПроцедуры
```

Снова выполните синтаксический контроль — ошибок быть не должно. Сохраните, запустите, нажмите **Выполнить**.

**Проверка:** вы видели текст ошибки о неопределённой переменной, а после правки синтаксический контроль проходит без замечаний.

## Шаг 5. Явная ссылка ЭтаФорма

Замените в `УвеличитьСчётчик` короткое обращение на явное:

```bsl
&НаКлиенте
Процедура УвеличитьСчётчик(Шаг)
	
	ЭтаФорма.Счётчик = ЭтаФорма.Счётчик + Шаг;
	
КонецПроцедуры
```

Сохраните, запустите, нажмите **Выполнить**. Поведение не изменилось: значение растёт точно так же. `ЭтаФорма.Счётчик` и `Счётчик` — одно и то же.

Зачем тогда длинная запись? Представьте, что у процедуры появился параметр с именем `Счётчик`. Тогда короткое имя внутри процедуры означало бы параметр, а реквизит формы остался бы недоступен. Явная запись такой путаницы не допускает.

**Проверка:** код с `ЭтаФорма.Счётчик` работает так же, как короткий вариант.

## Шаг 6. Выберите область видимости сами

Заполните последнюю колонку. Отвечайте, не подсматривая в теорию.

| Задача | Что выбрать |
| --- | --- |
| Показать пользователю количество обработанных позиций | |
| Запомнить между нажатиями кнопки, сколько раз запускали расчёт, не показывая это | |
| Хранить промежуточную сумму внутри одного расчёта | |
| Хранить наименование склада, которое пользователь выбирает на форме | |

Верные направления: показать пользователю — реквизит формы; помнить, но не показывать — переменная модуля; промежуточное значение внутри одного расчёта — локальная переменная; пользователь выбирает на форме — реквизит формы.

## Проверка результата

Занятие пройдено, если выполняются четыре условия:

1. На форме есть реквизит `Счётчик`, и его значение растёт при нажатии кнопки.
2. В модуле объявлена переменная `ЧислоВызовов`, и она помнит число вызовов.
3. Вы видели сообщение синтаксического контроля об обращении к чужой локальной переменной и исправили код через функцию и параметр.
4. Вы можете объяснить, почему процедура формы видит реквизит формы без параметров.
