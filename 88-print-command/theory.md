# Теория. Команда печати

## Какую задачу мы решаем

После занятия 87 заявку можно напечатать, но только из её формы. Утром снабженец согласует пять заявок и отправляет их поставщикам. Для каждой он открывает журнал, находит заявку, открывает форму, нажимает **Печать заявки**, закрывает форму. Пять открытий формы ради пяти листов.

Он просит кнопку печати прямо в журнале: выделил строку — напечатал. Можно добавить ещё одну команду формы в форму списка и скопировать в неё код. Но тогда печать заявки окажется в двух местах, а на следующем экране, где покажут заявки, появится третья копия.

Печать — действие не над формой, а над **документом**. Ей нужна команда, которая принадлежит документу и появляется везде, где документ виден.

## Три вида команд — снова

На занятиях 23 и 34 мы различали три вида команд.

| Вид | Где описана | Где видна |
| --- | --- | --- |
| Команда формы | в одной форме | только в этой форме |
| Команда объекта | в объекте конфигурации, в ветке **Команды** | во всех формах, где уместна, — по её настройкам |
| Общая команда | в ветке **Общие → Общие команды** | там, где подходит её параметр, у любых объектов |

До сих пор мы создавали только команды формы. Печать заявки — первая команда объекта.

## Параметр команды

Команда объекта должна знать, **какую** заявку печатать. Для этого у неё есть **параметр команды** и два свойства.

| Свойство | Значение для печати заявки | Смысл |
| --- | --- | --- |
| **Тип параметра команды** | `ДокументСсылка.ЗаявкаНаМатериалы` | команда работает с заявками |
| **Режим использования параметра** | **Одиночный** | команда получает одну заявку |

Платформа сама находит значение параметра в форме, откуда вызвана команда. В форме документа это ссылка на открытый документ. В форме списка — ссылка на текущую строку журнала. Разработчику не нужно писать, откуда взять заявку: тип параметра говорит платформе, что искать.

Режим **Множественный** передаёт массив ссылок — все выделенные строки списка. Он понадобится на занятии 89.

## Где команда появляется

Свойство **Группа** команды объекта говорит, в какую панель её встроить. Для печати подходит **Командная панель формы** — группа **Важное**: команда появится на панели формы документа и на панели формы списка, рядом со стандартными кнопками.

Мы не перетаскиваем команду ни в одну форму. Она встраивается сама во все формы, где есть значение её параметра. Появится новая форма заявки — команда окажется и в ней.

## Модуль команды

Код команды объекта лежит в **модуле команды**. Платформа вызывает в нём обработчик:

```bsl
&НаКлиенте
Процедура ОбработкаКоманды(ПараметрКоманды, ПараметрыВыполненияКоманды)

КонецПроцедуры
```

- `ПараметрКоманды` — значение параметра: ссылка на заявку.
- `ПараметрыВыполненияКоманды` — сведения о вызове. Свойство `Источник` — форма, из которой нажали команду.

Обработчик клиентский: команду нажимает пользователь, и результат — окно с листом — показывается на клиенте. Данные и макет нужны на сервере, поэтому в модуле команды рядом с обработчиком пишут серверную функцию, которая вызывает модуль менеджера и возвращает табличный документ.

## Тонкая команда

Команда печати только связывает три вещи: какую заявку взять, где собрать лист, как его показать. Сам лист по-прежнему собирает `ПечатнаяФормаЗаявки` модуля менеджера (занятие 87). Поэтому, переходя от команды формы к команде объекта, мы не переписываем ни строчки печатной формы — меняется только то, откуда её вызывают.

Правило «не печатать несохранённую заявку» переезжает в модуль команды. Данных формы команда объекта по-прежнему не читает — она работает с записанным документом (занятие 34). Но спросить источник, есть ли в нём несохранённые изменения, она может. В форме документа `Источник` — это форма заявки, и у неё есть свойство `Модифицированность`. В журнале `Источник` — форма списка, где несохранённых изменений заявки не бывает. Пустая ссылка значит, что заявка ни разу не записана.

## Общая команда

Если бы одна и та же печать понадобилась нескольким видам документов — например, «лист согласования» для заявки, поступления и передачи, — команду сделали бы **общей**: тип её параметра составной, из нескольких ссылочных типов. Печать заявки нужна только заявке, поэтому её место — в самом документе.

## Где живёт логика

| Что | Где | Почему |
| --- | --- | --- |
| Оформление листа | макет `ПФ_Заявка` | без изменений с занятия 87 |
| Заполнение листа | модуль менеджера документа | без изменений: функцию вызывает новый источник |
| Какую заявку печатать и как показать лист | модуль команды объекта | команда документа, видна во всех его формах |
| Проверка «не печатать несохранённое» | модуль команды, по `Источник` | форма документа больше не владеет печатью |

## Что важно запомнить

1. Команда объекта принадлежит объекту конфигурации и встраивается во все его формы сама — по своей группе и параметру.
2. Тип параметра команды говорит платформе, какое значение взять из формы: в форме документа — сам документ, в журнале — текущую строку.
3. Режим **Одиночный** передаёт одну ссылку, **Множественный** — массив выделенных.
4. Код команды объекта — в модуле команды, в клиентском обработчике `ОбработкаКоманды(ПараметрКоманды, ПараметрыВыполненияКоманды)`; `ПараметрыВыполненияКоманды.Источник` — форма, откуда вызвана команда.
5. Команда печати тонкая: лист собирает модуль менеджера, команда только вызывает его на сервере и показывает результат.
6. Общая команда нужна, когда одно действие подходит нескольким видам объектов.
