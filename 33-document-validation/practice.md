# Практика. Заявка, которую нельзя записать неправильно

## Перед началом

Запустите конфигуратор учебной конфигурации **«Управление строительной компанией с логистикой»**.

Понадобится документ `ЗаявкаНаМатериалы` с реквизитами шапки `ОбъектСтроительства`, `Ответственный`, `Приоритет`, `Комментарий` из занятия 29 и с табличной частью `Материалы` из занятия 31, выведенной на форму. Если чего-то из этого нет, вернитесь к занятиям 29 и 31.

Понадобятся обработчики пересчёта суммы из занятия 32: они остаются на месте, мы их не меняем. Весь новый код занятия ложится в другой модуль — в модуль объекта документа, который мы сегодня откроем впервые.

После каждой правки: `Ctrl+S`, затем `F5` — платформа предложит обновить конфигурацию базы данных, согласитесь. В запущенном приложении откройте раздел **Логистика** и выберите журнал **Заявки на материалы**.

Кнопок и команд на этом занятии мы не добавляем — команды документа разберём в занятии 34. Сегодня вся работа идёт на свойствах реквизитов и на двух обработчиках модуля объекта.

## Шаг 1. Включите проверку заполнения у реквизитов шапки

1. Откройте **Документы → ЗаявкаНаМатериалы**, перейдите на вкладку **Данные**.
2. Выделите реквизит `ОбъектСтроительства`, найдите в палитре свойств свойство **Проверка заполнения** и выберите значение **Выдавать ошибку**.
3. То же сделайте для реквизита `Ответственный`.
4. Реквизиты `Приоритет` и `Комментарий` оставьте со значением **Не проверять**: приоритет у заявки имеет значение по умолчанию, а комментарий необязателен по смыслу.
5. Раскройте табличную часть `Материалы`, выделите реквизит `Материал` и тоже поставьте **Выдавать ошибку**.
6. `Ctrl+S`, `F5` и попробуйте в приложении записать новую заявку, ничего не заполнив.

Ни строки кода — а платформа уже отказывается записывать заявку и подсвечивает незаполненные поля красным. Это и есть правило «что платформа умеет свойством, кодом не пишут».

Реквизиту `Количество` свойство не поможет: ноль для числа — заполненное значение, и проверка его пропустит. Этим займётся код.

**Проверка:** пустая заявка не записывается, в сообщениях перечислены незаполненные поля, и они подсвечены на форме.

## Шаг 2. Откройте модуль объекта документа

1. В окне редактирования документа `ЗаявкаНаМатериалы` перейдите на вкладку **Прочее**.
2. Нажмите кнопку **Модуль объекта**. Откроется пустой модуль — это и есть место для правил самого документа.
3. Обратите внимание: в этом модуле нет вкладок с реквизитами и элементами, как у формы. Здесь только код.

Сравните с модулем формы из занятия 32. Там у каждого события была кнопка с лупой в палитре свойств. **В модуле объекта лупы нет**: обработчики здесь набирают вручную, поэтому имя и список параметров должны совпадать с ожидаемыми платформой до буквы. Сверять их удобно по синтакс-помощнику: **Справка → Синтакс-помощник**, раздел про документы и их модуль объекта.

Если имя обработчика написать с опечаткой, синтаксический контроль промолчит: с точки зрения платформы это просто процедура, которую никто не вызывает. Поэтому в конце занятия мы проверим отладчиком, что обработчики действительно срабатывают.

**Проверка:** модуль объекта документа `ЗаявкаНаМатериалы` открыт и пуст.

## Шаг 3. Проверьте строки табличной части

1. Наберите в модуле объекта обработчик:

```bsl
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)

	Для Каждого СтрокаМатериала Из ЭтотОбъект.Материалы Цикл

		Если СтрокаМатериала.Количество <= 0 Тогда
			Сообщить("Строка " + Строка(СтрокаМатериала.НомерСтроки) + ": количество должно быть больше нуля");
			Отказ = Истина;
		КонецЕсли;

	КонецЦикла;

КонецПроцедуры
```

2. `Ctrl+S` и **Конфигурация → Проверка → Синтаксический контроль**.
3. `F5`, откройте новую заявку, заполните шапку, добавьте строку с материалом «Цемент М500» и количеством `0`, нажмите **Записать**.

Разберите код по частям. Цикл `Для Каждого` по `ЭтотОбъект.Материалы` — тот же обход коллекции строк, что в занятии 32, только документ здесь не реквизит формы `Объект`, а сам `ЭтотОбъект`. Директивы компиляции перед процедурой нет: модуль объекта целиком серверный, выбирать не из чего.

`Отказ = Истина` ставится внутри `Если` и больше не сбрасывается. Присвоение не прерывает цикл — и это правильно: пользователь должен увидеть сразу все плохие строки, а не исправлять их по одной.

**Проверка:** заявка с нулевым количеством не записывается, в сообщениях указан номер строки.

## Шаг 4. Привяжите сообщение к строке таблицы

1. Добавьте в модуль объекта процедуру вывода сообщения:

```bsl
Процедура СообщитьОбОшибкеСтроки(НомерСтроки, ИмяРеквизита, ТекстОшибки)

	Сообщение = Новый СообщениеПользователю;
	Сообщение.Текст = "Строка " + Строка(НомерСтроки) + ": " + ТекстОшибки;
	Сообщение.Поле = "Материалы[" + Строка(НомерСтроки - 1) + "]." + ИмяРеквизита;
	Сообщение.УстановитьДанные(ЭтотОбъект);
	Сообщение.Сообщить();

КонецПроцедуры
```

2. Перепишите обработчик проверки так, чтобы он пользовался этой процедурой и проверял обе ошибки строки:

```bsl
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)

	Для Каждого СтрокаМатериала Из ЭтотОбъект.Материалы Цикл

		Если Не ЗначениеЗаполнено(СтрокаМатериала.Материал) Тогда
			СообщитьОбОшибкеСтроки(СтрокаМатериала.НомерСтроки, "Материал", "не выбран материал");
			Отказ = Истина;
		КонецЕсли;

		Если СтрокаМатериала.Количество <= 0 Тогда
			СообщитьОбОшибкеСтроки(СтрокаМатериала.НомерСтроки, "Количество", "количество должно быть больше нуля");
			Отказ = Истина;
		КонецЕсли;

	КонецЦикла;

КонецПроцедуры
```

3. `Ctrl+S`, синтаксический контроль, `F5`.
4. В приложении создайте заявку из двух строк: в первой материал «Песок речной» и количество `0`, во второй материал не выбран, количество `5`. Нажмите **Записать**.
5. Щёлкните по сообщению об ошибке в нижней части окна — курсор встанет в ту самую ячейку таблицы.

Два места в коде заслуживают внимания. `УстановитьДанные(ЭтотОбъект)` связывает сообщение с документом: без этой строки текст появится, а подсветки ячейки не будет. А в пути `"Материалы[" + Строка(НомерСтроки - 1) + "]"` стоит именно `НомерСтроки - 1`, потому что индекс в пути считается от нуля, а `НомерСтроки` из занятия 31 — от единицы. В тексте же сообщения остаётся сам `НомерСтроки`: пользователь читает номер, который видит в таблице.

Проверку материала мы написали кодом, хотя в шаге 1 включили у него и свойство **Проверка заполнения**. Так сделано сознательно: платформенное сообщение скажет «не заполнен материал», а наше ещё и назовёт номер строки. Увидев в приложении оба сообщения, вы наглядно сравните, что даёт свойство и что — код.

**Проверка:** на каждую плохую строку выводится своё сообщение с номером строки, и щелчок по сообщению ведёт в нужную ячейку.

## Шаг 5. Запретите пустую заявку в обработчике `ПередЗаписью`

1. Наберите в модуле объекта второй обработчик:

```bsl
Процедура ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)

	ЭтотОбъект.Комментарий = СокрЛП(ЭтотОбъект.Комментарий);

	Если ЭтотОбъект.Материалы.Количество() = 0 Тогда
		Сообщить("В заявке нет ни одной строки материалов. Запись отменена.");
		Отказ = Истина;
	КонецЕсли;

КонецПроцедуры
```

2. `Ctrl+S`, синтаксический контроль, `F5`.
3. Создайте заявку, заполните шапку, не добавляйте ни одной строки и нажмите **Записать**.

Правило «заявка без материалов не имеет смысла» мы положили именно в `ПередЗаписью`, а не рядом с проверкой строк. Причина в теории: `ОбработкаПроверкиЗаполнения` вызывается при интерактивной записи, а `ПередЗаписью` — при любой, включая запись из кода. Когда в занятии 36 заявка начнёт участвовать в программных сценариях, это правило продолжит работать.

Первая строка обработчика — не проверка, а правка данных: `СокрЛП` из занятия 12 убирает случайные пробелы в начале и конце комментария. `ПередЗаписью` годится и для такой работы — это последний момент, когда документ ещё можно поправить.

Третий параметр обработчика относится к механизму, который включим на этапе 4. Платформа требует его в объявлении, а мы его не используем.

**Проверка:** заявка без строк не записывается, в сообщении сказано, что запись отменена.

## Шаг 6. Проверьте негативный сценарий целиком

1. В приложении создайте новую заявку и нажмите **Записать**, ничего не заполнив. Ожидаемо: сообщения про объект строительства, ответственного и про отсутствие строк.
2. Заполните объект строительства «ЖК Северный» и ответственного «Иванов Иван Петрович», снова нажмите **Записать**. Остаётся сообщение про отсутствие строк.
3. Добавьте строку, материал не выбирайте, количество оставьте нулевым. Нажмите **Записать**: придут сообщения и про материал, и про количество первой строки.
4. Выберите материал «Цемент М500» — цена подставится обработчиком из занятия 32. Нажмите **Записать**: осталось сообщение только про количество.
5. Введите количество `20`, нажмите `Tab`, затем **Записать и закрыть**.

Пройдя этот сценарий, вы проверили главное: **каждая ошибка данных закрывает запись, и ни одно сообщение не появляется зря**. Негативный сценарий — обязательная часть проверки любой валидации. Если проверить только правильную заявку, вы узнаете лишь то, что код не падает, но не то, что он работает.

**Проверка:** заявка записалась только после того, как исправлена последняя ошибка.

## Шаг 7. Посмотрите отладчиком, в каком порядке идут проверки

1. В модуле объекта поставьте точку останова `F9` на первой строке `ОбработкаПроверкиЗаполнения` и на первой строке `ПередЗаписью`.
2. `F5`, откройте записанную заявку, измените количество в строке и нажмите **Записать**.
3. Исполнение остановится сначала в `ОбработкаПроверкиЗаполнения`. Нажмите `F11` несколько раз и посмотрите в окне **Табло** значение `СтрокаМатериала.Количество`.
4. Продолжите исполнение — следующая остановка будет в `ПередЗаписью`.
5. Снимите точки останова повторным `F9`.

Порядок именно такой: сначала платформа спрашивает «эти данные приемлемы?», и только если никто не возразил, начинает запись и вызывает `ПередЗаписью`. Приёмы отладки те же, что в занятии 24, — изменился только модуль, в котором вы стоите.

Заодно это надёжная проверка имён: если обработчик назван с опечаткой, точка останова просто не сработает.

**Проверка:** оба обработчика останавливают исполнение, и `ОбработкаПроверкиЗаполнения` срабатывает раньше `ПередЗаписью`.

## Проверка результата

Занятие пройдено, если выполняются шесть условий:

1. У реквизитов `ОбъектСтроительства`, `Ответственный` и у реквизита `Материал` табличной части включено свойство **Проверка заполнения** со значением **Выдавать ошибку**.
2. В модуле объекта документа `ЗаявкаНаМатериалы` есть обработчики `ОбработкаПроверкиЗаполнения` и `ПередЗаписью`.
3. Заявку со строкой, где количество равно нулю или не выбран материал, записать невозможно.
4. Сообщение об ошибке называет номер строки, а щелчок по нему ведёт в нужную ячейку таблицы.
5. Заявка без строк материалов не записывается.
6. Правильно заполненная заявка записывается без сообщений.
