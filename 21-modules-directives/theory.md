# Теория. Модули и директивы компиляции

## Что такое модуль

**Модуль** — это файл с кодом, привязанный к объекту конфигурации. Код в 1С не лежит сам по себе: он всегда принадлежит модулю, а модуль — какому-то объекту.

До сих пор мы писали в одном месте — в модуле формы обработки `УчебнаяКонсоль`. Для учебных примеров это удобно, для настоящей разработки негодно: функцию, нужную в десяти формах, нельзя скопировать десять раз.

## Виды модулей

| Модуль | Где живёт | Когда исполняется | Зачем нужен |
| --- | --- | --- | --- |
| Модуль управляемого приложения | Корень конфигурации | При запуске и завершении сеанса | Начальные настройки, проверки при входе |
| Общий модуль | **Общие → Общие модули** | Когда его процедуру вызвали | Процедуры, нужные всей конфигурации |
| Модуль объекта | У справочника | При работе с одним элементом | Поведение элемента: проверки перед записью |
| Модуль менеджера | У справочника | При работе со справочником в целом | Действия над справочником, а не над элементом |
| Модуль формы | У формы | Когда форма открыта | Поведение одной формы — тот модуль, в котором мы писали |
| Модуль команды | У команды | Когда команду нажали | Короткий код запуска действия |

Новичок в этом списке — **общий модуль**. Остальные привязаны к чему-то одному, а он ни к чему: это склад процедур для всей конфигурации.

## Общий модуль и его флаги

Общий модуль создают в узле **Общие → Общие модули**. Затем в палитре свойств включают флаги — они решают, **где** код модуля может исполняться.

- **Клиент (управляемое приложение)** — процедуры компилируются для клиента, то есть для приложения у пользователя.
- **Сервер** — процедуры компилируются для сервера, где лежат данные.
- **Вызов сервера** — разрешает вызывать серверные процедуры модуля из клиентского кода. Без этого флага вызов с клиента не скомпилируется: платформа скажет, что метод недоступен.
- **Глобальный** — делает процедуры доступными без имени модуля: `РассчитатьСумму(...)` вместо `УчебныеФункции.РассчитатьСумму(...)`. Применяют редко: имена из разных модулей начинают спорить, и непонятно, откуда взялась процедура.

Рабочая комбинация — **Сервер** и **Вызов сервера** для серверного модуля, только **Клиент (управляемое приложение)** для клиентского.

## Экспорт

Создать процедуру в общем модуле недостаточно. По умолчанию она видна **только внутри своего модуля**. Чтобы вызвать её извне, в объявление добавляют `Экспорт`:

```bsl
Функция РассчитатьСумму(Количество, Цена) Экспорт
	Возврат Количество * Цена;
КонецФункции
```

Теперь к ней обращаются через имя модуля:

```bsl
Итог = УчебныеФункции.РассчитатьСумму(20, 12.50);
```

Без `Экспорт` тот же вызов не скомпилируется. Это полезное правило: разработчик сам решает, что в модуле публичное, а что внутренняя кухня.

## Директивы компиляции

**Директива компиляции** — строка со знаком `&` перед объявлением процедуры в модуле формы. Она говорит, где процедуру исполнять.

| Директива | Что доступно | Чего нет |
| --- | --- | --- |
| `&НаКлиенте` | Реквизиты формы, диалоги с пользователем, открытие форм | Менеджеры объектов, чтение и запись данных |
| `&НаСервере` | Реквизиты формы, работа с базой | Диалоги с пользователем, открытие форм |
| `&НаСервереБезКонтекста` | Работа с базой | Реквизиты формы, диалоги с пользователем |
| `&НаКлиентеНаСервереБезКонтекста` | Вычисления без контекста и без базы | И реквизиты формы, и база, и диалоги |

Про `&НаСервереБезКонтекста` отдельно. Такая процедура **не видит реквизитов формы** — для неё их не существует. Поэтому всё нужное передают параметрами, а результат она возвращает значением. Зато вызов дешевле: платформе не надо везти данные формы на сервер и обратно.

На занятии 18 директива `&НаСервере` была дана как пометка «этот код выполняется на сервере». Теперь понятно, что за ней стоит: `ТаблицаЗначений` недоступна в тонком клиенте, поэтому процедуру `ПостроитьТаблицуМатериалов` пришлось объявить серверной — иначе платформа не нашла бы этот тип.

## Куда что складывать

1. Общие вычисления, нужные больше чем в одном месте → общий модуль.
2. Работа с данными базы → сервер.
3. Диалоги с пользователем → клиент.
4. Код, нужный только одной форме → модуль этой формы.

Если функция понадобилась и в форме справочника, и в обработке — её место в общем модуле. Копировать код в два модуля нельзя: одну копию обязательно забудут исправить.

## Что важно запомнить

1. Код в 1С всегда лежит в модуле, а модуль привязан к объекту конфигурации.
2. Общий модуль — склад процедур для всей конфигурации; флаги решают, где код исполняется.
3. Флаг **Вызов сервера** разрешает вызывать серверные процедуры модуля с клиента.
4. Без `Экспорт` процедура видна только внутри своего модуля.
5. Директива компиляции задаёт место исполнения процедуры модуля формы.
6. `&НаСервереБезКонтекста` не видит реквизитов формы, зато вызов дешевле.
