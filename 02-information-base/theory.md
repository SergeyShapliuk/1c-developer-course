# Теория. Информационная база и два режима работы

## Информационная база

**Информационная база** (сокращённо ИБ) — это рабочий экземпляр прикладного решения. В ней лежат вместе две вещи:

- **конфигурация** — описание того, что может существовать в системе;
- **данные** — то, что уже введено пользователями.

Это ключевая особенность 1С: конфигурация хранится не отдельным файлом рядом с базой, а внутри самой базы. Поэтому, когда разработчик меняет структуру решения, платформа должна перестроить таблицы данных под новое описание.

Например, вы добавили в описание клиента поле «Телефон» — платформа при обновлении добавит соответствующий столбец в таблицу клиентов. Если поле, наоборот, удалить, платформа предупредит, что данные из него будут потеряны. Структурное изменение в 1С — это всегда операция над данными, а не просто правка описания.

На занятии 1 платформа была механизмом, а конфигурация — проектом решения. Информационная база — работающий экземпляр: механизм запущен, проект загружен, данные накапливаются.

## Файловый и клиент-серверный варианты

Информационную базу можно разместить двумя способами.

**Файловый вариант.** База — это обычный каталог на диске. Главный файл в нём называется `1Cv8.1CD`: внутри него и конфигурация, и все данные. Ничего доустанавливать не нужно — достаточно самой платформы. Файловый вариант рассчитан на небольшое число пользователей и прекрасно подходит для учёбы.

**Клиент-серверный вариант.** Данные хранит отдельная **СУБД** — система управления базами данных, например PostgreSQL или Microsoft SQL Server. Между СУБД и пользователями работает **сервер «1С:Предприятия»**: он выполняет серверный код, управляет соединениями и блокировками. Так устроены рабочие базы компаний, где одновременно работают десятки и сотни человек.

| Признак | Файловый вариант | Клиент-серверный вариант |
| --- | --- | --- |
| Где данные | Каталог с файлом `1Cv8.1CD` | Таблицы СУБД |
| Что нужно установить | Только платформу | Платформу, сервер «1С:Предприятия», СУБД |
| Сколько пользователей | Единицы | Десятки и сотни |
| Типичное применение | Учёба, небольшие задачи, разработка | Рабочие базы предприятий |

Для курса мы берём **файловый вариант**: он создаётся за минуту и не требует настройки сервера. Вся логика, которую мы напишем, одинаково работает и в клиент-серверном варианте.

## Почему нельзя править файлы базы вручную

Файл `1Cv8.1CD` имеет служебный внутренний формат: это не текст и не таблица, которую можно открыть и поправить. Там лежат страницы данных, индексы и служебные структуры, связанные между собой ссылками.

Если открыть такой файл текстовым редактором и сохранить, редактор перекодирует байты по своим правилам — и база перестанет открываться. Восстановить её после этого обычно невозможно.

Правило простое: **содержимое каталога информационной базы меняет только платформа**. Вы не создаёте, не переименовываете и не удаляете файлы внутри него руками. Копировать каталог целиком — можно, но только когда база закрыта (об этом ниже).

## Два режима запуска

Одну и ту же информационную базу платформа открывает в двух разных режимах.

| Режим | Для кого | Что делают |
| --- | --- | --- |
| **Конфигуратор** | Разработчик, администратор | Меняют структуру конфигурации, формы, модули, права; обновляют конфигурацию базы данных; отлаживают код. |
| **1С:Предприятие** | Обычный пользователь | Вводят и просматривают данные, проводят документы, формируют отчёты. |

Конфигуратор — это мастерская, а «1С:Предприятие» — готовое рабочее место. Пользователь обычно не имеет доступа к изменению метаданных. Разработчик сначала вносит изменения в Конфигураторе, обновляет конфигурацию базы данных, а затем проверяет результат в режиме «1С:Предприятие».

Переключение между режимами — обычная часть работы. На каждом занятии курса вы будете делать это по нескольку раз: что-то изменили в мастерской, проверили на рабочем месте, вернулись в мастерскую.

## Тонкий и толстый клиент

Режим «1С:Предприятие» запускается одним из двух клиентских приложений.

**Тонкий клиент** только отображает формы и передаёт действия пользователя на сервер, а вычисления выполняются на сервере. Это основной режим современных решений: он экономно расходует сеть и не требует мощного компьютера у пользователя.

**Толстый клиент** выполняет значительную часть кода на компьютере пользователя и имеет прямой доступ к данным. Он нужен для старых решений, написанных до появления управляемого интерфейса, и для некоторых административных операций. Подробно разницу между клиентом и сервером разберём на занятии 22 — там это станет важно для написания кода.

## Резервная копия

Разработчик регулярно ломает структуру базы — это нормальная часть обучения. Поэтому резервная копия нужна не «когда-нибудь», а привычно.

Есть два способа.

**Копирование каталога.** Закройте базу во всех режимах и скопируйте её каталог в другое место. Способ работает только для файлового варианта и только при закрытой базе: копия работающей базы может оказаться нецелостной.

**Выгрузка информационной базы — правильный способ.** В Конфигураторе выберите **Администрирование → Выгрузить информационную базу** и укажите файл с расширением `.dt`. Платформа соберёт в один файл и конфигурацию, и все данные. Обратная операция — **Администрирование → Загрузить информационную базу**: она заменяет содержимое базы тем, что лежит в файле `.dt`.

Выгрузка не зависит от варианта размещения: файл `.dt`, сделанный из файловой базы, загружается и в клиент-серверную.

Правило курса: **делайте выгрузку перед каждым опасным изменением структуры** — перед удалением объектов, сменой типов данных и любым обновлением, в котором вы не уверены. В имя файла удобно добавлять дату, чтобы копии не перезаписывали друг друга.

## Что важно запомнить

1. Информационная база хранит конфигурацию и данные вместе, поэтому изменение структуры перестраивает таблицы данных.
2. Файловый вариант — каталог с файлом `1Cv8.1CD`, клиент-серверный — данные в СУБД плюс сервер «1С:Предприятия»; для курса берём файловый.
3. Содержимое каталога базы меняет только платформа; править файлы вручную нельзя.
4. Конфигуратор — режим разработчика, «1С:Предприятие» — режим пользователя.
5. Правильная резервная копия — выгрузка в файл `.dt` через **Администрирование → Выгрузить информационную базу**.
