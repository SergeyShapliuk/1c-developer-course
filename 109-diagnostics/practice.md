# Практика. «Недостаёт 0»

## Перед началом

Понадобятся учебная база, совпадающая с `main` после занятия 108, клон Орлова, обработка `ТестыСнабжения` и конспект.

1. Запустите конфигуратор учебной базы под пользователем «Администратор». Выгрузите конфигурацию в `src\cf` и убедитесь, что `git status` чист.
2. Выгрузите базу в новый файл `.dt`: на шаге 2 конфигурация будет загружена из файлов.
3. Запустите **Разработка → Тесты снабжения** и убедитесь, что все проверки пройдены. Это исходное состояние: до правки Орлова всё работает.

## Шаг 1. Орлов отправляет правку

Во втором окне, в клоне Орлова:

```bash
git switch main
git pull
```

Задача Орлова — сделать сообщение о нехватке понятнее: назвать склад. Откройте `src/cf/Documents/ПередачаМатериалов/Ext/ObjectModule.bsl` и найдите процедуру `ПроверитьОстаткиМатериалов` (занятие 67).

1. Замените строку условия запроса `|	Остатки.КоличествоОстаток < 0";` на `|	Остатки.КоличествоОстаток <= 0";`. Это ошибка, которую Орлов сделал, «приводя условие в порядок»; повторите её точно.
2. Замените текст сообщения так, чтобы в нём был склад:

```bsl
		Сообщение.Текст = "Не хватает материала «" + Выборка.Материал + "» на складе «"
			+ Строка(Склад) + "»: недостаёт " + Строка(-Выборка.Остаток);
```

3. Сохраните файл. Орлов торопится и отправляет правку прямо в `main`, без ветки и pull request:

```bash
git add src/cf/Documents/ПередачаМатериалов/Ext/ObjectModule.bsl
git commit -m "Name warehouse in stock shortage message"
git push
```

**Проверка:** в `main` на сервере есть коммит Орлова `Name warehouse in stock shortage message`.

## Шаг 2. Получите изменения и запустите тесты

В первом окне:

```bash
git pull
git log --oneline -3
```

1. Загрузите конфигурацию из файлов `src\cf` в учебную базу и выполните `F7` — это правило занятия 100 для полученных изменений.
2. Запустите **Разработка → Тесты снабжения**.
3. Тест «Передача ровно остатка 10 проводится и оставляет 0» провален, в строке протокола — текст ошибки проведения. Остальные проверки пройдены.

Тест сделал воспроизведение за вас: минимальный пример уже есть — поступление `10`, передача `10`.

**Проверка:** после загрузки правки Орлова провалена ровно одна проверка — передача ровно остатка.

## Шаг 3. Зафиксируйте симптом

Теперь — то, что увидел бы Петров.

1. Под администратором сформируйте «Остатки на складах» по «Центральному складу» и выберите материал с небольшим целым остатком — например, песок или цемент. Запишите остаток.
2. Создайте передачу этого материала ровно на остаток с «Центрального склада» на «ЖК Северный» и нажмите **Провести**.
3. Проведение отклонено. Запишите сообщение дословно: «Не хватает материала «…» на складе «Центральный склад»: недостаёт 0».
4. Уменьшите количество на `1` и проведите: документ проводится. Отмените проведение и пометьте передачу на удаление.

Запишите в конспект, в файл `bugs/exact-balance.md`, симптом в формате отчёта об ошибке занятия 107. Подчеркните подсказку из текста сообщения: программа считает нехваткой нулевой остаток.

**Проверка:** симптом записан дословно; ошибка воспроизводится на «ровно остатке» и не воспроизводится на остатке минус один.

## Шаг 4. Выясните, когда это началось

1. Под администратором откройте журнал регистрации (занятие 96). Отберите события за сегодня по группе **Информационная база** и найдите событие обновления конфигурации базы данных, которое вы выполнили в шаге 2: пользователь «Администратор», время.
2. В репозитории посмотрите, что пришло в `main` после последней версии:

```bash
git log --oneline v1.1.0..main
```

В списке — слияния задач занятий 104 и 108, коммиты в `tests/regression.md` и последний — коммит Орлова. До шага 2 тесты проходили, значит, подозреваемый — то, что пришло последним `git pull`.

3. Сравните время обновления в журнале регистрации со временем коммита Орлова в `git log --format="%h %an %ad %s" -1` и запишите вывод в отчёт: симптом появился с обновлением, в которое вошёл коммит Орлова.

На рабочей базе этот шаг выглядел бы так же, только вместо вашего `git pull` в журнале было бы обновление рабочей базы новой версией, а список изменений давал бы диапазон между двумя тегами.

**Проверка:** в отчёте записаны время обновления конфигурации из журнала регистрации и коммит, вошедший в это обновление.

## Шаг 5. Найдите строку

Сообщение «недостаёт» выдаётся из запроса отрицательных остатков. Найдём, кто и когда менял его условие:

```bash
git log -S "КоличествоОстаток <= 0" --oneline
git blame -L "/КоличествоОстаток </,+1" src/cf/Documents/ПередачаМатериалов/Ext/ObjectModule.bsl
git show HEAD
```

`git log -S` нашёл один коммит — тот, где условие `<= 0` появилось. `git blame` показал строку условия, её автора — Орлова — и коммит. `git show` вывел коммит целиком: в нём две правки, и только одна из них нужна задаче Орлова. Вторая — изменение условия — к сообщению отношения не имеет.

**Проверка:** найдены коммит и строка, где появилось условие `<= 0`; в отчёте записано, что изменение условия не относится к задаче коммита.

## Шаг 6. Посмотрите на причину в отладчике

История уже указала строку. Отладчик покажет, почему она даёт такой симптом.

1. В конфигураторе откройте модуль объекта передачи и поставьте точку останова `F9` на строку `Сообщение = Новый СообщениеПользователю;` внутри цикла `Пока Выборка.Следующий() Цикл` процедуры `ПроверитьОстаткиМатериалов`.
2. Откройте свойства точки останова и задайте условие `Выборка.Остаток = 0`.
3. Запустите отладку `F5` и повторите передачу ровно остатка из шага 3. Выполнение остановилось на точке.
4. Нажмите `Shift+F9` и вычислите `Выборка.Остаток`: `0`. Затем вычислите `Запрос.Текст` и найдите в нём `<= 0`. Остаток после передачи — ноль, ноль удовлетворяет условию, и программа сообщает о нехватке нуля.
5. Откройте **Отладка → Стек вызовов**: `ПроверитьОстаткиМатериалов` вызвана из `ОбработкаПроведения`.
6. Продолжите выполнение `F5`, закройте передачу без проведения, снимите точку останова.

Теперь посмотрите, как отладчик помогает, когда известна только ошибка теста.

7. Включите **Отладка → Остановка по ошибке** и запустите под отладкой **Тесты снабжения**.
8. Отладчик остановится на строке `Передача.Записать(...)` процедуры `ПровестиПередачу` в момент исключения. По стеку вызовов видно, из какого теста пришёл вызов: `Тест_ПередачаРовноОстатка`. Продолжайте `F5`: следующие остановки будут в негативных тестах, где исключение ожидаемое.
9. Выключите остановку по ошибке и остановите отладку.

**Проверка:** условная точка остановилась только на нулевом остатке; `Shift+F9` показал условие `<= 0`; остановка по ошибке привела к строке проведения в тесте «ровно остатка».

## Шаг 7. Исправьте причину

```bash
git switch -c bugfix/exact-balance
```

1. В конфигураторе в запросе `ПроверитьОстаткиМатериалов` верните условие `Остатки.КоличествоОстаток < 0`. Новый текст сообщения со складом оставьте: он полезен и сделан по задаче.
2. `Ctrl+S`, `F7`, запустите тесты. Все проверки пройдены.
3. Повторите передачу ровно остатка из шага 3: документ проводится. Отмените проведение и пометьте передачу на удаление.
4. Проверьте, что исправление не сломало сам контроль: передача на остаток плюс один отклонена с сообщением «… на складе «Центральный склад»: недостаёт 1». Закройте без проведения.

Регрессионный тест для этой ошибки уже есть — именно он её поймал. Если бы теста не было, вы написали бы его в этом шаге, до исправления.

5. Выгрузите конфигурацию, закоммитьте и отправьте:

```bash
git diff
git add src/cf/Documents/ПередачаМатериалов/Ext/ObjectModule.bsl
git commit -m "Fix exact-balance transfer refused as shortage"
git push -u origin bugfix/exact-balance
```

**Проверка:** в ветке `bugfix/exact-balance` одна изменённая строка — условие `< 0`; все тесты пройдены.

## Шаг 8. Оформите pull request и слейте

1. В конспекте создайте `pr/exact-balance.md`: задача — ссылка на `bugs/exact-balance.md`; причина — условие `<= 0` в коммите «Name warehouse in stock shortage message»; исправление — возврат условия `< 0` при сохранении нового сообщения; как проверить — тест «ровно остатка» и ручная передача ровно остатка; регрессия — тест уже в наборе.
2. Слейте исправление:

```bash
git switch main
git pull
git merge --no-ff bugfix/exact-balance -m "Merge bugfix/exact-balance: exact balance transfer posts again"
git push
git branch -d bugfix/exact-balance
git push origin --delete bugfix/exact-balance
```

3. Выгрузите конфигурацию и убедитесь, что `git status` чист: база совпадает с `main`.

Версию сегодня не выпускаем: исправление войдёт в версию занятия 110 вместе с остальными изменениями после `1.1.0`.

**Проверка:** исправление в `main`, ветка удалена, база совпадает с `main`, тесты пройдены.

## Шаг 9. Разберите, как ошибка дошла до main

Допишите в `bugs/exact-balance.md` раздел «Разбор»:

1. Как ошибка попала в `main`: правка отправлена без ветки и pull request, ревью не было, тесты перед отправкой не запускались.
2. Какое правило это предотвратит: защита `main` на сервере команды — только через одобренный pull request; запуск `ТестыСнабжения` перед каждым слиянием.
3. Почему разбор не называет виноватого: та же ошибка могла случиться у любого, и защищает от неё правило, а не осторожность одного человека.

Закоммитьте конспект.

**Проверка:** в отчёте об ошибке есть разбор с двумя правилами работы.

## Проверка результата

Занятие пройдено, если выполняются шесть условий:

1. Ошибка передачи ровно остатка обнаружена обработкой тестов сразу после загрузки правки.
2. Симптом записан дословно и воспроизведён вручную на ровном остатке.
3. Время обновления конфигурации найдено в журнале регистрации и сопоставлено с коммитом из `git log v1.1.0..main`.
4. Строка с ошибкой найдена через `git log -S` и `git blame`, причина показана в отладчике условной точкой и вычислением выражения.
5. Исправление слито через ветку `bugfix/exact-balance`; все тесты пройдены; сообщение со складом сохранено.
6. В отчёте об ошибке есть разбор: как ошибка дошла до `main` и какие правила это предотвратят.
